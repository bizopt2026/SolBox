# 솔박스 (solbox/CLAUDE.md)

이 저장소는 앱마다 폴더를 나눠 관리한다. 솔박스는 `solbox/` 폴더이고, 아래 경로와 명령은 모두 `solbox/` 기준이다 (명령은 `solbox/` 안에서 실행).

사내 한국어 웹 앱. 솔루션 발굴(접수→태핑→수요조사→박스 등록), 고객·파트너·프로젝트·활동 기록, AI 제안서(PPT), 주간 웹 리서치를 한곳에서 다룬다. FastAPI + SQLAlchemy 2 + SQLite + Jinja2/HTMX. AI는 Claude CLI(`claude -p`)를 호출한다.

## 폴더
- `app/` 코드. `routers/` 화면·API, `ai/` AI 작업(대기열 `queue.py`, 실행기 `runner.py`, 처리기, `prompts/`), `templates/`, `static/` (`app.css` 하나, 글꼴 Pretendard Variable 은 `static/fonts/` 에 OFL 라이선스 글과 함께 담았다. 바깥 주소·CDN 을 부르지 않는다)
- `app/research.py` 리서치, `scheduler.py` 주간 조사·일일 작업, `backup.py` 백업, `certs.py` 인증서, `system.py` 점검, `cli.py` 명령줄, `migrate.py` 컬럼 자동 추가, `guards.py` 고침 표시·폼 표·고친 사람
- `tests/` pytest (가짜 CLI `tests/fake_claude.py`), `scripts/` Windows PowerShell 스크립트, `docs/` 문서
- 운영 데이터는 `data_dir` (기본은 `solbox/data`이며 커밋하지 않는다. `config.toml` 로 다른 경로를 정할 수 있다): `app.db`, `uploads/`, `knowledge/`, `decks/`, `logs/`, `research_work/`, `intake_work/`(올리기 묶음별 작업 폴더), `models/`(음성 받아쓰기 모델, 백업하지 않음)

## 실행·테스트
- 설치 `pip install -e ".[dev]"`, 설정 `config.example.toml` → `config.toml` (저장소에 올리지 않는다)
- 실행 `python -m app`, 점검 `python -m app.cli check`, 인증서 `python -m app.cli make-cert --host <주소>`
- 테스트 `python -m pytest -q -W error` (경고도 오류. 실제 `claude` 는 테스트에서 부르지 않는다. 새 starlette 의 "httpx2 를 설치하라" TestClient 경고(`starlette.exceptions.StarletteDeprecationWarning`)만 `tests/conftest.py` 맨 위에서 그 종류와 문구를 함께 지정해 넘긴다: pyproject 의 `filterwarnings` 는 명령줄 `-W error` 에 밀려 듣지 않는다)
- 명령줄: `create-admin`, `rebuild-knowledge`, `backup`, `backup --verify <폴더>`, `make-cert`, `check`, `stt-setup`(받아쓰기 모델 받기, 인터넷 필요), `stt-test <음성 파일>`
- 받아쓰기(선택 설치) `pip install -e ".[stt]"`

## 화면 틀
- 사이드 메뉴(묶음: 오늘·발굴·영업·관리)는 `ontology.NAV_GROUPS`·`NAV_ITEMS`·`nav_groups()` 에서 그린다. 메뉴에 넣는 대상은 `ObjectType.nav_group` 이 있어야 한다. 모든 화면의 제목 줄은 `_macros.html` 의 `page_header`(또는 이를 감싼 `list_head`·`detail_head`) 하나다. 배지 색은 `ontology.CODE_TONES` 한 곳(`pill` 매크로). 목록 화면은 모두 같은 틀이다: `list_head`(온톨로지 `description` 한 줄) + `list_tools`(구분 탭 `seg`·검색·걸러 보기 칩) + `list-table`(제목 칸 `title_cell`, "연결" 건수는 `ontology.LIST_LINKS` → `relations.link_counts` 가 쪽의 번호만 묶어 센다) + `pager`. 구분 탭은 `ui.seg_tabs`(건수는 검색어·걸러 보기를 적용한 목록 기준). 홈은 대시보드(`routers/home.py`, 질의 수는 기록 수와 무관), 후속 조치 목록은 `/follow-ups`(`routers/follow_ups.py`). 전체 검색은 `app/search.py`(칸 목록 `FIELDS`: 이름·제목·소개·설명·메모·연락처·정리본·원문·후속 조치·고객 니즈, 맞은 칸 발췌 `<mark>`, 질의 수는 건수 질의 유형마다 1 + 맞은 유형의 줄 1 + 연결 미리 읽기 0~2 로 기록 수와 무관, 발췌는 줄 앞 마크다운 표지를 뗀다, "모두 보기" 는 그 글을 실제로 찾는 목록(후속 조치 `/follow-ups?q=`)만 잇고 고객 니즈는 링크 없음, 올리기 묶음 제외). 위쪽 줄의 AI 상태는 `main._ai_status`. 상세 화면은 모두 같은 틀이다: `detail_head`(삭제 → 수정 → 다음 동작 하나 `primary=`) + 흐름이 있는 대상은 `stage_stepper` + `.dgrid`(왼쪽 `.dmain` 내용 카드, 오른쪽 `.daside` 의 `related_card`·`meta_card`; 1100px 밑에서는 아래로). 폼은 `.form-page` 안에 `text_field`·`select_field`(`field_shell`)·`check_picker` + 맨 밑 `save_bar`, 오류는 위쪽 알림과 `ui.error_field` 가 가리키는 칸 옆에 함께. 경로는 `ui.crumbs`(메뉴 묶음 › 메뉴 이름 › …). 제안 작업 화면은 같은 틀에 `_primary.html`(제목 줄의 다음 동작 하나, 대화 답변이 끝나면 같이 바뀐다)·`_stepbar.html`(5단계, 구역 앵커)·왼쪽 단계 구역(지금 단계만 펼침)·오른쪽 맥락 카드(선택한 방향·출처·대상 요약·연결된 것)이고, 올리기 묶음 상세는 진행 띠(`.timeline`)와 상태별 제목 줄 동작이다. 상세 화면의 두 칸(`.dgrid`)은 쪽 본문 폭이 960px 이상일 때만(컨테이너 질의, `.page` 가 컨테이너) 나란하고 아니면 쌓인다. 상세·제안·올리기 묶음 화면의 제목 줄은 `page_header(cls="detail")`(좁은 화면에서 주 버튼이 한 줄을 다 쓴다), 목록·홈은 좁은 화면에서도 제목과 작은 버튼이 한 줄이다. 파일 고르기 칸은 `_macros.html` 의 `filepick`(브라우저 기본 버튼 글씨를 쓰지 않는다), 처리하지 못한 오류는 `main._server_error_handler`(500 화면, 예외 글은 로그에만), 홈의 "처음 시작하기" 안내는 `home.is_fresh_install`(솔루션·활동 기록·고객이 모두 0)일 때만 나온다.
- 결과 알림: 저장·삭제·단계 변경 같은 POST 는 `notices.redirect(주소, 코드)` 로 돌려보내고, 다음 화면 맨 위의 알림(`base.html` 의 `.flash`: 닫기 링크는 JS 없이 동작, JS 는 성공 알림만 서서히 지움)은 `main.render` 가 `?notice=<코드>` 를 `app/notices.py` 의 표에서 찾아 그린다. 글은 그 표에만 있고(주소로는 코드만 와서 사용자 글이 비치지 않고, 모르는 코드는 무시), 값이 붙는 코드는 `종류.값`(`stage.tapping`, 값은 온톨로지 코드 목록). 새 POST 를 더하면 `tests/test_ux_notices.py` 의 `POST_NOTICES` 표에 알림 코드(또는 알림이 없는 이유)를 적어야 한다.
- 지우기 확인: 되돌릴 수 없는 동작(삭제·묶음 버리기 …)은 `_macros.html` 의 `confirm_link`(링크, 주소는 삭제 POST 와 같다)로 그린다. JS 가 있으면 그 자리에서 "정말 삭제할까요? [삭제] [취소]"(`window.confirm` 안 씀), 없으면 서버가 그린 확인 화면(GET 같은 주소, `routers/confirm.py` 의 `SPECS` 한 줄씩 + `confirm.html`, 지우면 어떻게 되는지는 `ontology.DELETE_EFFECTS`)에서 POST 한다. 새 삭제 라우터는 `SPECS` 에 한 줄을 더한다 (시험이 모든 `/delete`·`/discard` POST 에 확인 화면이 있는지 본다).
- 미리 채우기(상세 화면의 "+ …" 동작): `/activities/new?customer_id=|partner_id=|project_id=|solution_id=|opportunity_id=`(`ontology.ACTIVITY_PREFILL`; 메모 화면은 저장·AI 정리가 연결을 이어받고 `?manual=1` 은 직접 입력 폼의 연결 칸), `/proposals/new?customer_id=|project_id=|opportunity_id=|solution_id=`(보류 솔루션이면 "직접 추가" 칸에 미리 체크, 아니면 이미 후보이므로 요청 메모에 "<이름> 중심으로 제안"과 안내 한 줄), `/opportunities/new?customer_id=&need_id=`, `/projects/new?customer_id=`, `/solutions/new?partner_id=`. 모두 있는 기록일 때만 채우고 틀린 값은 무시한다. 관계 카드의 동작 주소는 `ontology.MAIN_GROUPS` 한 곳(`item_action` 은 항목마다 붙는 동작).
- 따라가서 얻는 관계는 "A 빼기 B"(`Derived.minus`)로도 정의한다 (D14 "이야기했지만 아직 제안하지 않은 솔루션" = (D1 ∪ 영업기회 검토 솔루션) − D2; 고객 상세 왼쪽 칸 카드).
- 목록 정렬: `?sort=`(정의 `ontology.LIST_SORTS`, 첫 항목이 지금의 기본 순서이고 틀린 값은 기본, `routers/_common.sort_rows`, 도구줄의 `.sortbar` 는 `ui.sort_options`). 목록 표의 빈 선택 칸은 `none_dash()`(흐린 "–", `aria-label="없음"`). 줄 전체 누르기·글 칸 자동 높이·저장하지 않은 변경 경고·제안 대화 Ctrl+Enter 는 `app.js` 의 JS 보강이고 없어도 동작한다.
- 도움말 `/help`(`routers/help.py`, `help.html`, 사이드 메뉴 맨 아래 "도움말"): 업무 흐름 그림과 용어 풀이는 온톨로지(`HELP_GLOSSARY` 의 유형 이름·`description`)에서 만들고 "이럴 땐 이렇게"만 손으로 쓴 글이다. 화면 동작이 바뀌면 그 글도 고친다. 홈 후속 조치 카드의 "내 할 일"은 `?fu=mine`(담당 칸이 내 이름과 정확히 일치해 연결된 것), 올리기 확인 화면 맨 위 한 줄은 `intake.plan_summary`, 저장 뒤 결과 줄은 `plan["outcome"]`(`intake.outcome_text`).

## 올리기 구조
- 파일을 한 번에 올리면(`Intake`, `IntakeFile`; `app/intake.py`, `routers/intake.py`) AI 작업 `intake_analyze`(`ai/intake_tasks.py`, 프롬프트 `prompts/intake_analyze.md`)가 정리안(`Intake.plan`)을 만들고, 사용자가 확인하면 `intake.apply` 가 `app/records.py` 의 공용 저장 로직으로 기록을 만든다. 상태: 올림 → 정리 중 → 확인 대기 → 저장 중(`applying`) → 저장 완료 / 실패 / 버림. 저장 중에는 선점마다 `Intake.apply_token` 이 붙고, 저장을 끝내거나 풀 수 있는 것은 그 토큰의 주인뿐이다 (오래 멈춘 저장을 "다시 확인" 으로 풀어도 옛 저장이 뒤늦게 끝나 두 번 저장되지 않게).
- 음성 받아쓰기는 `app/transcribe.py` 의 연결 지점(설정 `transcriber`: `none` 은 "받아쓰기 필요"로 보관만, `faster-whisper` 는 서버 안 CPU 받아쓰기)이다. 설계 `docs/superpowers/specs/2026-11-20-audio-transcription-design.md`. 실제 받아쓰기는 개발 환경에서 돌려 보지 못했다 (모델 저장소 접속 불가).

## 온톨로지 (단일 정의)
- `app/ontology.py` 가 대상 유형(한국어 이름·모델·물리 표·주소·지식 사본 경로·속성 이름표), 코드 값 목록(발굴 단계·활동 종류·제안 단계 …), 관계(R1~R33), 사본 경로 해석(`parse_rel`, 옛 `businesses/N.md` 도 읽는다)을 한 곳에 정의한다. 새 목록·이름표·경로 형식은 여기에 더하고, 다른 곳(`labels.py` 는 다시 내보내기뿐)에 다시 적지 않는다. 일관성은 `tests/test_ontology.py` 가 검사한다.
- 프로젝트(옛 "기존 사업")는 코드에서 `Project`·`project_id`·`/projects` 이지만 물리 표·열은 `businesses`·`business_id`·`activity_businesses` 그대로다 (표·열 이름을 바꾸거나 지우지 않는다). 옛 `/businesses` 주소는 영구 이동한다. 저장된 옛 값(정리안의 `businesses` 키, 출처 `businesses/N.md`)은 읽을 수 있어야 하고 고쳐 쓰지 않는다.
- 용어: 프로젝트, 제안 건(메뉴는 "제안", PPT 는 "제안서"), 올리기 묶음/올린 파일, 자료, 고객 니즈(JSON 키는 `demand_signals` 그대로), 확인 항목(근거 문제·확인할 점), 출처/이유. 화면·사본·프롬프트는 `ontology.label/prop/term` 에서 읽는다.
- 후속 조치·고객 니즈는 `follow_ups`·`customer_needs` 표가 원본이다. `activities.follow_ups`·`demand_signals` JSON 열은 옛 데이터로만 남아 있으니 읽지도 쓰지도 않는다 (ORM 이름 `legacy_*`, 시작 때 한 번 복사하는 `migrate.copy_activity_json` 만 읽는다). 화면에서 저장할 때는 줄 번호(숨은 칸 `fu_id`·`ds_id`)로 행을 맞춘다: 같은 번호는 고치고, 빠진 번호는 지우고, 새 줄은 만든다. 고객·담당 연결은 `activity_rows.LinkIndex` 의 정확히 하나 일치 규칙 한 곳만 쓴다.
- 제안 후보 = 보류가 아닌 모든 솔루션 + 제안 건에 직접 추가한 솔루션 (`proposals.candidate_condition` 한 곳).
- 유래: 솔루션·활동 기록·고객·파트너의 `origin_type`(직접 입력/올리기/리서치, 비면 모름)·`origin_id`(묶음 번호 또는 보고서 번호, 제약 없는 응용 수준 키)는 `app/origin.py` 로 읽고 지운다. 새로 만들 때만 쓴다(`records.get_or_create(origin=…)` 기본은 직접 입력, 올리기 저장은 묶음 번호; 연결·덧붙임은 건드리지 않는다). 올리기 묶음이나 리서치 실행을 지우는 곳은 같은 트랜잭션에서 `origin.clear_dangling` 을 부른다. 시작 때 한 번 `Intake.result` 로 되짚어 채운다(`migrate.backfill_origins`, 근거 없는 기록은 비워 둔다). 기록을 지울 때는 `clear_file_targets` 로 올린 파일의 `target_*` 도 비운다.
- 같은 회사: `partners.customer_id`(유일)가 파트너 ↔ 고객 연결의 유일한 저장이고 `app/same_company.py` 가 양쪽 화면의 규칙을 한 곳에 둔다. 이름이 같아도 자동으로 잇지 않는다(올리기 포함, 안내만).
- BM·영업기회(단위 4): BM 은 사업 모델이고 고객에 묶이지 않으며, 특정 고객별로 나뉘는 것은 프로젝트다. 흐름은 활동 기록 → 고객 니즈 → 영업기회 → 프로젝트. 행위 조건(같은 고객의 아직 묶이지 않은 니즈만 묶기, 수주일 때 한 번만 프로젝트로 전환·같은 고객의 기존 프로젝트 잇기, 영업기회·프로젝트·BM·고객 삭제 규칙)은 `app/opportunities.py` 한 곳에 있고 라우터·템플릿이 그것만 부른다. 단계 목록·배지 클래스·화면 안내 글은 `ontology.py`(`OPPORTUNITY_*`). `customer_needs.opportunity_id` 는 제약 없는 번호 열이라 지울 때 응용 코드가 비운다 (영업기회·`proposals.opportunity_id`·`businesses.bm_id` 는 `migrate.py` 가 옛 DB 에 더한다). AI 정리·올리기는 영업기회·BM 을 제안하거나 만들지 않는다 (활동 기록 화면에서 직접 고른다). 제안 후보의 집합은 그대로이고 순서만 영업기회의 검토 솔루션 → 그 BM(영업기회가 없으면 프로젝트의 BM)의 솔루션 → 나머지다 (`proposals.priority_groups`).
- 연결 따라가기(단위 5): `ontology.related(db, 대상, viewer=…)` 와 `ontology.path_query(db, 시작, ["R1", "R14", …])`(엔진은 `app/relations.py`)가 정의만 보고 관계를 따라간다. 모든 상세 화면의 "연결된 것"(`templates/_related.html`, 라우터는 `relations.related_for_page`)과 지식 사본의 "## 연결"이 같은 조회를 쓴다. **새 대상 유형·관계를 더하는 법**: ① `ontology.py` 에 유형(`_TYPE_LIST`)과 관계(`RELATIONS`: 저장 위치 `physical` 을 정확히)를 정의하고, ② `VIEW_LABELS` 에 양방향 보는 이름을 적고, ③ JSON·글에 든 관계면 `RESOLVERS` 에 양방향 해석기를 등록하고(따라가지 않을 관계는 `UNTRAVERSED` 에 이유), ④ 건너서 얻는 관계는 `DERIVED` 에 경로로 정의한다. 그러면 따라가기·상세 화면·사본이 따라온다. 화면이 이미 속성 줄·특수 구역으로 보이는 그룹은 `RELATED_EXCLUDE`, 목록의 `?customer_id=` 걸러 보기와 "모두 보기"는 `LIST_FILTERS`. 빠뜨리면 `tests/test_related.py` 가 깨진다 (레지스트리 전체를 돌며 양방향 따라가기·보는 이름·따라가서 얻는 관계의 방향을 검사). 화면마다 손으로 조인하지 않는다. 올리기 묶음에 닿는 그룹은 `viewer` 가 열 수 있는 것만 (`origin.can_open_intake`). 사본의 "## 연결" 중 따라가서 얻는 구역은 조금 늦을 수 있고 `rebuild-knowledge` 가 맞춘다.
- 사본 형식이 바뀌면 `knowledge.KNOWLEDGE_FORMAT` 을 올린다. 시작할 때 표시(`app_settings.knowledge_format`)와 다르거나 옛 폴더가 남아 있으면 사본을 한 번 다시 만든다.

## 베타 B 묶음이 더한 규칙
- 제안서 PPT 는 한 구성안에서 고객용(`build_deck(audience="customer")`: 노트 없음, 사본 경로가 든 줄 제거)과 내부 검토용(`-internal` 파일: 노트에 출처 이름·확인 항목) 두 파일을 쓴다. 마무리 장 연락처는 AI 가 아니라 만든 사용자(`users.contact`, `/account`)로 서버가 채운다 (`proposals.contact_lines`). `clean_outline` 은 본문의 작성자용 말투(`AUTHOR_INSTRUCTION_PATTERNS`)를 `needs_check` 로 옮긴다.
- 음성만 있어 읽을 파일이 없는 묶음은 `intake.is_archived`(상태 코드는 `uploaded` 그대로, 화면만 "보관됨"). 유래 걸러 보기는 `routers/_common.origin_filter`, 같은 이름 경고는 `_common.duplicate_warning`(폼의 `confirm_dup`), 파일 내용 해시는 `intake_files.sha256`·`solution_files.sha256`(옛 파일은 비교할 때 채움), 지우기 영향은 `ontology.DELETE_IMPACT` → `impact.py`, 문장 속 조사 고르기는 `korean.josa`, 점검 항목의 뜻·할 일은 `system.CHECK_INFO` (웹과 `cli check` 가 같은 목록), 코드 값의 한 문장 뜻은 `CodeList.descriptions`(`ontology.code_help`).

## 꼭 지킬 규칙
- 고치기 폼은 **고침 표시(revision stamp)** 를 가진다 (`app/guards.py`): 숨은 칸 `_rev` = 기록의 신원(표·번호·`created_at`) + 마지막 변경(`updated_at`; 제안 건은 대상 폼 값, 사용자는 값)의 뜻 없는 해시. 템플릿은 `rev_fields(기록, conflict, 상세 주소)`(폼 맨 위, 숨은 칸 + 충돌 알림 + "그래도 내 내용으로 저장" 은 다른 곳에서 바뀐 경우만), 라우터는 update 의 `rev: Rev = Depends(rev_form)` 와 `guards.check_rev(기록, rev)` → 충돌이면 저장하지 않고 쓴 값 그대로 `409` 로 폼을 다시 그린다. 같은 번호에 새 기록이 만들어진 경우("신원" 불일치)는 강제 저장 없음. 표시가 없으면(옛 화면·API) 한 번 받아 준다. **모든 쓰기는 `updated_at` 을 올려야 한다**: ORM 변경은 `guards` 의 flush 처리기가 한곳에서 올리고(연결 표·후속 조치/니즈 줄 → 활동 기록, 같은 회사 연결 → 고객 포함) `updated_by_id` 도 채운다(요청 세션 `db.info["user_id"]`, `require_user` 가 단다). 코어 `UPDATE` 는 열의 `onupdate` 가 올리고, 값이 그대로인 연결만 바뀐 곳은 `guards.touch`. 새 고치기 폼을 더하면 이 셋(숨은 칸·`check_rev`·시험)을 함께 더한다. 지운 번호는 `app/idmarks.py` 가 다시 쓰지 않게 한다: 표마다 "지금까지 쓴 가장 큰 번호"를 작은 표 `id_marks` 에 두고, ORM 으로 새 줄을 넣을 때(`before_flush`, 메타데이터에서 기본키가 정수 한 열이고 실제 표 정의에 AUTOINCREMENT 가 없는 모든 표) 번호를 `max(표시, MAX(id)) + 1` 로 쓰기 잠금 안에서 직접 정해 표시를 올리고, 지울 때도 표시가 그 번호 이상이 되게 한다(시작할 때 `ensure_marks` 가 표시를 만든다). 이 장치가 켜지기 전에 지운 번호는 다시 쓰일 수 있어 고침 표시가 그 경우를 막는다. 코어 INSERT 는 쓰지 않는다(`migrate.copy_activity_json` 만 예외, 그 뒤 `ensure_marks`). 새 코어 INSERT 가 필요하면 `idmarks.reserve_ids` 를 쓴다. 새 표는 `sqlite_autoincrement` 를 따로 선언하지 않아도 이 장치가 덮는다.
- 모든 **만들기 폼**(과 "원문만 저장"·AI 정리 시작)은 한 번 쓰는 **폼 표** `_tok`(`form_token()` 매크로)를 싣고, POST 는 `once: Once = Depends(form_once)` 를 받아 성공하면 `return once.done(응답)` 한다(`form_tokens` 표에 처음 결과 주소를 적고, 같은 표로 다시 오면 알림을 새로 붙여 처음 결과로 보낸다; 검증 오류·예외면 표를 풀어 다시 낼 수 있다; 표가 없으면 받아 준다; 표는 사용자·주소마다 따로, 1시간 뒤 지운다). 올리기 저장(`/intake/{id}/apply`)도 같다. JS 는 제출하면 버튼을 잠그고 `pageshow` 에 푼다 (없어도 서버가 막는다).
- **비밀번호 규칙** (`security.password_problem`): 8자 이상, 아이디와 같지 않음, 한 글자만 되풀이하지 않음 — 직원이 `/account` 에서 바꿀 때와 관리자가 만들거나 다시 정할 때(그때는 `users.must_change_password` 를 달아 다음 로그인 뒤 `/account` 로만 갈 수 있다, 로그아웃 가능) 같은 규칙. 규칙 이전의 짧은 비밀번호로도 로그인은 되고(잠그지 않는다) 안내만 한다. 로그인은 서명 쿠키라 서버에 기록이 없으므로 쿠키의 `pv`(비밀번호 해시의 짧은 해시)가 바뀌면 옛 로그인을 끝낸다 (`security.current_user`). 비활성 계정은 맞는 비밀번호일 때만 "사용이 중지된 계정" 을 알려 준다.
- 알림(`notices.redirect`)은 `&nt=<초>` 시각 표시가 30초 안일 때만 그린다 (옛 주소를 다시 열어도 일어나지 않은 일이 뜨지 않는다). POST 가 오류 화면을 그린 주소를 GET 으로 열면 405 대신 같은 일을 하는 폼·목록으로 보낸다 (`main._get_fallback`). 주소 번호 자리에 글자가 오면 GET 화면은 없는 항목 404 화면이다 (`main._validation_error_handler`).
- 올리기 정리 작업의 작업 폴더는 `intake_work/<묶음 번호>/`(글 사본·줄인 사진·`파일목록.md`)이고 도구는 파일 도구(`DEFAULT_TOOLS`)뿐이다. 이름만 쓴 `Read` 는 어느 경로든 허용이라 폴더 밖을 읽을 수 있으므로, 이 작업은 `run_json(..., file_scope=True)` 로 `Read(./**)`·`Glob(./**)`·`Grep(./**)` 만 허용해 실행한다 (실제 CLI 로 확인: 폴더 안 파일·PNG 는 읽고, `../`·절대 경로·폴더 밖으로 가는 심볼릭 링크는 거절). 다른 작업(지식 폴더 읽기)은 그대로다. 작업 폴더는 저장·버림 뒤에 지우고 실패한 묶음에는 "다시 정리"를 위해 남기며, 정리를 시작할 때 비었거나 읽기 상태가 비었거나 `failed` 이면 다시 준비한다. 원본은 `uploads/intake/` 에 있고 실패·버림 뒤에도 지우지 않는다 (자동 정리 없음: 디스크와 백업이 계속 커진다). 이 제한은 CLI 버전과 서버 계정의 Claude 설정에 따라 달라질 수 있고 Windows 에서는 확인하지 못했다 (README 수동 확인 16번).
- 받아쓰기는 파일을 PyAV 로 조금씩 읽어 `transcribe_chunk_minutes` 조각으로 나눠 하고(메모리 제한) 길이는 모델을 부르기 전에 확인한다. 받아쓰기는 업로드 요청이 아니라 올리기 정리 작업(`intake_analyze`) 안에서, 프로세스 전체에서 한 번에 하나만(`transcribe.run`의 잠금) 한다. 받아쓴 글은 원본 옆 `<저장이름>.transcript.txt`(첫 두 줄 `#model:`·`#language:`, 모델·언어가 바뀌면 쓰지 않음)에 저장해 다시 정리·작업 폴더 재생성 때 재사용한다. 모델 내려받기는 `stt-setup` 에서만 하고 서버는 인터넷에 접속하지 않는다.
- 올리기의 AI는 기록을 추가만 한다. 기존 기록을 고치거나 지우는 정리안 항목은 만들지 않는다. 단 하나의 예외가 `add_contact`(연락처 추가): 이미 등록된 파트너·고객의 `contact` 칸 끝에 새 연락처 한 줄을 덧붙이는 것만 허용한다. 기존 글을 바꾸거나 지우지 않고(덮어쓰기 금지), 같은 전화·이메일이 이미 있으면 건너뛰며("이미 있는 연락처"), 그 밖의 칸(이름·소개·메모 등)은 건드리지 않는다. 대상은 같은 종류의 등록된 기록이어야 하고 저장 때 다시 확인한다.
- 한 묶음은 한 번만 저장된다 (두 번 눌러도, 동시에 눌러도 기록이 한 벌만).
- DB가 원본, `knowledge/` 는 사본이다. 저장·수정·삭제 뒤에는 커밋 후 사본을 갱신한다 (`KnowledgeMirror`).
- AI 도구 분리: 지식 폴더를 읽는 작업은 `Read/Glob/Grep` 만, 웹 조사는 `WebSearch/WebFetch` 만, 한 작업에 둘을 섞지 않는다 (`assert_tool_separation`). 웹 조사의 작업 폴더는 빈 `research_work`.
- 웹 글·업로드 자료·메모는 신뢰할 수 없는 글이다. 프롬프트에서 구분하고 "지시가 아니라 자료" 라고 적는다.
- AI 결과는 초안이다. 사용자가 저장해야 반영한다. AI가 안 돼도 조회·수동 입력은 된다.
- 화면 문구는 한국어. 경로는 `pathlib`, 파일은 `encoding="utf-8"`. Windows와 Linux 모두 동작해야 한다.
- 데이터는 `data_dir` 아래에만 쓴다. 주소·포트·경로를 코드에 박지 않는다 (모두 `config.toml`).
- JSON 컬럼은 새 list/dict 를 대입한다 (제자리 수정 금지). DB 컬럼 추가는 `migrate.py` 가 시작 때 자동 처리한다.
- `secret_key`, 비밀번호, 인증서 키, `config.toml`, `data/`, `certs/`, `backups/` 를 커밋하지 않는다.
- PowerShell 스크립트(`scripts/`)는 Linux에서 작성돼 Windows 실행 검증이 안 됐다. 고치면 저장소에 반영한다.

## 베타 C 묶음이 바꾼 규칙
- 폼 표(`guards.Once`): 같은 표라도 폼 내용 해시(`form_tokens.body_hash`, `_tok` 뺀 칸·올린 파일은 이름+크기만, `guards.form_digest`)가 다르면 새 제출이다(끝난 줄을 새 제출이 이어받는다). 요청 세션이 커밋한 뒤에는 예외가 나도 표를 풀지 않고 목록 주소로 끝낸다(`Once.keep`, 중복 방지). 저장 상태를 스스로 되돌리는 라우터(올리기 저장)만 `once.sticky = False`.
- `guards.check_rev` 가 통과하면 세션에 저장 직전 검사를 걸고, 첫 쓰기 flush 직전에 쓰기 잠금을 잡은 뒤 줄을 다시 읽어 표시를 견준다. 그 사이 바뀌었으면 `StaleWrite`(409). 모든 고치기 라우터가 `check_rev` 를 쓰므로 따로 더할 것이 없다 (슬라이드 저장은 `fresh=` 로 장 표시를 다시 계산하고 `_lock_proposal` 이 먼저 잠근다).
- 쿠키에 `pv` 가 없으면 로그아웃으로 본다. `clean_outline` 의 작성자 말투는 분명한 표지(`할 것`·`하세요`·`바랍니다`·`요망`·`…필요`·`함께 …`·`반드시 …`·TBD·자리표시)가 있을 때만, 마무리 장 연락처 줄은 전화·이메일 또는 "담당:" 같은 이름표만 거른다. 고객용 PPT 의 사본 경로는 폴더(온톨로지)+`/번호` 모양일 때만 지우고 뺀 줄 수를 `proposals.deck_removed` 에 적어 제안서 상자에 보인다.
- 옛 한 파일 제안서(`-internal` 짝 없음, `proposals.deck_is_old`)는 GET 에서 다시 쓰지 않고 `notice=deck_old` 로 제안 화면에 보내 "다시 만들기" 를 안내한다. PPT 는 임시 파일(`.part`)에 쓴 뒤 바꿔치기한다.
- 문장 속 조사는 `이(가)` 같은 겹쓰기를 쓰지 않고 `korean.josa` 로 고른다 (`tests/test_beta_c.py` 가 앱 전체를 훑는다). 화면 구성 문서: `docs/화면구성도.md` (화면을 바꾸면 함께 고친다).

## 베타 D 묶음이 바꾼 규칙
- AI 를 쓰는 동작은 `main.ai_gate`(상단 줄과 같은 `_ai_status` 에 `blocked`·`reason`·`upload` 를 더한 것, 템플릿 `{% set aig = ai_gate() %}`)와 `_macros.html` 의 `ai_note(aig)`(AI 꺼짐·사용 불가일 때 안내 한 줄)·`ai_attrs(aig)`(꺼짐일 때만 버튼 비활성) 하나로 안내한다. 화면마다 상태를 다시 판단하지 않는다. 활동 기록 쓰기는 꺼짐일 때 "원문만 저장"이 주 버튼이다. 올리기·사용 불가의 동작은 아래 베타 E 묶음 규칙이 정한다 (베타 D 의 "사용 불가도 버튼 비활성"은 바뀌었다). PPT 만들기는 AI 가 아니라 막지 않는다. 새 AI 버튼을 더하면 이 둘을 붙인다.
- 단계 설명은 접힌 `<details class="stage-legend">`. 목록 도구줄은 좁은 화면(≤600px)에서 유래 탭과 정렬을 "걸러 보기·정렬" 펼침으로 접는다(두 벌을 그리고 CSS 가 한 벌만 보임, 기본이 아닌 것이 걸려 있으면 개수 표시). 목록 첫 칸(`title_cell`)은 두 줄(보조 글 한 줄 줄임표 + 태그 둘까지와 "+N"). 옆으로 미는 줄(단계 막대·제안 단계·구분 탭·표 감싸개)은 `app.js` 의 `initScrollers` 가 현재 항목을 보이게 하고 끝을 흐리게 한다. 제목 줄의 그 자리 삭제 확인은 제목 줄 밑 따로 선 줄에 놓는다.
- 충돌(409) 화면은 `guards.check_rev(..., values=쓴 값)` 의 `Conflict.diff`(온톨로지 속성 이름표 + 저장된 값 발췌)를 보인다. 연결 번호·후속 조치/니즈 줄·다중 선택은 비교하지 않는다. 같은 이름 경고는 `normalize_name(이름, company=True)`(고객·파트너: ㈜·(주)·주식회사 무시)로 견주고, 공백·대소문자만 다르면 "같은 이름", 그 밖이면 "비슷한 이름"이다. 사이드 메뉴 그림은 `ontology.NAV_ICONS`(새 메뉴 항목은 그림도 더한다).

## 베타 E 묶음이 바꾼 규칙
- 파이썬 3.11 에서도 돈다 (`pyproject` `>=3.11`). f-string 안에서 같은 따옴표를 다시 쓰거나 치환 칸에 역슬래시·주석을 넣지 않는다 (3.12 문법). `tests/test_beta_e.py` 가 토큰으로 앱 전체를 훑고, `python3.11` 이 있으면 컴파일도 한다. `itertools.batched`·`Path.walk`·`type` 문·`def f[T]` 같은 3.12+ 기능도 쓰지 않는다.
- AI 문(한 곳, `app/ai/gate.py`): **"off"(처리기 꺼짐)만** 버튼을 막고(`ai_gate().blocked`, `ai_attrs`), 서버도 새 AI 작업을 받지 않는다 — AI 작업을 시작하는 POST 는 `dependencies=[Depends(require_ai_on)]` 를 달고(거절하면 `AIOff` → `main._ai_off_handler` 가 보낸 화면(Referer)으로 알림 `ai_off`, HTMX 는 `HX-Redirect`. 로그인·권한 검사가 이 문보다 먼저다: `require_ai_on` 이 `require_user` 에 기대고, 관리자 전용은 `dependencies=[Depends(require_admin), Depends(require_ai_on)]`. 쓴 글이 있는 라우터는 `gate.keeps_text(view)` 로 글을 채운 화면을 돌려준다 — 아래 베타 F), 요청 세션(`db.info["ai_off"]`, `get_db`)에 새 `AIJob` 이 들어오면 flush 처리기가 한 번 더 거절한다. 일은 하되 작업만 안 넣는 예외 둘: 올리기(`POST /intake`: 파일 보관, "올림" 상태, 알림 `intake_kept_ai_off`, 정리 시작 버튼은 켜진 뒤)와 제안 건 만들기(`created_ai_off`). 스케줄러도 꺼져 있으면 예약 조사 실행을 만들지 않는다. **"down"(지난 작업이 `not_installed`/`auth` 로 실패)은 막지 않는다**: `ai_note` 가 "다시 시도하면 다시 확인, 계속 실패하면 관리 › 시스템 › AI 연결 확인"을 알리고(관리자는 링크), 성공한 작업이 하나 나오면 저절로 풀린다. 새 AI 버튼·POST 를 더하면 `ai_attrs` 와 `require_ai_on`, `tests/test_ux_notices.py` 의 알림 코드, `tests/test_beta_e.py` 의 `AI_POSTS` 를 함께 고친다. 시험의 서버는 처리기가 꺼진 채 만들어지므로 conftest 가 이 거절을 기본으로 열어 두고, 거절을 시험하는 시험만 `@pytest.mark.ai_gate` 를 단다.
- 로그인 문제 분류(`runner.classify_error`)는 CLI 의 오류 출력(표준 오류, 오류로 끝난 결과 글)에서 낱말 경계 정규식으로만 본다 (`error_text`).
- 고객용 PPT 사본 경로(`deck.has_internal_mark`)는 지우는 쪽으로 기운다: 폴더(온톨로지, 대소문자 무시) + `/번호` 낱말에서 머리말에 `knowledge/` 마디가 있으면 무엇이 앞에 붙어도 지우고(`https://` 주소만 예외), 머리말이 없거나 `근거=`·`→`·`※`·따옴표 같은 표지·`./`·`/`·`C:/`·`~/`·`$VAR/` 로 시작하는 경로면 지운다. 남기는 것은 주소(도메인·IP·`localhost:포트`)·일반 폴더 이름 뒤(`intranet/solutions/3`)·번호에 단위가 붙은 수량(`partners/2개사`, `solutions/5G`). 번호에 조사·다른 글자가 붙은 것은 지운다 (아래 베타 G). 단, 센 단위 + 조사는 수량이다 (아래 베타 I). 번호 뒤가 띄어쓰기인 글(`solutions/3 단계로 구성`)은 맨 경로와 구별되지 않아 지운다. 작성자 말투는 쓰기·확인 동사 바로 뒤에 `필요`·`요망`·`할 것`·`바랍니다`·`하세요` 가 붙거나 `함께|반드시 + 제시·기재·명시·작성` 일 때만 보되, 대상이 문서 값일 때·줄이 동사뿐일 때·뒤에 이름표나 괄호가 붙을 때로 더 좁혔다 (`proposals.AUTHOR_INSTRUCTION_PATTERNS`, 아래 베타 F).
- 쓰기 잠금: 잠금 대기 초과(`OperationalError`)는 충돌이 아니라 `guards.WriteBusy`(503, "잠시 후 다시 시도")이고, 읽은 뒤 다른 쓰기가 커밋된 경우(`SQLITE_BUSY_SNAPSHOT`)와 줄 표시가 다를 때만 `StaleWrite`(409). 두 오류 화면은 "저장하지 않았습니다" + 뒤로 가기 버튼(`data-history-back`, 브라우저가 쓰던 폼을 되살린다; 단추는 `hidden` 으로 그리고 JS 가 보이게 한다, JS 가 없으면 `<noscript>` 안내). 번호 표시(`idmarks`)의 잠금 단계도 같다 (새 기록이라 `StaleWrite` 는 없고 항상 `WriteBusy`).
- 같은 이름 경고는 `duplicate_warning()["company"]`(고객·파트너)로 회사 접미 안내를 정한다. 올리기 확인 화면의 저장 막대는 쪽 맨 끝(폼 밖, `form="plan-form"`)이다.

## 베타 F 묶음이 바꾼 규칙
- 쓰기 잠금 대기 초과는 어디서든 503: SQLite "잠김"(`guards.is_busy_error`: BUSY·LOCKED 와 하위 코드) `OperationalError` 는 `main._operational_error_handler` 가 `WriteBusy` 와 같은 "잠시 후 다시 시도" 화면으로 보낸다 (그 밖의 `OperationalError` 는 500). 만들기의 폼 표 차지(`Once.claim`)·결과 적기·지우기도 잠금에 막힐 수 있어, 못 풀었으면(`release`) 표를 기억해 뒀다가 같은 표로 다시 오면 이어받고(`_ABANDONED`: 집합에서 빼는 것이 관문이라 한 제출만 이어받는다, 베타 G), 결과 적기·`keep` 이 잠겨 실패해도 응답은 보낸다.
- 고객용 PPT 사본 경로 규칙은 위 베타 E 줄의 새 문장이 정본이다. 작성자 말투(`AUTHOR_INSTRUCTION_PATTERNS`)는 어림이라 한 줄을 분명한 규칙으로 가를 수 없으면 슬라이드에 둔다 (내부 검토용 PPT 와 확인할 점 상자가 안전망): `…필요`·`…요망`·`…하세요`·`…할 것` 은 대상이 문서 값(금액·수치·절감률·가격·단가·일정·날짜·비율·건수·사례·레퍼런스·근거·내용 …)이거나 줄이 동사뿐이거나 `[확인 필요]`·`확인 필요:`·`확인 필요 - 견적팀`·`확인 필요(영업팀)` 처럼 이름표·괄호가 붙을 때만 옮긴다. `네트워크 구성 확인 필요`·`현장 여건 검토 요망`·`제안 내용을 검토해 주시기 바랍니다`·`TODO 앱 연동`·`담당: OOO 팀` 은 고객 문장이다. 알려진 한계: 앞 묶음이 옮기라고 한 `보안 정책을 반드시 명시`·`도입 전 … 확인 필요` 와 같은 모양이라 `법적 기준을 반드시 명시` 도 옮겨진다 (`도입 전 … 귀사 … 확인 필요` 는 고객 쪽 조건이라 베타 I 부터 둔다). `…필요`·`…요망`·`…예정` 의 가름은 아래 베타 I 가 정본이다.
- 로그인 문제 분류(`runner._AUTH_PATTERNS`)는 낱말 `401`·`oauth` 만으로 보지 않는다: `API Error: 401`·`HTTP 401`·`status 401`·`401 Unauthorized`, `oauth (error|token|…)`, `authentication_error`, `invalid x-api-key`, `Could not resolve authentication method`, `must be logged in`, `Unauthenticated`, `claude login` 같은 표현만. 분류 순서는 로그인 → 한도(`429` 는 상태 줄로만) → 네트워크·시간 초과. 0 이 아닌 종료 코드에 JSON 결과가 없으면 JSON 이 아닌 표준 출력도 표준 오류와 함께 분류한다 (`error_text`, 스트리밍 실행도 JSON 이 아닌 줄을 모은다).
- 처리기가 꺼진 서버의 시작 복구(`research.recover_runs(worker_on=False)`)는 제안 작업을 만들지 않는다 (돌지 않는 대기 줄이 생기지 않게). 분야가 모두 끝난 조사는 "진행 중"으로 남고 상태 화면이 "AI 처리기가 꺼져 있어 …"를 알리며, 처리기를 켠 서버가 시작될 때 이어서 만든다.
- AI 꺼짐 문: 로그인·권한 → 꺼짐 순서. 쓴 글이 있는 라우터(`/activities/draft` 메모, 제안 대화 `message`, 구성안 `instruction`)는 `@keeps_text(view)` 로 글을 채운 같은 화면을 409 로 다시 그리고(폼 표는 쓰지 않는다, 알림 `ai_off`), `/intake/{id}/analyze` 는 고친 메모만 저장하고 묶음 화면으로 보낸다(베타 G: 메모가 너무 길면 보통 경로와 같은 400 화면). 제안 화면 409 에는 AI 꺼짐 줄(`ai_note`) 하나만 보인다 (알림·입력칸 오류를 얹지 않는다). 글이 비었으면 보통의 돌려보내기다. 막힌 AI 버튼이 있는 화면에는 화면마다 `ai_note(aig, id=…)` 한 줄과 `ai_attrs(aig, by=…)` 의 `aria-describedby`.
- 상단 줄 AI 상태의 "마지막으로 끝난 작업" 질의는 `LIMIT 1` 이고 `ai_jobs.finished_at` 에 색인(`ix_ai_jobs_finished_at`)이 있다 (옛 DB 는 `migrate.ADDED_INDEXES` 가 시작 때 더한다).

## 베타 G 묶음이 바꾼 규칙
- 고객용 PPT 사본 경로(`deck.has_internal_mark`): 글을 NFKC·영폭 글자 제거·`%2F`/`%5C` 되돌리기 뒤에 본다. 번호 바로 뒤에는 **단위**(`개사 개 건 종 명 곳 인당 대 억 만 천 % G 년 월 일 차 배 회 원 …`, `2.5억`·`3~5종`·`5G/LTE`·`100명/월`)만 남기고 조사·`번`·`호`·`_v2` 같은 다른 글자가 붙으면 경로로 지운다(단위 뒤에 확장자가 오면 경로). `//`·`/./` 도 한 구분자다. 닻 있는 머리말(`출처:/`·`~/`·`C:/`·`/`·`./`·`file://`)에는 주소 판정을 하지 않고, 닻 없는 머리말은 첫 마디만 주소로 본다. 일반 폴더 머리말(`data/solutions/3.md`)은 번호 뒤에 확장자나 `/card.md` 꼴이 있을 때만 파일 경로로 지운다(`intranet/solutions/3` 는 남김). 표 머리글(`columns`)도 `_scrub_customer` 가 거른다(칸을 비우고 `removed` 에 센다). 알려진 한계: 표지(커버)의 글머리는 그려지지 않는데도 걸러지면 `removed` 에 센다.
- 작성자 말투(베타 I 가 앞말 길이로 다시 정했다: 아래 베타 I 가 정본): `…필요`·`…요망`·`…예정` 은 문서 값 낱말(`_DOC`)이 동사 앞 두 낱말 안에 있을 때만 옮긴다(`_NEAR`; 베타 H 가 줄 어디서든으로 넓혔다가 베타 I 가 되돌렸다). 앞말이 길면 고객 약속·조건으로 보아 둔다. `예정` 은 `작성|기재|기입|삽입 예정` 한 줄이거나 `<문서 값 낱말 포함 두 낱말 이내> <동사> 예정`. 맨 앞 `TODO:`·`TBD:` 와 `이 슬라이드는 삭제할 것` 은 옮긴다. `하세요`·`할 것` 꼴에서 "검토" 는 뺀다.
- 쓰기는 한 트랜잭션: 제안 대화 메시지는 `start_job(rows=[…])` 로 AI 작업과, 올리기 "다시 정리"의 고친 메모는 `start_analysis(note=…)` 로 정리 작업과 함께 커밋한다 (잠금에 막혀 503 이어도 메시지·메모만 남지 않는다). 새 POST 가 "저장 + 작업 넣기" 를 하면 둘을 같은 커밋에 넣는다 (제안 건 만들기도 `start_job` 이 새 제안 건을 작업과 한 커밋에 넣는다. AI 꺼짐이면 제안 건만 저장한다). 기록을 두 번 이상 커밋하는 POST 는 아래 "베타 H" 의 네 가지 예외와 "베타 I" 의 다섯째 예외뿐이다 (시험이 아니라 POST 라우터와 그 라이브러리 호출을 훑어 본 결과).
- 폼 표 이어받기(`guards._take_abandoned`): 잠금 때문에 못 푼 표의 기억(`_ABANDONED`)에서 빼는 데 성공한 제출 하나만 이어받는다. DB 열이 아닌 프로세스 안 기억이다(풀지 못한 순간 DB 가 잠겨 있어 열을 적을 수 없다). 다른 프로세스에는 보이지 않는다. 표를 지울 때(`purge_tokens`) 남은 기억도 치운다.
- 오류 분류(`runner._AUTH_PATTERNS`·`_LIMIT_PATTERN`·`_PROXY_PATTERN`): `ANTHROPIC_API_KEY is not set`·`API Error (401)`·`{"status":401}` 은 로그인, `status code 429`·`API Error (429)`·`Credit balance is too low` 는 한도, `407 Proxy Authentication Required` 는 네트워크, `unauthorized tool use` 는 로그인이 아니다. 오류 글은 저장·표시 전에 `runner.redact` 를 거친다 (`ClaudeError` 가 만들 때 한 번, 대기열이 예상 밖 예외 글에도). 무엇을 가리는지는 아래 베타 I 가 정본이다 (G 의 `sk-ant-…`·`*_API_KEY=`·`Authorization: Bearer`·`x-api-key:` 에서 H 를 거쳐 I 에서 바뀌었다).
- AI 꺼짐 화면: 처리기가 꺼진 동안 리서치 진행 조각(`_run_status.html`)은 5초 다시 부르기를 하지 않고 대기 순번 대신 "대기 중". 한 화면에 꺼짐 줄은 하나(리서치 설정의 조각은 `?note=0`, 실행 화면은 진행 중일 때 조각만). 제안 상세의 PPT 폼 `back` 은 주소가 아니라 넣는 화면이 `{% with back=… %}` 로 정한다.

- 고객용 PPT 사본 경로(`deck.has_internal_mark`): 센 단위(개사·개·건·종·명·곳·년·월·일·회·배·억·천·원·단계·시간…, `KB MB GB Mbps Gbps`·`K`) + 조사·접미(`가 이 을 를 의 에 에서 에는 로 와 도 만 까지 간 씩 급 …`)는 수량이라 남긴다(`partners/2개사가`, `customers/100명의`, `solutions/3개를`, `projects/6개월의`, `research/2026년에는`, `solutions/100MB`). 약한 단위(`만 인 대 위 등 분 차 조 % G D M x` 서수)는 낱말 끝일 때만 수량이고 앞 단위에 잇지 않는다(`3조차`·`3%a`·`3%의`·`3대로`·`3만`·`3를` 은 경로). 파일 확장자는 1~10자(`.markdown`), 머리말의 `..`/`.` 마디(`solutions/../solutions/3`)는 경로다. 글을 맞출 때 유니코드 분류 Cf 전부·변형 선택자·결합 낱말 이음 글자·한글 채움 글자를 지우고, 슬래시를 닮은 글자(`∕ ⁄ ⧸ ╱ ⟋`)·역슬래시를 닮은 글자(`∖ ⧵`)와 개체 참조(`&#047;`·`&#x02F;`·`&#47`·`&#92;`·`&bsol;`·`&amp;#47;`), 몇 번 부호화한 `%25…252F` 를 구분자로 되돌린다. 낱말 하나를 한 번만 훑어 머리말·꼬리 사실을 모아 두고 후보마다 이진 탐색으로 묻는다: 길이 한도가 없고(베타 H 의 300자 한도는 없앴다) 아무리 긴 줄도 선형이다(1MB 시험). 긴 주소(`https://…/solutions/3.html`)는 머리말이 아무리 길어도 남기고, 긴 닻 있는 경로(`/…/solutions/3`, `C:/…`)는 지운다. 알려진 한계: `3G망`·`24h`·`customers/3만 명`·`customers/5인`·`solutions/1위를`·`customers/50%를` 처럼 약한 단위나 영문 단위에 낱말·조사가 붙은 수량은 경로로 지우고(안전한 쪽), 일반 폴더 머리말의 맨 번호 뒤에 `.`·`.한글` 만 붙은 것(`data/solutions/3.`)과 `&#473`(번호와 구별 못 함)은 남는다.
- 작성자 말투(`proposals.is_author_instruction`): `…필요|요망|예정` 은 줄 끝 `<동사> 필요|요망|예정` 의 **앞말 길이**로 가른다. 앞말이 없고 동사만(`확인 필요`) 또는 앞말이 한두 낱말이고 그 안에 문서 값 낱말(`_DOC_NEAR`)·그림 자리(`로고·사진·도표…`, 동사 바로 앞이면 넉 낱말까지)·`담당자 이름`·`고객사 담당자`면 옮긴다. 앞말이 길면(`납품 후 검수 기간 확인 필요`, `가격은 별도 견적서에 기재 예정`) 고객 약속·조건이라 둔다. 길어도 옮기는 분명한 표지: `실제 … (으)로 교체`, `산출` + 추가·보강·확인, `추후 작성|기재|보완|업데이트 (예정)`, `<문서 값>은 … 후 기재|기입|작성|삽입 예정`(`…에 기재 예정` 은 고객 약속), `이 슬라이드(장·페이지·쪽) 삭제`(사이에 고객·관리자·사용자·직접·`…에서` 가 끼면 고객 문장). `수치 확인 필요함`·`수치 확인이 필요`·`금액 확인 필요!` 도 같은 규칙. 문서 값 낱말 뒤 `.*` 로 줄 끝을 찾던 규칙은 첫 문서 값 낱말 뒤에서 한 번만 찾고(`_DOC_THEN`), 줄 끝 정리(`_strip_line`)도 한 번 훑는다: 1MB 줄도 선형. 알려진 한계: 두 낱말 앞말 + 문서 값 낱말(`장비 수량 확인 필요`, `계약 기간 확인 필요`, `추가 예산 검토 필요`)은 `도입 시기 확인 필요` 와 가를 수 없어 옮긴다(G·H 와 같다). `고객 로고 삽입`·`레퍼런스 넣기`·`XX% 절감` 같은 줄은 규칙이 없어 슬라이드에 둔다. `귀사` 가 든 `도입 전 … 확인 필요` 는 고객 쪽 조건이라 둔다.
- 오류 글 가리기(`runner.redact`)는 **이름 규칙**이다: 정확한 비밀 이름(`token`·`api_key`·`secret`·`password`·`passphrase`·`credentials`·`auth`·`authorization`·`private_key`, `ANTHROPIC_`·`MY_`·`x-`·`access_` 같은 이름 조각은 붙어도 된다) 바로 뒤에 `=`·`:`·`=>`·`->`·`is`·`(`·`%3D`·`KEY=\` 다음 줄이 오면 값이 짧아도 가린다(`token=abc`, `x-api-key: short1`, `ANTHROPIC_API_KEY=abcdefghijk`). 따옴표 값은 닫는 따옴표까지(닫지 않았으면 줄 끝까지, 세 글자 이상), `{…}`·`[…]` 값은 닫는 괄호까지. 이름이 더 긴 낱말의 앞부분이면 그대로 둔다(`tokens`·`tokenizer`·`token_path`·`token_type`·`secretary`·`passwordless`·`apiKeySource`). 값이 진단 글이면 그대로 둔다: 진단 낱말(`not set`·`missing`·`required`·`expired`·`invalid`·`none`·`undefined` …), 소문자 낱말로 이어진 문장(`header is required`), 소문자 스네이크 낱말(`invalid_request_error`), `***`·`<key>`, `:` 뒤 한글 문장, `Unexpected token: '}'`. 값 모양을 보는 것: `sk-ant-…`·`sk-proj-…`·`sk-<20자>`·`Bearer …`·JWT·`ghp_…`·`AKIA…`·PEM 개인 키·`://user:pass@`·`?key=…` 쿼리. 이름 뒤 빈칸만 오는 `x-api-key X`·`--token X` 는 값이 비밀 모양일 때만. 반복 수를 한정해 1MB 도 선형. 알려진 한계: `customApiKeyResponses=…` 처럼 이름 뒤에 낱말이 이어진 이름·`Authorization: Bearer` 다음 줄 값·이름 없는 값은 못 가린다. 진단 낱말 목록 밖의 한 낱말(`password: incorrect2`)은 가린다.
- 오류 분류: `407` 은 `statusCode=407`·`"status": 407`·`{"statusCode":407}`·`API Error (407)`·`HTTP 407`·`Error: 407`·`code=407`·`proxy auth…` 일 때 네트워크이고 `error: 407 files could not be read` 는 아니다. 로그인(`_AUTH_PATTERNS`)은 Claude 이름(`ANTHROPIC_…`·`CLAUDE_…` 로 시작하는 `*_API_KEY|*_AUTH_TOKEN|*_OAUTH_TOKEN`)이 `: not set`·`is not set`·`isn't set`·`is empty`·`required`·`missing`·`Missing ANTHROPIC_API_KEY` 일 때와 앞에 다른 낱말이 없는 `api key is invalid|missing|not set` 일 때뿐이다(`OpenAI api key is missing`·`Tavily API key is invalid`·`the weather api key is not set`·`invalid credentials for MCP server x`·`invalid token in JSON`·`invalid token at position 3` 은 아니다).
- 솔루션 자료 여러 개 올리기(`files.upload_files`): 진짜 SQLite 쓰기 잠금 아래에서 `WriteBusy`(번호 표시 잠금)와 `OperationalError`(저장·커밋 잠금)를 같이 잡는다. **저장된 파일이 하나도 없는 채로** 막히면 503, 앞에 저장된 파일이 있으면 200 "저장하지 못한 파일: …(앞의 파일은 저장했습니다)". `_save_upload` 는 `saved`/`too_big`/`duplicate` 를 돌려주고 건너뛴 중복·큰 파일은 저장으로 세지 않는다. `db.rollback()` 이 로그인 사용자 줄을 낡은 값으로 만들어 닫힌 세션에서 오류 화면이 `DetachedInstanceError`(500)가 되던 것은 `get_db` 가 세션을 닫기 전에 사용자 줄을 한 번 다시 읽어 막는다(`db._keep_user_loaded`): 라우터가 스스로 `rollback()` 한 뒤 `WriteBusy`·`StaleWrite` 를 내는 어느 화면에도 같다.
- 관리 › 시스템: `claude --version` 은 `system.run_bounded`(`Popen`, 입력 막음)로 돌고 제한을 넘으면 프로세스 나무째 죽인다(POSIX: `start_new_session` + `killpg`, Windows: `taskkill /F /T /PID`; Windows 의 npm `.cmd` 껍데기 → node 를 죽이지 못해 파이프가 끝나지 않던 문제. 한정 없는 `communicate()` 는 부르지 않는다). 첫 줄은 200자(`VERSION_LINE_MAX`)까지만 보이고 캐시한다. 캐시가 비었을 때 동시에 열린 화면은 잠금(`admin._CHECK_LOCK`) 안에서 한 번만 점검한다. 시험은 POSIX 경로(손자가 파이프를 쥔 스크립트)와 Windows 가지의 `taskkill` 선택(모의)만 했고, **Windows 에서 실제 `.cmd` 껍데기는 확인하지 못했다**.
- 쓰기는 한 트랜잭션(베타 I): 올리기 "다시 정리"(`POST /intake/{id}/analyze`)는 메모와 정리 작업을 한 트랜잭션으로 저장하지만, 그 앞의 작업 폴더 준비(`prepare_workdir`)가 파일 읽기 상태를 따로 커밋한다 — 다섯째 예외(위 베타 H 의 예외 목록 ⑤).

## 베타 J 묶음이 바꾼 규칙
- 회귀표(`tests/test_beta_i.py`)가 여전히 정본이다. 이 묶음이 고친 줄은 거기 더했고(`DECK_*`·`AUTHOR_*`·`MASK`·`LEAVE`·`CLASSIFY`), **모든 `MASK` 줄에는 사라져야 하는 값(`gone`)이 있고**(`***` 만 보는 줄은 없다) `MASK`·`LEAVE` 는 두 번 가려도 같아야 한다(`redact(redact(x)) == redact(x)`). 1MB 선형 시험은 시계 한도 대신 100KB 대비 시간 비율(`tests/test_beta_j.py` 의 `_ratio_ok`)이나 넉넉한 한도다. 시험 소스에는 비밀 모양 글자(`sk-ant-`·`ghp_`·`AKIA…`·`-----BEGIN`)를 그대로 두지 않고 이어 붙인다(공개 저장소의 비밀 검사기가 잡지 않게).
- 오류 분류(`runner.classify_error`): 환경 변수 이름 뒤 `\s*[:\s]\s*` 는 제곱이어서 `(?:\s*:\s*|\s+)` 로 갈랐다. 분류·가리기에 쓰는 글은 `MAX_TEXT`(20만 자)를 넘으면 앞 절반 + 뒤 절반만 쓴다(상태 줄은 처음이나 끝에 있다. `runner._cap`). 규칙 본체는 자르지 않는 `_classify`·`_redact_all` 이고 선형 시험은 이것을 부른다. 이름 없는 `API key` 글(`The API key is invalid`·`Provided API key is invalid`·`API key expired`·`API key is not valid`)은 Claude 로그인이고, 다른 업체·MCP 서버 이름이 든 글(`OpenAI API key …`·`… is invalid for MCP server x`)은 아니다. `ANTHROPIC_API_KEY not found`·`Could not find ANTHROPIC_API_KEY` 도 로그인. 프록시는 `proxy auth(entication) required`·`407 Proxy Auth`·`statusCode=407` 같은 상태 꼴만 네트워크이고(`exit code: 407`·`mcp-proxy auth ok`·`proxy auth plugin loaded` 는 아니다) 같은 글의 로그인·한도 신호를 가리지 않는다(`mcp-proxy auth ok; rate limit exceeded` → 한도).
- 비밀 가리기(`runner.redact`): `sk-ant-…` 는 왼쪽 경계 없이(`KEY_sk-ant-…`·`\nsk-ant-…`·`한글sk-ant-…`) 꼬리의 `.`·`/`·`+`·`=` 까지 가린다(숫자가 없고 16자 미만인 `risk-ant-colony` 는 둔다). `ghp_…`·`github_pat_…` 도 왼쪽 경계가 없다. 짧은 이름 `pass`·`pwd`·`pw`·`auth` 는 이름 전체일 때만 본다(`compass`·`bypass`·`OAuth`·`OLDPWD` 는 이름이 아니다). `max_token`·`min_token` 은 한도 값. 새 이름: `SECRET_KEY_BASE`·`API_KEY_V2`(꼬리 `_v2`)·`ANTHROPIC_KEY`·`ACCESS_KEY`·`ENCRYPTION_KEY`·`SIGNING_KEY`·`LICENSE_KEY`·`DB_PW`·`비밀번호`·`토큰`·`API 키`. 이름은 비밀이어도 값이 다른 뜻이면 둔다: `PWD=/home/…`·`credentials: /home/kim/.claude/.credentials.json`(경로), `auth: 401`·`pass: 3`(숫자), `auth: OAuth`(방식), `getAccessToken(/usr/lib/cli.js:1:2)`(스택 줄), `The token '--verbose' is not recognized`(옵션), `Cookie: disabled`. `{"Authorization":["Bearer X"]}` 는 값 전체, 주소 속 `https://user:p@ssX@proxy` 는 마지막 `@` 앞까지, `http://TOKEN@proxy`(`ssh://git@host` 는 둔다), `\"api_key\": \"X\"`, `-u user:X`, 줄바꿈이 글자 `\n` 으로 든 PEM(끝 표지까지, 본문 8000자까지)도 가린다.
- 알려진 한계(가리기): 따로 접힌 JSON 안의 안쪽 객체(`"auth": {"nested": {"pw": "X"}}`), 블록 스칼라(`api_key: |` 다음 줄), 형식 없는 프록시 자격(`proxy=user:X@host`), `--key X`·`-p X`·`--auth user:X`, 개체·퍼센트로 쓴 구분자(`api_key&#61;X`·`api_key%3AX`·`\u003d`), 비밀번호 속 `/`(`https://user:pa/ssX@proxy`), `session=`·`SESSION_ID`·`TOKEN_VALUE`·`AWS_ACCESS_KEY_ID`, 낱말이 이어진 비밀번호(`password: correct horse X`), 이름이 낱말로 이어진 이름(`customApiKeyResponses`). 이름 없는 값은 모양을 아는 것(`sk-ant-`·`ghp_`·`AKIA`·JWT·`Bearer`)만 가린다.
- 작성자 말투(`proposals.is_author_instruction`): 문서 값 낱말은 `_DOC_NEAR`, 그림 낱말(도면·사진·이미지 …)은 앞말에 장소 낱말(`_SITE_WORD`: 현장·설치·위치·건물·시설·CCTV·장비·센서 …)이 없을 때만 센다(`현장 도면 확인 필요`·`CCTV 이미지 확인 필요`·`현장 사진 첨부 필요` 는 고객 쪽 일). 앞말이 **모두 문서 값 낱말**(약어 ROI·KPI·TCO·BEP, 수량 `30%는`·`2건` 포함)이면 길이와 상관없이 옮긴다(`절감률 수치 근거 확인 필요`, `레퍼런스 사례 2건 추가 필요`). 앞말이 `이`·`위`·`아래`·`여기에`·`이 부분`·`해당 슬라이드` 같은 지시어로 시작하고 문서 값 낱말이 있으면 길어도 옮긴다(`이 금액은 다시 확인 필요`, `여기에 고객 사례 추가 필요`). `수정 필요` 도 `…내용으로` 처럼 세 낱말 안에 문서 값이 끝에 있으면 옮긴다(`고객사 맞춤 내용으로 수정 필요`). `추후 …`(`_is_later_fill`)는 앞말이 없거나 문서 값 낱말이 든 네 낱말 이내일 때만(`수치는 추후 업데이트`; `기능은 추후 업데이트 예정`·`상세 일정은 추후 확인` 은 고객 약속). `실제 … 로 교체`(`_is_real_value`)는 사이에 문서 값 낱말이나 `값` 이 있을 때만(`노후 장비를 실제 운영 장비로 교체`·`실제 운영 환경으로 교체` 는 고객 쪽 일). `… 필요`(`_is_source_need`)는 `출처|근거` 이고 앞말이 없거나 문서 값 낱말 하나일 때만(`증빙 자료 필요`·`법적 근거 필요`·`추가 자료 필요` 는 고객 문장). 알려진 한계: 이 어림은 규칙이라 `이 장비 수량 확인 필요` 처럼 지시어 + 문서 값 낱말은 고객 문장이어도 옮긴다.
- 고객용 PPT 사본 경로(`deck.has_internal_mark`): 단위 뒤 확장자는 **단위·번호 바로 뒤**(`3개.md`)나 구분자 뒤 마디(`3개/card.md`)에서만 본다(`file_tail`): 같은 낱말 먼 곳의 `(kt.com)`·`(v2.0)` 은 확장자가 아니다(`partners/2개사(kt.com)`·`customers/100명(2026.11 기준)`·`projects/3개월(2026.1~2026.3)` 은 수량). 번호는 천 단위 쉼표를 포함한다(`customers/1,200명`). 다른 단위와 이어 쓰지 않는 단위 `안 편 자 중화 중 MM x<숫자>`(`solutions/3안`·`research/3편`·`partners/3자 협력`·`solutions/2중화`·`projects/3MM`·`solutions/24x7`)와 `억원대|억대|주차|일차|회차` 를 더했다. 사본 폴더 머리말(`knowledge/…`)이 있으면 단위가 붙어도 경로다(`knowledge/solutions/3일`, `C:\data\knowledge\solutions\3개`). 번호가 개체·퍼센트로 쓰인 것(`solutions/&#51;`·`solutions/&#x33;`·`solutions%2F%33`)도 되돌려 본다(숫자 글자만; `&#115;olutions` 처럼 폴더 이름을 개체로 쓴 것은 못 본다). 번호 없는 사본·데이터 파일(`knowledge/index.md`·`knowledge/solutions/card.md`·`data/app.db`·`data/solbox.db`, 주소 속은 제외)도 지운다. 알려진 한계: `data/solutions/3` 같은 일반 폴더 머리말의 맨 번호(확장자 없음)와 `https://solbox.kt.local:8443/solutions/3` 같은 앱 안 주소는 남는다 (일반 문장·주소와 구별할 수 없다).
- 점검 명령(`system.run_bounded`): 표준 출력·표준 오류를 읽기 스레드가 `OUTPUT_CAP`(64KB)까지만 담고 나머지는 읽어서 버린다(자식이 파이프가 차서 멈추지 않는다). 파이프는 읽기가 끝난 것만 닫고 읽는 스레드가 쥔 것은 버린다(읽는 쪽이 쥔 파일 객체의 `close()` 는 그 스레드를 기다리며 멈출 수 있다). 자식이 끝났는데 손자가 파이프를 쥐고 있으면 남은 시간까지만 기다린 뒤 프로세스 그룹을 죽이고 읽은 만큼 돌려준다. 보이는 버전 줄은 제어 문자(NUL·ESC·`\r`)를 뺀 첫 줄 200자. `runner._reap` 은 Windows 에서 파이프를 닫지 않고 버리고(POSIX 는 그대로 닫는다) 어디서도 한정 없이 기다리지 않는다 — `_CHECK_LOCK` 을 쥔 동안 끝없이 멈추는 단계가 없다. **Windows 는 실제로 확인하지 못했다** (모의와 이유로만).
- `get_db` 닫기(`db._keep_user_loaded`)의 사용자 줄 다시 읽기는 `session.no_autoflush` 안이다: 롤백 뒤 세션에 남은 새 줄이 닫는 길에서 INSERT 되어 쓰기 잠금에 막히지 않는다 (`tests/test_beta_j.py` 가 진짜 `BEGIN IMMEDIATE` 아래에서 본다).
