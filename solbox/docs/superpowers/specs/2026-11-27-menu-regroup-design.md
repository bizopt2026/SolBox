# 메뉴 재편 (1단계) 설계

2026-11-27, 사용자 승인.

## 왜
영업 메뉴에 섞여 있던 BM(사업 틀)을 사업기획으로 떼고, 공급 쪽 재료 묶음 "발굴"을 "소스"로 바꾼다. 뒤이어 2단계(소스 › 고객니즈 관리)와 3단계(사업기획 › 기존 BM·신규 BM, AI 신규 BM 개발)를 얹을 자리를 만든다.

## 바꾸는 것
| 묶음(코드) | 메뉴 |
|---|---|
| 오늘 `today` | 그대로 |
| 과제 `work` | 그대로 |
| 소스 `source` (옛 발굴 `discover`) | 솔루션 · 파트너 · 리서치 |
| 사업기획 `planning` (새 묶음) | BM |
| 영업 `sales` | 고객관리 · 영업기회 · 제안 · 프로젝트 |
| 관리 `admin` | 그대로 |

- 묶음 순서: 소스 → 사업기획 → 영업 (소스로 BM을 만들고 BM으로 영업한다).
- 고객은 메뉴 이름(`ObjectType.nav`)과 경로 줄만 "고객관리". 대상 이름(`label`)은 "고객" 그대로 (상세·연결·사본·프롬프트).
- 솔루션 "발굴 단계", 영업기회 "발굴" 단계, 리서치 "발굴 방향 제안" 은 메뉴가 아니라 그대로 둔다.
- 휴대폰 아래 탭은 바뀌지 않는다.

## 하지 않는 것
- DB·패키지 변경 없음.
- 고객니즈 메뉴(2단계), 기존 BM·신규 BM 구분과 AI(3단계)는 여기서 하지 않는다. 빈 메뉴를 미리 두지 않는다.

## 검토한 방법
메뉴는 `app/ontology.py` 의 `NAV_GROUPS`·`NAV_ITEMS`·`ObjectType.nav_group` 한 곳에서 그려지므로 그 정의만 고친다 (다른 방법은 이 정의를 우회하게 되어 맞지 않는다). 묶음 코드는 화면에 나오지 않지만 뜻에 맞게 `discover` → `source` 로 바꾸고 `planning` 을 더한다.
