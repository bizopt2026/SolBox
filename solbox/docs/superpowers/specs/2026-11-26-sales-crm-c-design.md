# 영업 CRM 보강 C 단계: 파이프라인 보드, 체류·전환 분석과 AI 해석

작성 2026-11-26. 상태: **승인 (2026-11-26)**. 화면 시안: claude.ai 아티팩트 "솔박스 영업 C 단계 시안". 로드맵·원칙은 `2026-11-26-sales-crm-a-design.md` 2장.

## 1. 왜 하나

A·B 단계로 영업기회마다 금액·담당·단계 이력·사유가 쌓인다. C 단계는 이 데이터를 **한눈에 움직이고(보드)**, **어디서 막히는지 숫자로 보는(분석)** 화면이다. Pipedrive 의 칸반 보드와 Salesforce 의 퍼널·단계 체류 리포트를 본뜬다. AI 는 숫자를 지어내지 않도록 **코드가 계산한 숫자를 읽고 해석 글만** 쓴다.

## 2. 정해진 것 (사용자 결정 2026-11-26)

- 보드는 **영업기회 목록의 보기 전환** ([표 | 보드]). 목록의 걸러 보기(담당·멈춘 건·AI 제안·사업방식·검색)를 그대로 쓴다. 메뉴는 늘리지 않는다.
- 보드 열: **발굴·제안 중·협상 3열 + 오른쪽에 최근 30일 수주·실패(접힘)**. 수주·실패 칸에 끌어다 놓으면 사유 화면으로 간다. 보류는 열 대신 건수 링크.
- 분석 화면: **팀별 비교**와 **기간별 추이**.
- AI 해석: **분석 화면의 버튼**. 지금 걸러 본 숫자(기간·팀)를 읽고 쓴다. 마지막 해석은 남아 있다.

## 3. 목표 · 하지 않을 것 · 실패로 볼 것

목표
- 보드에서 진행 중 영업기회를 단계별 열로 보고, 끌어다 놓아 단계를 바꾼다 (스크립트 없이도 카드의 단계 단추로 바꿀 수 있다). 열마다 건수·금액 합.
- 분석 화면에서 기간·팀을 골라 수주율, 단계별 평균 체류일, 단계 간 전환율, 월별 수주·실패 추이, 수주·실패 사유 분포, 팀별 비교를 본다.
- [AI 해석]을 누르면 그 숫자로 "주목할 점·원인 추정·권하는 행동" 글을 받는다.

하지 않을 것
- 담당자(사람)별 비교 (사용자가 고르지 않음; 20명이라 건수가 적어 들쭉날쭉), 사업방식·BM별 분석.
- 확률·가중 예측(8번, 고르지 않음).
- 보드에서 칸 값(금액 등) 고치기 — 카드는 상세로 이동만.
- 업무 보고에 해석 넣기 (사용자 결정: 버튼만).
- 새 DB 표·칸 (이번 단계는 **DB 변경 없음**: AI 해석은 작업 결과 `AIJob.result` 에 둔다).

실패로 볼 것
- 숫자가 틀리거나 뜻이 모호한 것 → 지표마다 한 줄 정의를 화면에 적고, 이력이 없는 기간("기록 전")은 빼고 몇 건을 뺐는지 알린다.
- AI 가 숫자를 지어내는 것 → AI 에는 코드가 계산한 숫자만 주고, 글 속 숫자는 그 숫자 중에서만 쓰라고 한다 (화면에 "이 숫자로 쓴 해석" 과 기준 시각).

## 4. 숫자의 정의 (`app/pipeline_stats.py` 한 곳)

- **기간**: 최근 90일(기본) / 이번 분기 / 지난 분기 / 올해 / 최근 12개월. 주소 `?period=90d|q|lq|y|12m`.
- **팀**: 전체(기본) / 팀 하나 (`?team=<번호>`). 영업기회의 팀은 **지금 담당의 팀** (A 단계 규칙. 사람이 팀을 옮기면 그 사람의 옛 건도 따라간다: 화면에 한 줄 알림).
- **세는 단위 (내 판단: 팀 업무 보고와 숫자를 맞춘다)**: 수주·실패는 **닫은 일(단계 이력의 `to_stage` 가 won·lost 인 줄)** 단위로 센다. 한 건이 실패 → 다시 진행 → 수주이면 그 기간에 실패 1·수주 1 이 모두 남는다 (`app/reports.py` 의 업무 보고 집계와 같은 기준). 그 닫은 일의 사유는 **같은 저장(같은 시각)의 필드 이력 `close_reason`** 에서 읽고(지금 `close_reason` 이 아니다), 금액은 그때의 금액(이력에서 그 시각 직전 값, 없으면 지금 값). 평균 수주 기간의 "수주한 때" 는 그 수주 줄의 시각.
- **단계에 머문 구간**: `opportunity_stage_changes` 를 영업기회마다 시간순으로 이어, 단계에 들어온 때 → 나간 때. 만든 줄(`from_stage` 빈 글)이 있으면 만든 때가 첫 단계의 시작. 이력 기능 전에 만든 영업기회(만든 줄이 없음)의 첫 구간은 시작을 몰라 **뺀다**("기록 전 n건").
- **평균 체류일(단계 S)**: 기간 안에 **끝난** S 구간들의 (나간 때 − 들어온 때) 평균과 중앙값(일). 따로 "지금 S 에 머무는 건의 평균 경과일".
- **전환율(S → 다음)**: 기간 안에 S 를 **떠난** 구간 중, 흐름에서 더 뒤 단계(진행 중 뒤 단계 또는 수주)로 간 비율. 실패·보류로 간 비율도 함께.
- **수주율**: 기간 안에 수주·실패로 닫힌 건 중 수주 비율 (보류는 넣지 않음). 수주 금액 합.
- **평균 수주 기간**: 기간 안에 수주한 건의 (수주한 때 − 만든 때) 평균 (만든 줄이 없으면 `created_at`).
- **월별 추이**: 기간을 달로 나눠 수주 건수·금액, 실패 건수.
- **사유 분포**: 기간 안의 닫은 일마다 그때 고른 사유별 건수 (수주·실패 따로).
- **팀별 비교 표**: 팀마다(팀 없음 포함) 진행 중 건수·금액, 기간 안 수주·실패·수주율, 단계별 평균 체류일, 멈춘 건 수.
- 계산은 영업기회·단계 이력을 한 번씩 읽어 파이썬에서 한다 (질의 수는 건수와 무관, 수백~수천 건 규모).

## 5. 동작

### 5.1 보드 (`GET /opportunities?view=board`)
- 목록과 같은 걸러 보기(검색·담당·사업방식·멈춘 건·AI 제안)를 적용한 뒤 진행 중 건을 열로 나눈다. 단계 탭(`?stage=`)은 보드에서는 숨긴다.
- 열 머리: 단계 이름 · 건수 · 금액 합 (금액 없는 건 수). 카드: 이름·고객·금액·담당(팀)·다음 할 일 날짜(지나면 빨강)·멈춘 사유 배지·AI 제안 배지, 정렬은 다음 할 일 날짜 → 금액.
- 오른쪽 접힌 칸: "최근 30일 수주 n · 실패 n" (이름·금액·사유). 보류 n건은 목록 링크.
- 단계 바꾸기:
  - JS 있음: 카드를 끌어 다른 열에 놓으면 `POST /opportunities/{id}/stage` (fetch, `back=board`). 수주·실패 칸에 놓으면 사유 화면으로 이동 (`/close?to=…&back=board`). 실패하면 카드를 제자리로 돌리고 알림.
  - JS 없음: 카드의 "단계 ▾" 펼침 안에 다른 단계 단추들 (같은 POST, `back=board`).
  - `back=board` 이면 `/stage`·`/close` 는 보드(지금 걸러 보기 유지)로 돌아가고 알림은 그대로 (`opportunity_stage…`, `opportunity_stage_open…`). `back` 은 정해진 값만 받는다.
- 좁은 화면: 열이 가로로 밀리고(한 열 85% 폭), 끌기 대신 "단계 ▾" 를 쓴다.
- 목록 머리의 [표 | 보드] 전환은 주소로만 기억한다.

### 5.2 분석 화면 (`GET /opportunities/analysis`)
- 영업기회 목록 머리에 "분석" 링크. 경로: 영업 › 영업기회 › 분석.
- 맨 위: 기간 탭, 팀 탭, 기준 시각, 정의 펼침("숫자는 이렇게 셉니다").
- 요약 칸 4개: 수주 건수·금액 / 실패 건수 / 수주율 / 평균 수주 기간.
- 단계별 표: 단계 · 평균 체류(중앙값) · 지금 머무는 건의 평균 경과 · 다음 단계로 간 비율 · 실패로 간 비율 · 표본 수. 이력이 없어 뺀 수.
- 월별 추이 막대(수주 금액 막대 + 수주·실패 건수), 서버가 그리는 SVG (외부 라이브러리 없음).
- 사유 분포 (수주·실패 가로 막대).
- 팀별 비교 표 (팀 탭이 "전체" 일 때).
- **AI 해석** 카드: [AI 해석 받기] (`POST /opportunities/analysis/ai`, `require_ai_on`, `AI_POSTS`) → 작업 `pipeline_insight`(입력: period, team). 처리기가 같은 함수로 숫자를 다시 계산해 JSON 으로 프롬프트에 넣는다 (도구 없음). 출력 `{"summary": 글, "highlights": [글], "causes": [글], "actions": [글]}` (항목 300자, 목록 5개). 결과는 작업 결과에 두고(입력에 기간 코드·팀·**계산된 시작·끝 날짜**·숫자 사본의 해시), 화면은 같은 기간 코드·팀의 가장 최근 끝난 해석을 "11월 26일 14:02 · 9월 1일~11월 26일 숫자 기준" 과 함께 보인다. 지금 숫자의 해시와 다르면 "그 뒤 숫자가 바뀌었어요 · 다시 받기" 를 붙인다 (내 판단: 지난 해석을 숨기지 않되 지금 숫자와 다른지 알린다). 진행 중이면 작업 상자.

## 6. 같이 고칠 것
- `app.js`: 보드 끌어 놓기 (진행만, 없어도 동작).
- 알림 표·`POST_NOTICES`(분석 AI), `AI_POSTS`·익명 시험 목록, `JOB_KINDS`·예상 시간.
- 도움말·화면구성도·`docs/ontology.md`(결정)·`docs/rules/대상과-데이터.md`(숫자 정의 한 곳).

## 7. 접근 방법 (고려한 것)
- **보드 위치**: (가) 목록의 보기 전환 / (나) 새 메뉴. → (가) (사용자 결정).
- **분석 계산**: (가) 파이썬에서 한 번에 / (나) SQL 집계. → (가). 단계 구간을 이어 붙이는 계산은 SQL 로 쓰기 어렵고, 규모(수천 건 이하)에서 충분히 빠르며, AI 처리기와 화면이 같은 함수를 쓴다.
- **AI 해석 저장**: (가) 작업 결과(`AIJob.result`) / (나) 새 표. → (가). 해석은 숫자 사본과 함께 남기만 하면 되고, 고치거나 반영할 상태가 없다. DB 변경을 피한다.
- **차트**: (가) 서버 SVG / (나) 차트 라이브러리. → (가). 사내망이라 CDN 을 쓰지 않는다는 규칙.

## 8. 시험 (요지)
- 숫자: 만든 줄·단계 이력으로 짠 영업기회로 체류(평균·중앙값)·전환·수주율·월별·사유·팀별 값이 정확히 나옴, 기록 전 제외 수, 기간 경계(포함/제외), 팀 없음.
- 보드: 열 배치·합계, 걸러 보기 유지, `back=board` 돌아가기(정해진 값만), 수주·실패는 사유 화면으로, JS 없는 단계 단추.
- 분석 화면: 탭·표·SVG 막대, 정의 펼침, 질의 수 일정.
- AI: 프롬프트에 숫자 JSON·"숫자를 지어내지 말 것"·도구 없음, 결과 표시(같은 기간·팀만), AI 꺼짐 문.
