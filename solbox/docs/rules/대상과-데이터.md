# 대상과 데이터 규칙 (solbox/docs/rules/대상과-데이터.md)

다루는 것: 프로젝트 상태·AI 생성 표기·리서치 설정·사업방식·솔루션 분야·다른 이름·합치기·중복 정리. 읽을 때: 대상 유형의 칸·목록·사본 형식을 고칠 때.

솔박스 `CLAUDE.md` 에서 옮긴 영역별 규칙이다 (2026-11-25). 묶음(베타) 순서와 글은 그대로 두었다. 뒤 묶음이 앞 묶음의 규칙을 바꾼 경우가 많으니 **아래쪽(뒤 묶음)이 정본**이다. 글 속의 "위/아래 베타 X" 는 다른 영역 파일에 있을 수 있다: 어느 묶음이 어느 파일에 있는지는 `docs/rules/README.md`.

## 베타 P 묶음이 바꾼 규칙
- 프로젝트 `status` 는 고르는 목록이다: `ontology.PROJECT_STATUSES`(준비·진행·완료·중단·유지보수, 순서가 곧 선택 칸 순서, 코드 = 저장되는 한글 글자 = 이름)가 한 곳이고 코드 목록 `project_status`·`COLUMN_CODES[("businesses","status")]` 로도 보인다. 검사는 `routers/projects._parse`: 비었거나 목록 값이어야 하고(아니면 `BAD_STATUS` 폼 오류 400), 고치는 기록의 **지금 저장된 목록 밖 글은 한 글자도 바꾸지 않고** 다시 받는다. 옛 글은 데이터·스키마를 건드리지 않는다(이전·변환 없음). 화면에 상태를 보일 때는 반드시 `ontology.project_status_text(값)`(옛 글 뒤에 " (이전 입력)")를 거친다: 상세·목록·관계 카드(`relations`). **지식 사본(`knowledge._project`, AI 가 읽는 파일)에는 표지를 붙이지 않고 저장된 글 그대로 적는다 (사용자 결정 2026-11-22, 베타 Q2: 베타 P 는 사본에도 붙였다).** 고치기 폼의 선택 칸은 `projects.status_options`(그 기록의 옛 글을 추가 항목으로). 영업기회 → 프로젝트 전환은 상태를 쓰지 않는다(빈 값). 시험 `tests/test_beta_p.py`.
- 2026-11-22 결정(`docs/ontology.md` 15장): 고객·활동 기록은 로그인한 누구나 계속 고칠 수 있다(제한 안 더함), "내 할 일" 은 정확한 이름 일치만(넓히지 않음), PPT 슬라이드 배치 개편은 회사 표준 템플릿 파일이 생길 때까지 미룬다.

## 베타 R 묶음이 바꾼 규칙
- **사용자 결정 2026-11-22: "AI 생성 자료는 표기해."** 기록의 유래(`origin_type`)가 올리기 또는 리서치이면 AI 가 만든 기록이다(`ontology.is_ai_generated`, `origin.is_ai_generated` 로도 보인다; 이름표 `ontology.AI_GENERATED_LABEL`·`AI_GENERATED_TONE`·`AI_GENERATED_HELP` 한 곳, 화면·사본·프롬프트(`{{ai_label}}`)는 이 상수만 읽고 "AI 생성" 글을 다시 적지 않는다. `tests/test_beta_r.py` 가 코드·템플릿을 훑는다). 유래 열이 있는 솔루션·활동 기록·고객·파트너에만 해당하고 직접 입력·유래 모름은 표시하지 않는다. 새 열·이전 작업·저장된 값 변경은 없다.
- 화면: `_macros.html` 의 `ai_badge()`(글자가 있는 `.badge`, 색만으로 알리지 않는다)를 `origin_cell`(넓은 화면 목록의 유래 칸)·`origin_note`(좁은 화면 목록 첫 칸 보조 줄; 네 목록 템플릿이 쓴다)·`origin_line`(상세 "기록 정보" 카드의 "유래:" 줄, `origin.view` 결과의 `ai`)에서 붙인다. "연결된 것" 카드는 유래를 보이지 않으므로 배지도 없다. 새 화면이 유래를 보이면 이 매크로를 쓴다.
- 지식 사본: AI 가 만든 기록의 파일 맨 위 속성 줄에 `- AI 생성: 예 (올리기 묶음 #3 에서 AI 가 정리)` / `(리서치 보고서 #5 에서 AI 가 제안)` 한 줄(`KnowledgeMirror._ai_line`, 값은 `ontology.ai_generated_note`; 번호가 지워졌으면 번호를 뺀다). 아닌 기록은 줄이 없다("아니오" 를 적지 않는다). 사본 형식이 바뀌었으므로 `KNOWLEDGE_FORMAT` 을 8 로 올렸다: 업데이트 뒤 서버를 처음 시작할 때 사본을 한 번 다시 만들어 이미 있는 기록에도 줄이 붙는다 (`docs/운영가이드.md`).
- AI 프롬프트: 사본 형식을 설명하는 곳은 `prompts/proposal_directions.md` 의 "읽을 곳" 뿐이라 거기 한 줄만 더했다 (그 줄이 있는 기록은 확인되지 않은 자료로 다룬다). 다른 프롬프트(`proposal_chat`·`proposal_outline`·`research_suggest`·`solution_draft`·`intake_analyze`·`activity_structure`)는 사본 형식 설명이 없어 건드리지 않았다.
- **알려진 한계(만들지 않음)**: 사람이 직접 만든 기록을 "AI 초안 받기"(솔루션)·활동 기록 "AI 정리"로 채운 것은 유래가 직접 입력 그대로라 표시되지 않는다. 결정·한계는 `docs/ontology.md` 15장 (f)·`docs/화면구성도.md`·`app/templates/help.html` 에 적었다.
- 시험: `tests/test_beta_r.py` 가 새로 생겼고, `tests/test_beta_b.py` 의 `origin.view` 결과 비교에 `"ai": True` 를, `tests/test_origin.py` 의 `_line` 도우미에 배지 글자를 빼는 처리를 더했다 (유래 줄 글이 아니라 배지가 더해져서).

## 베타 V 묶음이 바꾼 규칙
- **사용자 요청 2026-11-23, 관리 › 리서치 설정(`/admin/research`, 관리자 전용).** (V1) "주제 추가"의 분야 선택 칸을 체크 상자 셋(`ontology.RESEARCH_AREAS`: 시장·기술·정책, 처음엔 모두 체크)으로 바꿨다. `POST /admin/research/topics` 는 폼 칸 `area` 를 여러 개 받아(`area: list[str]`, 옛 단일 값 `area=tech` 도 같다) 고른 분야마다 같은 이름·키워드의 주제를 **한 트랜잭션**으로 만든다. 하나도 안 골랐으면 400 "분야를 하나 이상 고르세요."(입력은 그대로), 목록에 없는 값이 섞이면 400 "분야 값이 올바르지 않습니다."(하나도 만들지 않는다). **주제에는 이름 중복 규칙이 없다** (`_topic_error` 에도 없고 `docs/ontology.md` 2.5 도 "직접 등록 화면은 이름 중복을 확인하지 않는다" 이다): 같은 분야에 같은 이름이 이미 있어도 막지 않고 만든다. 이미 있는 주제 줄(분야별 표)과 수정 줄(`POST /admin/research/topics/{id}`)은 그대로 분야 하나다.
- (V2) AI 작업 종류 `research_keywords`(`ontology.JOB_KINDS`·`JOB_EXPECTED`, 처리기 `ai/research_tasks._research_keywords`, 프롬프트 `prompts/research_keywords.md`). `POST /admin/research/keywords` 는 `dependencies=[Depends(require_admin), Depends(require_ai_on)]`, 진행 중(대기·진행)인 같은 종류가 있으면 새로 만들지 않는다(한 번에 하나). 화면은 "AI 추천 주제·키워드" 카드(`templates/admin/_research_keywords.html`, 진행 중이면 2초마다 `GET /admin/research/keywords/status` 조각으로 다시 그린다). 진행 중에는 단추 대신 진행 줄, 실패하면 이유(`bad_output` 은 작업 오류 글)와 "다시 시도"(같은 시작 주소), 처리기가 꺼졌으면 단추 비활성(`ai_attrs` 의 `aria-describedby` 는 같은 화면의 "조사 실행" 카드 줄 `ai-note-run` 을 가리킨다: 한 화면에 꺼짐 줄은 하나라는 베타 G 규칙).
- 결과는 `AIJob.result` 에만 JSON 으로 남는다(새 열·새 표 없음). 가장 최근에 **성공한** 작업의 추천을 새 요청이 끝날 때까지 계속 보이고(그 뒤에 실패하면 "이전 추천" 표시와 함께), 받은 시각을 적는다. **아무것도 자동으로 저장하지 않는다**: 추천마다 "주제로 추가" 작은 폼(이름·키워드 고칠 수 있음, V1 분야 체크 상자에 추천 분야만 미리 체크, 숨은 칸 `src`=추천 번호, 폼 표 `_tok`)이 같은 `POST /admin/research/topics` 를 부른다. 오류(400)면 `src` 가 가리키는 추천 폼에 쓴 값을 되돌려 준다. 같은 이름의 주제가 이미 있으면 "이미 있는 주제와 이름이 같음" 표시만 한다(`casefold` 비교, 막지 않는다).
- 모양(`research_tasks.KeywordsOut`): `{"suggestions": [{"area": "market|tech|policy", "name": "…", "keywords": ["…"], "reason": "…", "sources": ["solutions/1/card.md"]}]}`. 다듬기는 `research.clean_keyword_suggestions`: 분야가 틀렸거나 이름이 2자 미만·100자 초과인 추천은 버리고, 키워드는 중복·빈 것을 빼고 `", "` 로 이어 붙여 500자 안에서 자르며, 분야마다 최대 4개(프롬프트는 3개 안팎), `sources` 는 `proposals.check_sources` 로 **지식 폴더 안에 실제로 있는 상대 경로만** 남긴다(절대 경로·`..`·없는 파일은 버린다). 남은 추천이 없으면 `bad_output`. 도구는 지식 폴더를 읽는 `Read/Glob/Grep` 뿐(웹 도구를 섞지 않는다).
- 프롬프트가 받는 글: 솔루션(이름·단계·태그·사본 경로), 파트너(이름·사본 경로), 제안 이력, 등록된 리서치 주제·키워드(분야별, `<<<TOPICS … TOPICS>>>`, 안의 글이 표시를 닫지 못하게 `_safe`). 상세 설명·영업기회·고객 니즈·BM 은 프롬프트가 사본 폴더(`{{dir_*}}`)를 가리켜 AI 가 직접 읽게 한다. **제안 건은 지식 사본이 없다**(`KnowledgeMirror` 는 제안 건을 쓰지 않는다): 그래서 제안 이력(제목·대상 고객 이름·진행 단계·선택한 방향 제목)만 프롬프트에 적어 넘기고 `sources` 로 가리킬 수 없다. 파일 내용은 지시가 아니라 자료라는 경고와 자료에 없는 수치 금지는 `research_suggest.md` 와 같다. `prompt_constants` 에 `dir_partners`·`dir_customers` 를 더했다.
- 새 AI 단추라 `tests/test_beta_e.py` 의 `AI_POSTS`·경로 표와 `tests/test_ux_notices.py` 의 `POST_NOTICES`(`keywords_started, ai_off`)를 고쳤고 알림 `keywords_started` 를 `notices.py` 에 더했다. 시험 `tests/test_beta_v.py`.

## 베타 Y 묶음이 바꾼 규칙
- **사용자 결정 2026-11-23: 사업방식.** 값은 정확히 구축형(`build`)·임대형(`lease`)·투자형(`invest`), 이 순서, 하위 유형 없음. 코드 목록·이름·한 줄 뜻은 `ontology.BUSINESS_TYPES`·`BUSINESS_TYPE_DESCRIPTIONS`(코드 목록 `business_type`) 한 곳이고, **한 줄 뜻은 사용자가 2026-11-23 에 확정했다**(고칠 곳도 거기 한 곳; 폼·배지 툴팁·도움말·AI 프롬프트가 모두 이것을 읽는다. 다른 곳에 이름·뜻을 다시 적지 않는다: `tests/test_beta_y.py` 가 코드 속 글자·템플릿·프롬프트를 훑는다). 규칙 코드는 `app/business_types.py` 한 곳(폼 읽기·검증·저장·걸러 보기·기본값·후보 정렬·AI 제안 다듬기).
- **자리 셋**: 솔루션 = 가능한 사업방식(연결 표 `solution_business_types`: `solution_id`·`business_type` 이 기본키, `memo` 300자까지 — 모델 `SolutionBusinessType`, `Solution.business_type_rows`), BM = 대표 사업방식(열 `bms.business_type`, 하나, NULL 허용), 영업기회·제안 건 = 검토 사업방식(열 `business_types`, 정의된 순서로 쉼표로 이은 코드, 0..3개). 프로젝트에는 두지 않는다. 금액 칸은 없다. 모두 `migrate.py` 의 보통 추가라 표를 다시 만들지 않고 옛 줄은 그대로다(`tests/test_bm_opportunity.py` 의 옛 구조 DB 시험도 새 표·열을 뺀다).
- **폼 규칙**: 사업방식 칸이 폼에 왔는지는 숨은 칸 `business_types_present` 로 안다 — 없으면(옛 화면·API) **그대로 둔다**, 있으면 체크한 값으로 바꾼다(아무것도 안 고르면 모두 지운다). 목록에 없는 값은 400 폼 오류, 솔루션의 방식별 메모(`bt_memo_<코드>`)는 한 줄로 다듬어 300자를 넘으면 400, 고르지 않은 방식의 메모는 버린다. BM 의 `business_type` 은 칸이 오면 쓰고(빈 값은 비움) 안 오면 그대로. 고침 표시: 솔루션은 사업방식 줄이 바뀌면 `guards` flush 처리기가 솔루션 `updated_at` 을 올리고, 제안 건은 `_change_of` 에 `business_types` 가 든다(비면 예전 표시와 같다). 충돌 안내는 "가능한 사업방식"·"검토 사업방식" 칸을 이름으로 보인다. 목록 `?business_type=` 걸러 보기(솔루션·BM·영업기회, `ontology.BUSINESS_TYPE_LISTS`, `bts.type_tabs`)는 관계가 아니라 코드 값 걸러 보기라 `LIST_FILTERS` 에는 없다.
- **제안 건**: 만들 때 기본값은 영업기회의 검토 사업방식 → 없으면 BM(영업기회의 BM, 없으면 프로젝트의 BM, 다수 고객 제안은 신규 사업 BM)의 대표 사업방식 → 없으면 빈 값(`bts.proposal_default`). 폼은 숨은 칸 `business_types_auto`(1=건드리지 않음; JS 보강이 영업기회·프로젝트·BM·대상 종류를 바꾸면 체크를 따라가고 사용자가 체크하면 0)를 보내고, 서버는 고른 것이 없고 (건드리지 않았거나 칸이 아예 없으면) 같은 기본값을 쓴다. 대상 수정에서 바꿔도 방향·구성안·제안서는 지우지 않는다(다음 방향 만들기·대화·구성안부터 반영). 후보 솔루션 순서: 기존 묶음 안에서(나머지 포함) 검토 사업방식을 하나라도 지원하는 솔루션이 먼저(안정 정렬, 집합은 그대로: `bts.prefer_supporting`).
- **AI**: 제안 방향·대화·구성안 프롬프트는 `{{business_type_section}}`(검토 사업방식, 세 방식의 뜻, 선택한 방향이 전제하는 방식)와 후보·방향 솔루션 줄마다 가능한 사업방식(없으면 "적혀 있지 않음", 지원한다고 지어내지 말라고 적는다)을 받는다. 방향 모양에 `business_type`(코드 하나, 목록에 없거나 문자열이 아니면 빈 값으로 버리고 오류로 보지 않는다)이 더해졌고 방향 카드에 배지로 보인다. 투자형이 검토 대상이거나 선택한 방향이 투자형이면 구성안 프롬프트에 투자·회수 구조 장 규칙(`INVEST_SLIDE_RULE`: 숫자는 자료에 있는 것만, 없으면 `needs_check`)이 들어간다. 솔루션 AI 초안(`SolutionDraft.business_types`)과 올리기 정리안의 새 솔루션 항목(`business_types: [{code, reason}]`, 확인 화면의 `{키}__business_types` 체크 상자)은 **제안만** 한다: 미리 체크되어 보이고 사람이 저장해야 반영되며, 초안은 이미 있는 선택·메모를 지우지 않고, 올리기는 새로 만든 솔루션에만 쓴다(이미 등록된 솔루션은 건드리지 않는다). 잘못된 모양·모르는 코드는 `bts.clean_suggestions` 가 조용히 버린다(분석·초안이 실패하지 않는다). 프롬프트 자리표시 `business_type_guide`·`business_type_codes` 는 `prompt_constants` 에 있다.
