# 시스템 업데이트 규칙 (solbox/docs/rules/시스템-업데이트.md)

다루는 것: 관리 › 시스템의 업데이트·다시 시작·화면 파일 스냅숏. 읽을 때: `update.py`·관리 › 시스템·시작 과정을 고칠 때.

솔박스 `CLAUDE.md` 에서 옮긴 영역별 규칙이다 (2026-11-25). 묶음(베타) 순서와 글은 그대로 두었다. 뒤 묶음이 앞 묶음의 규칙을 바꾼 경우가 많으니 **아래쪽(뒤 묶음)이 정본**이다. 글 속의 "위/아래 베타 X" 는 다른 영역 파일에 있을 수 있다: 어느 묶음이 어느 파일에 있는지는 `docs/rules/README.md`.

## 베타 X 묶음이 바꾼 규칙
- **시스템 업데이트(사용자 요청 2026-11-23)**: 관리 › 시스템의 카드에서 GitHub `main` 을 확인(`POST /admin/system/update/check`, 읽기만)하고 적용(`POST /admin/system/update/apply`, 관리자 전용·폼 표 `Once`·`data-confirm`)한다. 코드는 `app/update.py` 한 곳, 화면은 `admin/_update_card.html`·`admin/update_progress.html`(+`static/update.js`), 라우터는 `routers/admin.py`, 로그인 없는 `GET /healthz`(`routers/health.py`: 버전과 **서버가 시작될 때의 커밋**)는 다시 시작을 기다리는 화면이 쓴다.
- **명령은 모두 `system.run_bounded_ex`(= `run_bounded` 와 같은 시간 제한·Windows taskkill, 표준 오류도 돌려주고 `env` 를 받는다)로 고정 인자 목록만 돌린다**: `git -C <저장소> -c core.quotepath=off rev-parse|status --porcelain --untracked-files=no|fetch origin main|rev-list --count|log|diff --name-only|pull --ff-only origin main|reset --hard <40자리 커밋>`, `<sys.executable> -m pip install -e <solbox 폴더>`(15분). 셸 글·사용자 입력은 명령에 넣지 않고 `GIT_TERMINAL_PROMPT=0`. 오류 글은 `runner.redact` 를 거쳐 300자까지. 새 명령을 더해도 이 규칙을 지킨다.
- 막는 조건(확인과 적용이 같은 `update.check` 를 쓴다; 적용은 시작할 때 다시 돌린다): git 폴더 아님·`main` 아님·추적 파일 직접 고침(최대 10개 표시)·GitHub 에 없는 로컬 커밋·AI 작업 대기/진행·서버를 `run_server.ps1` 로 시작하지 않음(`SOLBOX_SUPERVISED=1`, 스크립트가 python 을 띄우기 전에 설정). 적용 순서: 다시 확인 → `backup.run_backup`(실패하면 멈춤) → `git pull --ff-only` → pyproject.toml 이 바뀌었으면 pip → 기록 → 종료 예약. 실패하면 **`pull` 이 HEAD 를 옮긴 경우에만** `reset --hard <이전 커밋>` 하고 다시 시작하지 않는다. 한 번에 하나(`_APPLY_LOCK`, 백그라운드 스레드), 확인은 적용 중이면 거부.
- 저장: 마지막 확인 결과는 **메모리**(`update._LAST_CHECK`, 다시 시작하면 지워짐), 마지막 업데이트 기록은 `app_settings.system_update_last`(누가·언제·from→to·pip·ok·reset·error·`notice_pending`)와 `app` 로그. 결과 알림은 한 번만(`take_notice`: 성공은 시작 커밋이 새 커밋일 때만 보인다).
- **다시 시작**: `update.schedule_restart` 가 3초 뒤 `signal.raise_signal(SIGINT)` 로 uvicorn 의 얌전한 종료(요청 마무리 → `lifespan` 정리: 작업자·스케줄러·로그 닫기)를 부르고, 20초 안에 안 끝나면 `logging.shutdown()` 뒤 `os._exit(0)`. `run_server.ps1` 의 반복문이 10초 뒤 다시 띄운다. 시험은 `schedule_restart`/`request_shutdown`/`hard_exit`/`run_pip` 를 바꿔 끼우고 실제 종료·pip 은 부르지 않는다. 알려진 한계(모르는 것): Windows 에서 다른 스레드의 `raise_signal(SIGINT)` 가 uvicorn 을 실제로 멈추는지, 진행 중 AI 작업이 시작되는 틈(확인과 pull 사이)은 시험하지 못했다. **첫 실제 업데이트는 사람이 서버 PC 에서 해 보아야 한다** (확인 목록은 운영가이드 9-1). `GET /healthz` 는 비밀이 아닌 버전·커밋만 준다.
- 보안: 관리자 전용·고정 명령·기록이 있다. **GitHub main 에 올릴 수 있는 사람은 이 서버에서 코드를 실행하게 할 수 있다** (GitHub 계정 보호). 시험 `tests/test_beta_x.py`. 문서: 운영가이드 9번, `docs/화면구성도.md`, `help.html`(관리자).

## 베타 Z 묶음이 바꾼 규칙
- **사용자 요청 2026-11-24: "앱도 깨지지 않게 보완".** 로컬 PC 에서 서버를 켠 채로 `git pull` 만 하자 홈·올리기 화면이 500 이었다 (옛 프로그램이 `max_paste` 를 넘기지 않는데 새 `intake/_dropzone.html` 이 `"{:,}".format(max_paste)` 를 불러 `TypeError: unsupported format string passed to Undefined.__format__`).
- **화면 파일은 시작 때 한 번 읽어 둔다**: `main.snapshot_loader(templates_dir)` 가 `templates` 아래 모든 `.html`(·`.txt`·`.xml`·`.md`·`.j2`)을 읽어 `DictLoader` 로 만들고 `auto_reload = False`. 실행 중에 폴더가 바뀌어도 다시 시작할 때까지 시작 때의 프로그램과 화면이 짝을 이룬다. **템플릿을 고친 뒤에는 서버를 다시 시작해야 보인다** (개발 중에도). 시험의 `TestClient` 는 앱을 새로 만들 때마다 다시 읽는다.
- **관리자 알림**: `update.code_changed_on_disk()` 가 `.git` 파일만 읽어(git 을 실행하지 않음, 작업 트리·packed-refs·분리된 HEAD 지원, 30초 캐시, 어떤 오류도 None) 폴더의 HEAD 가 시작 때의 커밋(`update._BOOT`)과 다르면 `base.html` 이 관리자에게만 "서버 폴더의 코드가 바뀌었지만 서버는 아직 옛 코드(…)로 돌고 있어요…" 를 보인다. 시험 `tests/test_beta_z.py`.

## 베타 서버 (2026-11-27)
- 한 PC 에 운영·베타 솔박스를 함께 띄울 때(운영가이드 14장, 시험 `tests/test_beta_instance.py`): 베타는 **코드 폴더·가상환경·data_dir·포트·`secret_key`** 를 따로 두고, `config.toml` 에 `session_cookie`(로그인 쿠키 이름, 기본 "session": 브라우저 쿠키는 포트를 가리지 않는다)·`instance_label`(로고 옆 표지·창 제목·`body[data-instance]` 맨 위 띠, 12자까지, 비면 표시 없음)·`scheduler_enabled = false` 를 적는다. 자동 시작은 `install_autostart.ps1 -TaskName SolutionBoxBeta` (기본 이름 그대로 등록하면 운영 작업을 덮어쓴다). 베타의 "시스템 업데이트"는 베타 폴더만 바꾼다.
- 시험자 안내: `docs/베타테스트-안내.md` (화면·이름이 바뀌면 "이번에 바뀐 것"·"해 볼 일"도 고친다).

## HTTPS 인증서: 자체 발급자 + 서버 인증서 (2026-11-27, 휴대폰 접속 준비)
- 시험 `tests/test_certs.py`. `certs.make_self_signed` 는 같은 폴더의 자체 발급자 `ca.crt`·`ca.key`("SolBox Local CA", 10년, CA)를 만들거나 다시 쓰고, 그 발급자로 서버 인증서 `server.crt`(825일 이하·serverAuth·발급자까지 이어 붙인 PEM)를 서명한다. 아이폰은 825일을 넘거나 서버 용도가 없는 인증서를 믿지 않고 신뢰 스위치는 발급자에만 있다. `--overwrite` 는 발급자를 그대로 써서 기기 재설치가 필요 없고, `--new-ca` 만 발급자를 새로 만든다. 새 발급자 파일은 서버 쌍을 다 쓴 뒤에 저장한다(중간 실패 때 아무것도 남지 않게).
- `GET /ca.crt`(로그인 없이): `ssl_certfile` 옆의 `ca.crt` 를 PEM 인증서일 때만 내려준다(키는 절대 아님). 휴대폰·PC 설치 안내는 운영가이드 4-1·4-2.
- 점검(`system._check_cert`)은 서버 인증서 만료 60일 전부터 문제로 알린다.
