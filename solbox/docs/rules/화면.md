# 화면 규칙 (solbox/docs/rules/화면.md)

다루는 것: 화면 공통(조사·좁은 화면·충돌 화면·유래 걸러 보기 등). 읽을 때: 템플릿·`app.js`·`app.css` 를 고칠 때 (기본 틀은 CLAUDE.md "화면 틀").

솔박스 `CLAUDE.md` 에서 옮긴 영역별 규칙이다 (2026-11-25). 묶음(베타) 순서와 글은 그대로 두었다. 뒤 묶음이 앞 묶음의 규칙을 바꾼 경우가 많으니 **아래쪽(뒤 묶음)이 정본**이다. 글 속의 "위/아래 베타 X" 는 다른 영역 파일에 있을 수 있다: 어느 묶음이 어느 파일에 있는지는 `docs/rules/README.md`.

## 베타 B 묶음이 더한 규칙
- 음성만 있어 읽을 파일이 없는 묶음은 `intake.is_archived`(상태 코드는 `uploaded` 그대로, 화면만 "보관됨"). 유래 걸러 보기는 `routers/_common.origin_filter`, 같은 이름 경고는 `_common.duplicate_warning`(폼의 `confirm_dup`), 파일 내용 해시는 `intake_files.sha256`·`solution_files.sha256`(옛 파일은 비교할 때 채움), 지우기 영향은 `ontology.DELETE_IMPACT` → `impact.py`, 문장 속 조사 고르기는 `korean.josa`, 점검 항목의 뜻·할 일은 `system.CHECK_INFO` (웹과 `cli check` 가 같은 목록), 코드 값의 한 문장 뜻은 `CodeList.descriptions`(`ontology.code_help`).

## 베타 C 묶음이 바꾼 규칙
- 문장 속 조사는 `이(가)` 같은 겹쓰기를 쓰지 않고 `korean.josa` 로 고른다 (`tests/test_beta_c.py` 가 앱 전체를 훑는다). 화면 구성 문서: `docs/화면구성도.md` (화면을 바꾸면 함께 고친다).

## 베타 D 묶음이 바꾼 규칙
- 단계 설명은 접힌 `<details class="stage-legend">`. 목록 도구줄은 좁은 화면(≤600px)에서 유래 탭과 정렬을 "걸러 보기·정렬" 펼침으로 접는다(두 벌을 그리고 CSS 가 한 벌만 보임, 기본이 아닌 것이 걸려 있으면 개수 표시). 목록 첫 칸(`title_cell`)은 두 줄(보조 글 한 줄 줄임표 + 태그 둘까지와 "+N"). 옆으로 미는 줄(단계 막대·제안 단계·구분 탭·표 감싸개)은 `app.js` 의 `initScrollers` 가 현재 항목을 보이게 하고 끝을 흐리게 한다. 제목 줄의 그 자리 삭제 확인은 제목 줄 밑 따로 선 줄에 놓는다.
- 충돌(409) 화면은 `guards.check_rev(..., values=쓴 값)` 의 `Conflict.diff`(온톨로지 속성 이름표 + 저장된 값 발췌)를 보인다. 연결 번호·후속 조치/니즈 줄·다중 선택은 비교하지 않는다. 같은 이름 경고는 `normalize_name(이름, company=True)`(고객·파트너: ㈜·(주)·주식회사 무시)로 견주고, 공백·대소문자만 다르면 "같은 이름", 그 밖이면 "비슷한 이름"이다. 사이드 메뉴 그림은 `ontology.NAV_ICONS`(새 메뉴 항목은 그림도 더한다).

## 베타 E 묶음이 바꾼 규칙
- 같은 이름 경고는 `duplicate_warning()["company"]`(고객·파트너)로 회사 접미 안내를 정한다. 올리기 확인 화면의 저장 막대는 쪽 맨 끝(폼 밖, `form="plan-form"`)이다.

## 베타 AE 묶음이 바꾼 규칙
- `_macros.html` 의 `detail_head` 는 안쪽 `call` 이 `caller` 를 가려서 바깥 `caller()` 를 먼저 받아 둔다 (제목 줄에 동작을 더하는 `{% call detail_head(...) %}`).

## UX 개선 묶음 (2026-11-26)
- 계획 `docs/superpowers/plans/2026-11-26-ux-refresh.md`, 시험 `tests/test_ux_refresh.py`.
- 사이드 메뉴의 관리 묶음은 `<details>`(관리 화면에서만 펼침). "AI 제안함"(`/ai/inbox`, `app/ai_inbox.py`)은 오늘 묶음: 영업기회 분석과 AI 동료의 반영 대기 제안, 반영·무시는 각 출처 POST 에 `back=/ai/inbox`(이 값만 받는다, `routers/ai_inbox.back_target`).
- 목록 도구줄은 구분 탭 + 검색 + "걸러 보기·정렬" 펼침 하나 (모든 폭). 유래·정렬·목록별 걸러 보기(`list_tools(extra=…, extra_on=켜진 수)`)는 펼침 안. 하나라도 켜져 있으면 펼친 채.
- 홈 맨 위 "내 할 일" 띠(`home.my_work`, 여섯 칸: 기한 지난 후속 조치·내 열린 과제·멈춘 내 영업기회·반영 대기 AI 제안·방향 밖 기록·올리기 정리 확인). 홈의 올리기 칸(드롭존)은 없앴다 (올리기는 `/intake/new`). 발굴 흐름은 맨 아래 카드.
- 위쪽 줄 "내 AI 작업"(`main._my_jobs`: 내가 시작한 24시간 안의 6개, 진행 중이 먼저, 링크에 `?from=tray`), 상세 화면 오른쪽의 정렬 카드·AI 동료는 `.ai-dock` 하나에.
- 연결 카드가 넷 이상인 상세 화면은 위에 구역 바로 가기(`.jumpnav`, 카드 `id="rel-<관계>-<유형>"`), 빈 카드는 한 줄(`empty-rel`). 영업기회 요약 띠는 네 칸이 모두 비면 한 줄 안내.
- 휴대폰(759px 이하) 아래 고정 탭(`.tabbar`: 홈·활동·＋활동 기록 쓰기·영업기회·과제), 단계 막대는 가로로 밀어 본다.
- 목록 만들기 버튼은 "+ 새 <대상>"(`list_head` 기본값). Ctrl+K(⌘K) 는 전체 검색칸, 검색 결과 위 "바로 만들기"(`search.quick_actions`).

## UX 1순위 묶음: 휴대폰 기록 흐름 (2026-11-27)
- 시험 `tests/test_ux_mobile_record.py`.
- 휴대폰(759px 이하) 머리는 `.top` 한 줄: `.m-mark`(홈) + 검색 + AI 상태 + `details.m-menu`("+ 올리기"·전체 메뉴·내 정보·도움말·로그아웃). 메뉴 목록은 `base.html` 의 `navblock` 한 곳에서 그려 사이드 메뉴와 펼침에 두 번 넣는다 (CSS 가 폭에 맞는 한 벌만 보인다. `<aside>` 안에는 한 벌). 비밀번호를 먼저 바꿔야 하는 계정은 `<aside data-locked>` 라 사이드 줄(로고·로그아웃)을 그대로 보이고 펼침·아래 탭이 없다. `app.js` 는 바깥 누르기·Esc 로 펼침을 닫는다 (없어도 동작).
- 아래 고정 탭 높이는 토큰 `--tab-h`(넓은 화면 0, 탭이 있으면 `:root:has(.tabbar)` 에서 64px + 안전 영역). 아래에 붙는(sticky `bottom`) 저장 막대(`.form-page > .savebar`·`.card.stack > .savebar`·`.plan-savebar`)는 모두 `bottom` 에 `--tab-h` 를 더한다. 새 sticky 아래 막대도 같다.
- 정리본(마크다운)의 한 줄 요약은 `ui.summary_line`(제목 줄·`## 참석자` 구역을 건너뛴 첫 본문 줄, 규칙은 `ui.plain_lines` 한 곳; 템플릿 필터 `summary_line`). 활동 기록 목록·전체 검색·업무 보고 AI 자료가 쓴다. `first_line` 은 제목 줄도 글로 읽으므로 정리본에는 쓰지 않는다.
- 활동 기록 쓰기(`activities/new.html`): 노란 안내는 AI 상태(`ai_note`) 하나뿐, 다른 길(올리기·칸 직접 채우기)은 카드 밑 `.memo-alt` 한 줄, 저장 막대는 주 버튼·보조 버튼·"취소"(`.ghost`) 셋이라 휴대폰에서도 한 줄이다.

## UX 2순위 묶음: 주 동작 하나와 정보 우선순위 (2026-11-27)
- 시험 `tests/test_ux_priority2.py` (홈 주 버튼·올리기 카드는 `tests/test_home.py`, 목록 머리 버튼은 `tests/test_intake_pages.py`).
- 홈 제목 줄: "+ 올리기"(보조, `.to-intake`) + "활동 기록 쓰기"(주). 올리기 카드는 확인 대기·정리 중 묶음이 있을 때만. "내 할 일" 띠의 0 칸은 `.is-zero`(점선·흐린 숫자, 칸은 그대로). 휴대폰도 제목 줄 올리기 버튼을 감추지 않는다(사이드 줄 올리기가 "메뉴" 펼침 안으로 들어갔으므로).
- 활동 기록·솔루션 목록: 주 버튼 "+ 새 …", 보조 "올리기" (솔루션 목록은 사용자 요청으로 같은 날 맞췄다). 올리기가 주 버튼인 목록은 올리기 묶음 목록뿐. "연결" 칸의 고객은 이름(`routers/activities.customer_names`, 쪽 단위 질의 하나), 나머지는 `LIST_LINKS` 건수.
- 영업기회 목록의 기본 정렬(`LIST_SORTS` 첫 항목)일 때만 진행 중(`OPPORTUNITY_OPEN_STAGES`)이 위(안정 정렬이라 그 안은 최근 수정순). 표 위 `.list-sum` 한 줄은 걸러 보기·검색을 적용한 목록의 진행 중 건수·금액 합계(전체·진행 중 탭에서만).
- 상세 옆 칸 순서는 (변경 이력) → 연결된 것 → AI 칸(`.ai-dock`) → 기록 정보 (영업기회·솔루션·파트너). 과제 상세는 AI 동료가 중심이라 그대로.
- 활동 기록 상세(UX 다듬기): 제목 밑 한 줄과 겹치던 "기본 정보" 카드는 없애고 참석 담당자가 있을 때만 그 카드(`#h-attendees`). 제목 줄 다음 동작은 고객이 이어졌고 아직 영업기회로 묶이지 않은 첫 니즈의 "영업기회 만들기"(없으면 주 버튼 없음). 메뉴 묶음("오늘 › 활동 기록" 경로)은 2026-11-27 재편 그대로 둔다.

## 메뉴 개편: 위쪽 줄 탭 (2026-11-27)
- 시험 `tests/test_nav_top.py`.
- `ontology.TOP_NAV_GROUP`("today") 묶음은 넓은 화면(1100px 이상)에서 위쪽 줄 탭(`.top-tabs`), 순서는 홈·활동 기록·업무 보고·AI 제안함·올리기 묶음. 그 옆 `.top-upload`("+ 올리기", 옅은 남색: 꽉 찬 주 버튼은 화면 제목 줄 하나), 오른쪽 끝 `details.top-admin`(관리자만, 관리 화면이면 `summary.current`)·`.top-help`. 사이드는 같은 메뉴를 다 그리고(`navg[data-group]`) 넓은 화면에서만 today·admin 묶음·사이드 올리기·도움말을 CSS 로 숨긴다 (태블릿 가로 줄·휴대폰 메뉴 펼침은 사이드 쪽을 그대로 쓴다).
- 이 묶음 화면은 경로에 묶음 이름을 쓰지 않는다: `nav_group_label` 이 빈 글, `ui.crumbs` 는 묶음 마디를 빼고, `breadcrumb` 매크로는 빈 이름 마디를 건너뛴다. 홈 제목 줄에는 올리기 버튼을 두지 않는다.
- 소스 묶음 순서: 고객니즈 · 솔루션 · 파트너 · 리서치.
- 이름 (2026-11-27 사용자 결정): 영업 › "제안서"(메뉴·경로, `TERMS["proposal_nav"]`; 한 건은 그대로 "제안 건"), 제안 건의 마지막 단계·PPT 구역·버튼은 "PPT"(`TERMS["proposal_deck"]`, "PPT 만들기"·"PPT 파일"). 사업기획 › "운영 사업"(옛 "기존 BM")·"신규 사업"(옛 "신규 BM"), 대상 유형 이름은 그대로 "BM". "기존 사업"은 프로젝트의 옛 이름이라 쓰지 않는다.
