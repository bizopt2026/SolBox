# 화면 규칙 (solbox/docs/rules/화면.md)

다루는 것: 화면 공통(조사·좁은 화면·충돌 화면·유래 걸러 보기 등). 읽을 때: 템플릿·`app.js`·`app.css` 를 고칠 때 (기본 틀은 CLAUDE.md "화면 틀").

솔박스 `CLAUDE.md` 에서 옮긴 영역별 규칙이다 (2026-11-25). 묶음(베타) 순서와 글은 그대로 두었다. 뒤 묶음이 앞 묶음의 규칙을 바꾼 경우가 많으니 **아래쪽(뒤 묶음)이 정본**이다. 글 속의 "위/아래 베타 X" 는 다른 영역 파일에 있을 수 있다: 어느 묶음이 어느 파일에 있는지는 `docs/rules/README.md`.

## 베타 B 묶음이 더한 규칙
- 음성만 있어 읽을 파일이 없는 묶음은 `intake.is_archived`(상태 코드는 `uploaded` 그대로, 화면만 "보관됨"). 유래 걸러 보기는 `routers/_common.origin_filter`, 같은 이름 경고는 `_common.duplicate_warning`(폼의 `confirm_dup`), 파일 내용 해시는 `intake_files.sha256`·`solution_files.sha256`(옛 파일은 비교할 때 채움), 지우기 영향은 `ontology.DELETE_IMPACT` → `impact.py`, 문장 속 조사 고르기는 `korean.josa`, 점검 항목의 뜻·할 일은 `system.CHECK_INFO` (웹과 `cli check` 가 같은 목록), 코드 값의 한 문장 뜻은 `CodeList.descriptions`(`ontology.code_help`).

## 베타 C 묶음이 바꾼 규칙
- 문장 속 조사는 `이(가)` 같은 겹쓰기를 쓰지 않고 `korean.josa` 로 고른다 (`tests/test_beta_c.py` 가 앱 전체를 훑는다). 화면 구성 문서: `docs/화면구성도.md` (화면을 바꾸면 함께 고친다).

## 베타 D 묶음이 바꾼 규칙
- 단계 설명은 접힌 `<details class="stage-legend">`. 목록 도구줄은 좁은 화면(≤600px)에서 유래 탭과 정렬을 "걸러 보기·정렬" 펼침으로 접는다(두 벌을 그리고 CSS 가 한 벌만 보임, 기본이 아닌 것이 걸려 있으면 개수 표시). 목록 첫 칸(`title_cell`)은 두 줄(보조 글 한 줄 줄임표 + 태그 둘까지와 "+N"). 옆으로 미는 줄(단계 막대·제안 단계·구분 탭·표 감싸개)은 `app.js` 의 `initScrollers` 가 현재 항목을 보이게 하고 끝을 흐리게 한다. 제목 줄의 그 자리 삭제 확인은 제목 줄 밑 따로 선 줄에 놓는다.
- 충돌(409) 화면은 `guards.check_rev(..., values=쓴 값)` 의 `Conflict.diff`(온톨로지 속성 이름표 + 저장된 값 발췌)를 보인다. 연결 번호·후속 조치/니즈 줄·다중 선택은 비교하지 않는다. 같은 이름 경고는 `normalize_name(이름, company=True)`(고객·파트너: ㈜·(주)·주식회사 무시)로 견주고, 공백·대소문자만 다르면 "같은 이름", 그 밖이면 "비슷한 이름"이다. 사이드 메뉴 그림은 `ontology.NAV_ICONS`(새 메뉴 항목은 그림도 더한다).

## 베타 E 묶음이 바꾼 규칙
- 같은 이름 경고는 `duplicate_warning()["company"]`(고객·파트너)로 회사 접미 안내를 정한다. 올리기 확인 화면의 저장 막대는 쪽 맨 끝(폼 밖, `form="plan-form"`)이다.

## 베타 AE 묶음이 바꾼 규칙
- `_macros.html` 의 `detail_head` 는 안쪽 `call` 이 `caller` 를 가려서 바깥 `caller()` 를 먼저 받아 둔다 (제목 줄에 동작을 더하는 `{% call detail_head(...) %}`).

## UX 개선 묶음 (2026-11-26)
- 계획 `docs/superpowers/plans/2026-11-26-ux-refresh.md`, 시험 `tests/test_ux_refresh.py`.
- 사이드 메뉴의 관리 묶음은 `<details>`(관리 화면에서만 펼침). "AI 제안함"(`/ai/inbox`, `app/ai_inbox.py`)은 오늘 묶음: 영업기회 분석과 AI 동료의 반영 대기 제안, 반영·무시는 각 출처 POST 에 `back=/ai/inbox`(이 값만 받는다, `routers/ai_inbox.back_target`).
- 목록 도구줄은 구분 탭 + 검색 + "걸러 보기·정렬" 펼침 하나 (모든 폭). 유래·정렬·목록별 걸러 보기(`list_tools(extra=…, extra_on=켜진 수)`)는 펼침 안. 하나라도 켜져 있으면 펼친 채.
- 홈 맨 위 "내 할 일" 띠(`home.my_work`, 여섯 칸: 기한 지난 후속 조치·내 열린 과제·멈춘 내 영업기회·반영 대기 AI 제안·방향 밖 기록·올리기 정리 확인). 홈의 올리기 칸(드롭존)은 없앴다 (올리기는 `/intake/new`). 발굴 흐름은 맨 아래 카드.
- 위쪽 줄 "내 AI 작업"(`main._my_jobs`: 내가 시작한 24시간 안의 6개, 진행 중이 먼저, 링크에 `?from=tray`), 상세 화면 오른쪽의 정렬 카드·AI 동료는 `.ai-dock` 하나에.
- 연결 카드가 넷 이상인 상세 화면은 위에 구역 바로 가기(`.jumpnav`, 카드 `id="rel-<관계>-<유형>"`), 빈 카드는 한 줄(`empty-rel`). 영업기회 요약 띠는 네 칸이 모두 비면 한 줄 안내.
- 휴대폰(759px 이하) 아래 고정 탭(`.tabbar`: 홈·활동·＋활동 기록 쓰기·영업기회·과제), 단계 막대는 가로로 밀어 본다.
- 목록 만들기 버튼은 "+ 새 <대상>"(`list_head` 기본값). Ctrl+K(⌘K) 는 전체 검색칸, 검색 결과 위 "바로 만들기"(`search.quick_actions`).
