# 솔박스 화면 구성도

- 기준: 2026-11-20, 화면 재설계와 베타 수정 반영
- 정의의 원본은 코드다. 메뉴는 `app/ontology.py`(`NAV_GROUPS`·`NAV_ITEMS`), 화면 틀은 `app/templates/_macros.html`, 주소는 `app/routers/`. 이 문서는 그것을 사람이 읽기 좋게 옮긴 것이므로, 화면을 바꾸면 함께 고친다.

## 1. 전체 틀

모든 화면(로그인 제외)은 같은 틀이다.

```
┌──────────────┬──────────────────────────────────────────────┐
│ 솔박스        │ [전체 검색 ( / )]                 AI 상태 · 대기 n │  ← 위쪽 줄
│ [+ 올리기]    ├──────────────────────────────────────────────┤
│ 오늘          │ 경로: 묶음 › 메뉴 › 항목                         │
│  홈           │ 제목                     [삭제] [수정] [다음 동작] │  ← 제목 줄
│  올리기 묶음 ●│ (결과 알림)                                     │
│  활동 기록    │                                              │
│ 발굴          │ 본문                                          │
│  솔루션       │                                              │
│  파트너       │                                              │
│  리서치       │                                              │
│ 영업          │                                              │
│  고객         │                                              │
│  영업기회     │                                              │
│  제안         │                                              │
│  프로젝트     │                                              │
│  BM          │                                              │
│ 관리 (관리자) │                                              │
│  사용자       │                                              │
│  AI 작업      │                                              │
│  리서치 설정  │                                              │
│  시스템       │                                              │
│ 도움말        │                                              │
│ 이름 [로그아웃]│                                              │
└──────────────┴──────────────────────────────────────────────┘
```

- 좁은 화면(휴대폰)에서는 사이드 메뉴가 접히고, 제목 줄의 주 버튼이 한 줄을 다 쓴다.
- "올리기 묶음" 옆 숫자는 내가 올린 묶음 중 확인을 기다리는 것의 수다.
- "관리" 묶음은 관리자에게만 보인다.
- 이름을 누르면 "내 정보"(`/account`)로 간다.

## 2. 화면의 세 가지 틀

| 틀 | 구성 | 쓰는 화면 |
|---|---|---|
| 목록 | 제목 줄(설명 한 줄, "+ 등록") → 도구 줄(구분 탭·검색·걸러 보기·정렬) → 표(제목 칸, 배지, "연결" 건수) → 쪽 넘김 | 솔루션, 파트너, 고객, 영업기회, 제안, 프로젝트, BM, 활동 기록, 올리기 묶음, 후속 조치 |
| 상세 | 제목 줄(삭제 → 수정 → 다음 동작 하나) → 단계 막대(흐름이 있는 대상) → 두 칸: 왼쪽 내용 카드, 오른쪽 "연결된 것"·기록 정보 | 솔루션, 파트너, 고객, 영업기회, 프로젝트, BM, 활동 기록 |
| 폼 | 가운데 한 칸 폼 → 맨 밑 저장 막대. 오류는 위쪽 알림과 해당 칸 옆 | 모든 등록·수정 |

상세의 두 칸은 본문 폭이 960px 이상일 때만 나란하고, 좁으면 아래로 쌓인다.

## 3. 화면 목록

### 오늘

| 화면 | 주소 | 하는 일 |
|---|---|---|
| 홈 | `/` | 대시보드. 확인을 기다리는 올리기 묶음, 후속 조치(14일 이내 / 내 할 일), 진행 중인 영업기회·제안, 최근 활동. 처음 설치했을 때만 "처음 시작하기" 안내 |
| 올리기 | `/intake/new` | 파일(문서·사진·음성)과 메모를 한 번에 올린다 |
| 올리기 묶음 목록 | `/intake` | 내가 올린 묶음(관리자는 전체). 상태 탭 |
| 올리기 묶음 상세 | `/intake/{번호}` | 진행 띠(올림 → 정리 중 → 확인 대기 → 저장 완료). 확인 대기일 때는 정리안 확인 화면 |
| 활동 기록 목록 | `/activities` | 종류 탭, 유래 걸러 보기, 정렬 |
| 활동 기록 쓰기 | `/activities/new` | 메모를 적고 "AI 로 정리" 또는 "원문만 저장". `?manual=1` 은 직접 입력 폼 |
| AI 정리 초안 | `/activities/draft/{작업}` | AI 가 정리한 초안을 고쳐 저장 |
| 활동 기록 상세·수정 | `/activities/{번호}`, `…/edit` | 정리본, 원문, 후속 조치, 고객 니즈, 연결 |
| 후속 조치 | `/follow-ups` | 모든 후속 조치. 완료 표시, "내 할 일로" |

### 발굴

| 화면 | 주소 | 하는 일 |
|---|---|---|
| 솔루션 목록 | `/solutions` | 발굴 단계 탭(접수·태핑·수요조사·박스 등록·보류), 유래 걸러 보기 |
| 솔루션 상세 | `/solutions/{번호}` | 단계 막대와 단계 변경, 소개·설명, 자료 올리기, AI 초안, 연결된 것 |
| 솔루션 등록·수정 | `/solutions/new`, `…/edit` | |
| 파트너 목록·상세·등록·수정 | `/partners…` | 같은 회사인 고객 연결 |
| 리서치 | `/research` | 주간 조사 실행 목록, "지금 조사" |

## 4. 주요 흐름

### 4.1 올리기 (가장 자주 쓰는 길)

```
[+ 올리기] ──▶ 파일·메모 올림 ──▶ 정리 중 (AI, 음성은 받아쓰기 먼저)
                                      │
                                      ▼
                              정리안 확인 (확인 대기)
                              · 맨 위 한 줄 요약
                              · 항목 카드: 새 솔루션 / 솔루션에 자료 추가 / 활동 기록
                                / 새 고객 / 새 파트너 / 연락처 추가 / 둘 곳 없음
                              · 카드마다 "고치기", "이 항목 제외"
                              · 이미 저장된 같은 파일·같은 할 일 안내
                                      │ [저장]
                                      ▼
                              저장 완료 ──▶ 만들어진 기록으로 이동
```

- 한 묶음은 한 번만 저장된다. 실패하면 "다시 정리", 필요 없으면 "버리기".
- 음성만 있고 받아쓰기가 꺼져 있으면 "보관됨"으로 남는다.

### 4.2 영업 흐름

```
활동 기록 ──▶ 고객 니즈 ──▶ 영업기회 ──▶ 프로젝트
 (미팅 메모)   (기록 안의 줄)   (같은 고객의      (수주한 영업기회를
                              니즈를 묶음)      전환하거나 기존 것에 이음)
                                 │
                                 ├──▶ 제안 건 (고객 필수, 영업기회·프로젝트 선택)
                                 └──▶ BM (선택: 어떤 사업 모델로 진행하는지)
```

- 고객 상세 → 니즈 옆 "영업기회로" → 영업기회 등록 폼에 미리 채워진다.
- 단계 순서는 강제하지 않는다. 프로젝트로 전환은 수주일 때 한 번만.

### 4.3 솔루션 발굴 흐름

```
접수 ──▶ 태핑 ──▶ 수요조사 ──▶ 박스 등록          (어느 단계에서든 보류)
 ▲
 ├─ 직접 등록
 ├─ 올리기 정리안의 "새 솔루션"
 └─ 리서치 보고서의 "후보로 등록"
```

- 보류가 아닌 솔루션은 모두 제안 후보가 된다.

## 5. 제안 작업 화면 (5단계)

```
제목 줄:  고객 · 제안 이름                         [다음 동작 하나]
단계 막대: ① 대상 ─ ② 방향 ─ ③ 구체화 ─ ④ 구성안 ─ ⑤ 제안서
┌───────────────────────────────────┬──────────────────────┐
│ ① 대상: 고객·프로젝트·영업기회·요청 메모 │ 선택한 방향             │
│ ② 방향: AI 가 낸 방향 2~3개 중 하나 선택 │ 출처                  │
│ ③ 구체화: AI 와 대화 (예시 질문 칩,     │ 대상 요약              │
│    답변은 대화 안에서 바로 이어짐)       │ 연결된 것              │
│ ④ 구성안: 장별 카드 (고치기·순서·삭제,   │                      │
│    확인 항목 확인 표시)               │                      │
│ ⑤ 제안서: 고객용 PPT / 내부 검토용 PPT  │                      │
└───────────────────────────────────┴──────────────────────┘
```

- 지금 단계 구역만 펼쳐지고, 지난 단계는 접힌다.
- 제목 줄의 다음 동작은 단계에 따라 바뀐다: 방향 만들기 → 방향 선택 → 구성안 만들기 → 제안서 만들기 → 고객용 PPT 내려받기.
- 고객용 PPT 에는 발표자 노트와 확인 항목이 없다. 내부 검토용에는 출처 이름과 확인 항목이 노트에 들어간다.
- 마무리 장의 연락처는 "내 정보"의 연락처로 채워진다.

## 6. 화면 사이를 잇는 공통 장치

| 장치 | 설명 |
|---|---|
| 연결된 것 | 모든 상세 화면 오른쪽. 온톨로지의 관계 정의를 따라가 연결된 기록을 묶음별로 보여 주고, 묶음마다 "+ …" 동작과 "모두 보기"가 있다 |
| 미리 채우기 | 상세 화면의 "+ 활동 기록", "+ 제안", "+ 영업기회" 등은 그 기록이 미리 골라진 등록 폼을 연다 |
| 결과 알림 | 저장·삭제·단계 변경 뒤 다음 화면 맨 위에 한 줄 |
| 유래 | 솔루션·활동 기록·고객·파트너에 "직접 입력 / 올리기 / 리서치" 표시와 걸러 보기 |
| 덮어쓰기 방지 | 수정 화면을 연 뒤 다른 곳에서 바뀌었으면 저장을 막고 알려 준다 |
| 같은 이름 경고 | 등록할 때 같은 이름이 있으면 "기존 것 열기 / 그래도 새로 등록" |
| AI 상태 | 위쪽 줄 오른쪽. 사용 가능 여부와 대기 중인 작업 수 |
