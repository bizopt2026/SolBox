# 솔박스 화면 구성도

- 기준: 2026-11-20, 화면 재설계와 베타 수정 반영
- 정의의 원본은 코드다. 메뉴는 `app/ontology.py`(`NAV_GROUPS`·`NAV_ITEMS`), 화면 틀은 `app/templates/_macros.html`, 주소는 `app/routers/`. 이 문서는 그것을 사람이 읽기 좋게 옮긴 것이므로, 화면을 바꾸면 함께 고친다.

## 1. 전체 틀

모든 화면(로그인 제외)은 같은 틀이다.

```
┌──────────────┬──────────────────────────────────────────────┐
│ 솔박스        │ [전체 검색 ( / )]                 AI 상태     │  ← 위쪽 줄
│ [+ 올리기]    ├──────────────────────────────────────────────┤
│ 오늘          │ (결과 알림)                                     │
│  홈           │ 경로: 묶음 › 메뉴 › 항목                         │
│  올리기 묶음 ●│ 제목                     [삭제] [수정] [다음 동작] │  ← 제목 줄
│  활동 기록    │                                              │
│ 발굴          │ 본문                                          │
│  솔루션       │                                              │
│  파트너       │                                              │
│  리서치       │                                              │
│ 영업          │                                              │
│  고객         │                                              │
│  영업기회     │                                              │
│  제안         │                                              │
│  프로젝트     │                                              │
│  BM          │                                              │
│ 관리 (관리자) │                                              │
│  사용자       │                                              │
│  AI 작업      │                                              │
│  리서치 설정  │                                              │
│  시스템       │                                              │
│ 도움말        │                                              │
│ 내 이름 [로그아웃]│                                            │
└──────────────┴──────────────────────────────────────────────┘
```

- 폭이 1100px 보다 좁으면(휴대폰 포함) 사이드 메뉴가 위쪽 줄로 바뀐다: 로고, "+ 올리기", 이름(글자 없이 동그라미)·로그아웃이 한 줄에 놓이고, 그 아래에 묶음 메뉴가 가로로 밀린다. 도움말은 메뉴 줄 끝으로 옮겨 간다. 상세·제안 화면의 제목 줄은 600px 보다 좁으면 주 버튼이 한 줄을 다 쓴다.
- "올리기 묶음" 옆 숫자는 내가 올린 묶음 중 확인을 기다리는 것의 수다 (0이면 안 보인다).
- AI 상태에 따라 AI 동작이 있는 모든 화면(활동 기록 쓰기, 올리기, 솔루션 소개 초안, 제안 방향·대화·구성안·시작 질문 칩·다시 시도·다시 만들기, 리서치 "지금 조사"·"다시 조사")이 그 자리에서 한 줄로 알린다. **"AI 꺼짐"(처리기 꺼짐)이면 AI 버튼이 모두 비활성**이고 서버도 새 AI 작업을 받지 않는다(로그인·권한을 먼저 보고, 그다음 어떤 POST 든 같은 화면으로 돌려보내며 알림 `ai_off`. 끝나지 않는 대기 줄이 생기지 않는다). 쓴 글이 있는 동작은 글을 잃지 않는다: 활동 기록 "AI로 정리"는 메모·연결 칩을 채운 같은 폼을, 제안 대화 보내기·구성안 다시 만들기는 쓴 글을 채운 제안 화면(409)을, 올리기 "다시 정리"는 고친 메모를 저장하고 묶음 화면을 보여 준다(메모가 너무 길면 보통 경로와 같은 400 "메모가 너무 깁니다" 화면. 첨부 파일은 다시 골라야 한다). 한 화면에 AI 꺼짐 안내는 한 줄만 보인다(제안 화면 409 에는 알림·입력칸 오류를 더 얹지 않는다. 리서치 조사 화면은 아래 조각의 줄 하나, 리서치 설정은 "조사 실행" 카드의 줄 하나). 처리기가 꺼진 동안 조사 진행 조각은 5초마다 다시 부르지 않고 "AI 대기 n번째" 대신 "대기 중"으로 보인다. 버튼이 비활성인 화면(AI 작업·시스템·리서치 조사 화면·솔루션 초안 다시 시도·작업 상태)에는 화면마다 한 번 이유 줄이 있고 버튼이 `aria-describedby` 로 가리킨다. 올리기는 파일을 보관만 하고(정리 작업을 넣지 않는다, 알림 `intake_kept_ai_off`) 처리기가 켜진 뒤 올리기 묶음의 "정리 시작"을 누른다. 제안 건 만들기는 등록만 하고 방향 만들기는 시작하지 않는다(`created_ai_off`). **"AI 사용 불가"(지난 작업이 설치·로그인 문제로 실패)는 버튼을 막지 않는다**: 안내가 "다시 시도하면 연결을 다시 확인하고, 성공하면 사라진다, 계속 실패하면 관리 › 시스템 › AI 연결 확인"(관리자에게는 링크)을 알린다. PPT 만들기는 그대로. 휴대폰에서는 정상이 아닐 때 점 옆에 짧은 글이 보인다.
- 저장하지 못한 오류 화면(409 충돌, 503 "잠시 후 다시 시도")의 "뒤로 가기" 단추는 JS 가 있을 때만 보이고, JS 가 없으면 브라우저의 뒤로 가기를 쓰라는 안내 글과 "첨부한 파일은 다시 골라야 한다"가 보인다. 503 은 저장 중 쓰기 잠금을 제때 잡지 못한 만들기·고치기·지우기에서 같고, 그때는 아무것도 저장되지 않았다(제안 건 만들기는 제안 건과 방향 작업이, 제안 대화 메시지는 AI 작업과, 올리기 "다시 정리"의 고친 메모는 정리 작업과 한 트랜잭션이라 따로 남지 않는다). 예외는 솔루션 자료를 여러 개 올릴 때와 올리기 "다시 정리"의 파일 읽기 상태뿐이다. 자료는 파일마다 따로 저장하므로 저장된 파일이 하나도 없는 채로 막히면(이미 있는 자료·큰 파일로 건너뛴 파일은 저장이 아니다) 503, 앞에 저장된 파일이 있으면 503 대신 "저장하지 못한 파일" 안내와 함께 앞 파일은 저장돼 있다(화면 200). 올리기 "다시 정리"는 고친 메모와 정리 작업이 한 트랜잭션이라 503 이면 메모가 남지 않지만, 그 앞의 작업 폴더 준비가 올린 파일의 읽기 상태를 따로 저장하므로 읽기 상태는 갱신돼 있을 수 있다(사용자가 쓴 값이 아니고 다음 시도가 다시 계산한다). 구성안 쪽의 PPT 만들기 폼의 숨은 칸 `back=outline` 은 구성안 화면에만 있고, 구성안 다시 만들기 오류(409) 뒤 제안 상세에는 없다.
- 위쪽 줄 오른쪽의 AI 상태는 "AI 사용 가능 · 대기 n", "AI 작업 중 n · 대기 m", "마지막 AI 작업 실패 (…)", "AI 사용 불가", "AI 꺼짐" 중 하나다. 관리자에게는 누르면 "AI 작업" 화면으로 가는 링크다.
- 검색 칸에서 `/` 키로 바로 검색할 수 있다.
- "관리" 묶음은 관리자에게만 보이고, 그 화면 주소를 일반 사용자가 열면 "권한이 없습니다"(403) 화면이 나온다.
- 사이드 메뉴 맨 아래의 이름 칸을 누르면 "내 정보"(`/account`)로 간다.
- 후속 조치(`/follow-ups`)는 메뉴 항목이 따로 없고 "오늘" 묶음에 속해 "홈"이 눌린 것으로 보인다. 홈의 후속 조치 카드에서 들어간다.

## 2. 화면의 세 가지 틀

| 틀 | 구성 | 쓰는 화면 |
|---|---|---|
| 목록 | 제목 줄(설명 한 줄, "+ 등록", 올리기가 있는 목록은 "+ 등록"과 "올리기") → 도구 줄(구분 탭·검색·걸러 보기·정렬; 휴대폰은 유래·정렬이 "걸러 보기·정렬" 펼침 하나로 접힌다) → 표(제목 칸, 배지, "연결" 건수) → 쪽 넘김 | 솔루션, 파트너, 리서치, 고객, 영업기회, 제안, 프로젝트, BM, 활동 기록, 올리기 묶음. 후속 조치는 표 대신 할 일 줄 목록 |
| 상세 | 제목 줄(삭제 → 수정 → 다음 동작 하나) → 단계 막대(흐름이 있는 대상: 솔루션·영업기회; 밑에 접힌 "단계 설명") → 두 칸: 왼쪽 내용 카드, 오른쪽 "연결된 것"·기록 정보 | 솔루션, 파트너, 고객, 영업기회, 프로젝트, BM, 활동 기록 (제안 건과 올리기 묶음은 자기 틀이다) |
| 폼 | 가운데 한 칸 폼 → 맨 밑 저장 막대. 오류는 위쪽 알림과 해당 칸 옆 | 모든 등록·수정 |

상세의 두 칸은 본문 폭이 960px 이상일 때만 나란하고, 좁으면 아래로 쌓인다.

## 3. 화면 목록

### 오늘

| 화면 | 주소 | 하는 일 |
|---|---|---|
| 홈 | `/` | 제목 "오늘 할 일"(날짜·기한 지난 후속 조치 수)과 "활동 기록 쓰기"·"+ 올리기" 버튼. 발굴 단계별 건수 띠(누르면 그 단계의 솔루션 목록), 후속 조치 카드(기한 14일 이내 / 내 할 일 탭), 최근 활동 기록, 올리기 카드(파일 올리는 칸과 확인 대기·정리 중 묶음), 영업기회 단계 막대와 진행 중 건수, 진행 중인 제안 건, 최신 리서치(시사점·발굴 방향 제안). 처음 설치했을 때만 "처음 시작하기" 안내 |
| 올리기 | `/intake/new` | 파일(문서·사진·음성)과 메모를 한 번에 올린다 (한 번에 20개, 파일 하나 100MB까지). 파일 칸 아래 "글 붙여넣기"(제목 선택 60자까지 + 글 칸, 글자 수 `n / 200,000자`)로 메일·회의 메모·웹페이지 글을 파일 없이, 또는 파일과 함께 올릴 수 있다: 붙여넣은 글은 `.txt` 파일 하나로 올라가 파일 수에 센다. 파일도 글도 없으면 "파일을 고르거나 글을 붙여넣어 주세요." (홈의 올리기 카드는 접힌 "글 붙여넣기"에 글 칸만) |
| 명함 파일 가져오기 (베타 AA) | `/intake/cards` | 명함 앱에서 내보낸 파일(.xlsx·.csv·.vcf) 하나를 올린다 (크기 제한은 다른 올리기와 같다, 명함 2,000장까지, "등록되지 않은 회사는 먼저 고객/파트너" 선택). 로그인한 누구나. `/intake/new` 아래와 올리기 묶음 목록 위에 링크. **AI 를 쓰지 않고** 파서가 정리안을 만든 묶음(`Intake.source = cards`)이 생기고 상세 화면으로 간다 |
| 올리기 묶음 목록 | `/intake` | 내가 올린 묶음(관리자는 전체, "올린 사람" 칸이 보인다). 상태 탭: 올림·정리 중·확인 대기·저장 중·저장 완료·실패·버림 |
| 올리기 묶음 상세 | `/intake/{번호}` | 진행 띠(올림 → 정리 중 → 확인 대기 → 저장 완료). 확인 대기일 때는 정리안 확인 화면 |
| 명함 묶음 상세 (베타 AA) | `/intake/{번호}` | 진행 띠는 올림 → 확인 대기 → 저장 완료 ("정리 중" 없음, "정리 방법: 프로그램이 읽어 정리 (AI 미사용)"). **열 지정 단계**(이름·회사 열을 못 찾았을 때, 상태 "올림"): 파일의 첫 5줄 표 + 열 이름이 적힌 줄 + 칸마다 열 고르기(이름·회사 필수) + 새 회사 기본 분류 → "이 열로 읽기"(`POST /intake/{번호}/cards-map`). **확인 화면**: 맨 위 "명함 n장을 읽어 m건으로 정리했습니다 · …" 한 줄, "읽은 방법" 카드(어느 열이 이름·회사 …가 되었나, 쓰지 않은 열, 합친 명함 수, 같은 파일을 이미 가져왔는지, "열 다시 고르기" `POST …/cards-remap`), "모두 펼치기·접기"와 "모두 포함·제외", 카드: 새 회사(분류 고객/파트너 선택, 연락처 한 줄에 한 명)·연락처 추가(대상은 고정 글, 같은 휴대폰·이메일이 이미 있으면 처음부터 제외)·정리하지 못한 명함(회사 이름이 없는 명함의 이름·연락처 줄). "다시 정리"(AI)는 없다 |
| 활동 기록 목록 | `/activities` | 종류 탭(회의·파트너 미팅·고객 태핑·수요조사·기타), 유래 걸러 보기, 정렬 |
| 활동 기록 쓰기 | `/activities/new` | 메모를 적고 "AI로 정리" 또는 "원문만 저장". "칸을 직접 채우기"(`?manual=1`)는 직접 입력 폼 |
| AI 정리 초안 | `/activities/draft/{작업}` | AI 가 정리한 초안을 고쳐 저장 |
| 활동 기록 상세·수정 | `/activities/{번호}`, `…/edit` | 정리본, 후속 조치, 고객 니즈(고객이 연결된 줄 옆에 "영업기회 만들기"), 원문(접어 둠), 연결 |
| 후속 조치 | `/follow-ups` | 활동 기록에서 나온 할 일. 구분 탭(남은 일·기한 지남·완료), 할 일 글 검색(`?q=`), 완료 표시, "내 할 일로" |
| 업무 보고 목록 | `/reports` | 팀이 윗선에 올리는 일·주·월 업무 보고. 단위 탭(전체·일간·주간·월간), 줄마다 기간·상태(실적 확인·계획 작성 중·확정)·만든 파일. 사이드 메뉴 "오늘" 묶음의 "업무 보고". 위쪽 "보고 만들기" |
| 업무 보고 만들기 | `/reports/new` | 단위(일·주·월)와 기준 날짜를 고르면 기간이 계산된다 (기본은 오늘이 든 기간). 같은 단위·기간의 보고가 이미 있으면 그 보고로 안내한다. 폼 표 `Once` |

AI 가 꺼져 있어도 집계·직접 입력·확정·파일 만들기는 된다. 파일 내려받기 `/reports/{번호}/files/{pptx\|docx\|md}` |

## 4. 주요 흐름

### 4.1 올리기 (가장 자주 쓰는 길)

```
[+ 올리기] ──▶ 파일·붙여넣은 글·메모 올림 ──▶ 정리 중 (AI, 음성은 받아쓰기 먼저)
                                      │
                                      ▼
                              정리안 확인 (확인 대기)
                              · 맨 위 한 줄 요약
                              · 항목 카드: 새 솔루션 / 솔루션에 자료 추가 / 활동 기록
                                / 새 고객 / 새 파트너 / 연락처 추가 / 정리하지 못한 파일
                              · 카드마다 "고치기", "이 항목 제외"
                              · 이미 저장된 같은 파일·같은 할 일 안내
                                      │ [이대로 저장 (n건)]
                                      ▼
                              저장 완료 ──▶ 만들어진 기록으로 이동
```

- 한 묶음은 한 번만 저장된다. 실패하면 "다시 정리", 필요 없으면 "버리기".
- **올리기 칸의 사진 붙여넣기 (베타 AA, JS 보강)**: 파일 영역 아래 "사진을 복사(Ctrl+C)한 뒤 여기에서 붙여넣기(Ctrl+V)해도 돼요." 한 줄(JS 가 있을 때만 보인다). 클립보드의 사진은 끌어다 놓은 파일처럼 같은 `<input type=file>` 에 더해지고(이름 `붙여넣은 사진 N.png`) 고른 파일 목록에 "빼기" 단추가 붙는다. 글만 붙이는 것은 건드리지 않는다. 전체 화면과 홈 카드 모두.
- **명함 파일 가져오기 (베타 AA)**: `/intake/cards` 에서 파일 하나 → 파서(`app/cardfile.py`)가 읽어 정리안(`app/cardplan.py`)을 직접 만든다 → 확인 화면(위 "명함 묶음 상세") → "이대로 저장". 항목 종류와 저장 길(`intake.apply`)은 AI 정리와 같다.
- 올리기 확인 화면의 "이대로 저장" 막대는 쪽 맨 끝(폼 밖, `form="plan-form"` 으로 연결)에 떠 있고, "다시 정리하거나 버리기" 위에는 빈틈이 없다.
- 음성만 있고 받아쓰기가 꺼져 있으면 "보관됨"으로 남는다. 정리 전에는 "정리 시작", 저장 전에 "이 묶음 버리기"(확인 한 번).

### 4.2 영업 흐름

```
활동 기록 ──▶ 고객 니즈 ──▶ 영업기회 ──▶ 프로젝트
 (미팅 메모)   (기록 안의 줄)   (같은 고객의      (수주한 영업기회를
                              니즈를 묶음)      전환하거나 기존 것에 이음)
                                 │
                                 ├──▶ 제안 건 (특정 고객: 고객 필수, 영업기회·프로젝트 선택 / 다수 고객: 그룹 이름 필수, 붙인 고객·BM 선택)
                                 └──▶ BM (선택: 어떤 사업 모델로 진행하는지)
```

- 활동 기록 상세에서 고객이 연결된 니즈 줄 옆의 "영업기회 만들기"(또는 고객 상세 "+ 영업기회 만들기") → 영업기회 등록 폼에 그 고객과 니즈가 미리 채워진다. `/opportunities/new` 를 그냥 열면 먼저 고객을 고르고 "다음"을 누른다.
- 단계 순서는 강제하지 않는다. 프로젝트로 전환은 수주일 때 한 번만. 수주·실패로 바꿀 때는 사유를 받는다 (영업 A 단계).
- 홈 "챙길 영업기회" 카드: 진행 중이면서 다음 할 일 없음·다음 할 일 날짜 지남·예상 수주일 지남·30일 넘게 활동 없음인 건. 탭 내 건(기본)·우리 팀·전체(`?opp=team|all`), 6건까지, "멈춘 건 모두 보기" 는 목록의 `?stale=1&who=…`.

### 4.3 솔루션 발굴 흐름

```
아이템 접수 ──▶ 사전 태핑 ──▶ 수요조사 ──▶ 박스 등록          (어느 단계에서든 보류)
 ▲
 ├─ 직접 등록
 ├─ 올리기 정리안의 "새 솔루션"
 └─ 리서치 보고서의 "후보로 등록"
```

- 보류가 아닌 솔루션은 모두 제안 후보가 된다.

## 5. 제안 작업 화면 (5단계)

```
제목 줄:  고객(다수 고객이면 "다수 고객" 배지·그룹 이름·붙인 고객 수·신규 사업) · 제안 이름   [다음 동작 하나]
단계 막대: ① 대상 ─ ② 방향 ─ ③ 구체화 ─ ④ 구성안 ─ ⑤ 제안서
┌───────────────────────────────────┬──────────────────────┐
│ ① 대상: 고객·프로젝트·영업기회·검토 사업방식·요청 메모 │ 선택한 방향             │
│ ② 방향: AI 가 낸 방향 2~3개 중 하나 선택 │ 출처                  │
│ ③ 구체화: AI 와 대화 (예시 질문 칩,     │ 대상 요약              │
│    답변은 대화 안에서 바로 이어짐)       │ 연결된 것              │
│ ④ 구성안: 장별 카드 (고치기·순서·삭제,   │                      │
│    확인 항목 확인 표시)               │                      │
│ ⑤ 제안서: 고객용 PPT / 내부 검토용 PPT  │                      │
└───────────────────────────────────┴──────────────────────┘
```

- 지금 단계 구역만 펼쳐지고, 지난 단계는 접힌다.
- **검토 사업방식**(구축형·임대형·투자형 0~3개): 제안 만들기 폼의 요청 내용 쪽에 체크 상자로 있고, 영업기회를 고르면 그 사업방식이, 없으면 BM(프로젝트의 BM 포함, 다수 고객은 신규 사업 BM)의 대표 사업방식이 미리 체크된다(고칠 수 있다). 제안 화면 ① 대상 구역에 배지로 보이고 "대상 수정"에서 고친다 — 고쳐도 만들어 둔 방향·구성안은 그대로이고 다음 방향 만들기·대화·구성안부터 반영된다. 방향 카드에는 그 방향이 전제하는 사업방식 배지가 붙고, 오른쪽 "대상 요약"에도 보인다.
- 제목 줄의 다음 동작은 단계에 따라 바뀐다: 방향 만들기 → 방향 고르기 → 구성안 만들기 → 제안서 만들기(옛 파일이면 "제안서 다시 만들기") → 고객용 PPT 내려받기. 제안 화면 제목 줄에는 "수정"이 없고(대상은 ① 대상 구역에서 고친다) "삭제"만 있다.
- 고객용 PPT 에는 발표자 노트와 확인 항목이 없고, 지식 사본 경로(`solutions/3.md`, `근거=customers/12.md`, `~/data/knowledge/solutions/3/card.md` 처럼 머리말·표지가 붙은 것도 포함. 주소와 `partners/2개사`·`customers/12%`·`solutions/5G/LTE`·`customers/1,200명`·`solutions/3안`·`opportunities/10억대` 처럼 번호 뒤에 단위가 붙은 수량은 남지만(단위 바로 뒤가 `.md` 같은 확장자이거나 `/card.md` 꼴이면 경로, 뒤의 `(kt.com)` 은 확장자가 아니다. 사본 폴더 안 `knowledge/solutions/3일` 은 단위가 붙어도 경로), `knowledge/solutions/card.md`·`data/app.db`·`app.db.before-migrate-…`·`activities/undated/12.md`·`intake_work/…`·`decks/…`·`data/models/small/…` 처럼 앱이 쓰는 번호 없는 사본·데이터 파일 경로도 빠지고(앱이 쓰지는 않지만 `knowledge/index.md`·`data/solbox.db` 같은 이름도 같이 뺀다. 주소(`https://`·`s3://` 처럼 `…://` 로 시작하는 모든 주소) 속과 `docs/knowledge/guide.md`·`kt.com/data/app.db`·`data/logs/metrics 수집`·`/data/models/ 에 배포` 같은 일반 글은 남는다. 이 판정은 어림이다), `solutions/3에서`·`solutions/3번`·`solutions/3_v2` 처럼 조사·다른 글자가 붙은 것은 경로로 보아 빠진다. 표 머리글도 같다)가 든 줄은 빠진다. 뺀 줄이 있으면 제안서 상자에 "고객용 파일에서 내부 경로가 든 n줄을 뺐습니다"가 나온다. 내부 검토용에는 출처 이름과 확인 항목이 노트에 들어간다.
- 구성안·방향을 만드는 동안(대기·진행) 그 구역 맨 위에 진행 상자가 보인다: "AI가 슬라이드 구성안을 만드는 중… (보통 1분 안에 끝납니다 · n초 경과)" 또는 "AI 대기 n번째". 2초마다 갱신하고 끝나면 쪽이 새로 고쳐져 새 결과가 보인다. 실패하면 구역 안에 이유와 "다시 시도". 만들기 버튼은 누르면 "만드는 중…" 으로 바뀌고 잠긴다 (JS 가 있을 때).
- 제안서를 만들고 돌아오면 제안서 상자 맨 위에 "제안서 파일을 만들었습니다 (시각)" 이 보인다. 확인하지 않은 항목 경고에는 항목이 남은 장으로 가는 링크("3장(1개)")가 있다. 옛 파일을 지우지 못해도(파워포인트가 열어 둠) 새 제안서는 정상이다.
- 제안서 상자에는 마지막으로 만든 고객용 파일의 "품질 검사: 경고 N건"(펼치면 쪽 번호와 고칠 점: 줄표·원형숫자·30자를 넘는 대제목·결론 띠 없는 장·넘친 글 …) 또는 "품질 검사: 경고 없음" 이 보인다 (베타 AF, `app/deck_gates.py`; 검사는 만들기를 막지 않고, 옛 제안 건에는 줄이 없다). PPT 디자인은 paperlogy-ppt 디자인 시스템(강의·마케팅 모드)이다: 챕터 라벨 → 대제목 → 본문 카드 → 결론(SO WHAT) 띠 → 쪽 번호.
- 고객용·내부 검토용으로 나누기 전에 만든 옛 제안서는 상자에 "다시 만들어 주세요"가 나오고 내려받기 버튼이 없다. "다시 만들기"를 눌러야 두 파일이 생긴다.
- 마무리 장의 연락처는 "내 정보"의 연락처로 채워진다.

## 6. 화면 사이를 잇는 공통 장치

| 장치 | 설명 |
|---|---|
| 연결된 것 | 모든 상세 화면 오른쪽. 온톨로지의 관계 정의를 따라가 연결된 기록을 묶음별로 보여 주고, 묶음마다 "+ …" 동작과 "모두 보기"가 있다 |
| 미리 채우기 | 상세 화면의 "+ 활동 기록", "+ 제안", "+ 영업기회" 등은 그 기록이 미리 골라진 등록 폼을 연다 |
| 결과 알림 | 저장·삭제·단계 변경 뒤 다음 화면 맨 위에 한 줄 |
| 유래 | 솔루션·활동 기록·고객·파트너에 "직접 입력 / 올리기 / 리서치" 표시와 걸러 보기. 올리기·리서치로 AI 가 만든 기록에는 목록(휴대폰은 첫 칸 보조 줄, 넓은 화면은 유래 칸)과 상세 "기록 정보" 카드의 "유래:" 줄 옆에 "AI 생성" 배지가 붙는다 (직접 입력·모름은 없음. "연결된 것" 카드는 유래를 보이지 않으므로 배지도 없다) |
| 덮어쓰기 방지 | 수정 화면을 연 뒤 다른 곳에서 바뀌었으면 저장을 막고 알려 준다. 쓴 내용은 그대로 남고, "그래도 내 내용으로 저장"을 누를 수 있다 (같은 번호에 새 기록이 만들어진 경우는 불가) |
| 중복 제출 방지 | 등록 폼의 두 번 누르기·"뒤로 가서 다시"는 처음 결과 화면으로 간다. 내용을 고쳐 다시 내면 새 등록이다 |
| 삭제 권한 | 지우기는 만든 사람 또는 관리자만. 지우기 전에 영향을 알리는 확인 화면이 나온다 |
| 같은 이름 경고 | 등록할 때 같은 이름이 있으면 "기존 것 열기 / 그래도 새로 등록" |
| AI 상태 | 위쪽 줄 오른쪽. 사용 가능 여부와 대기 중인 작업 수 |
