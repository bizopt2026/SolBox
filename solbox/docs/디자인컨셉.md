# 솔루션 박스 디자인 컨셉: 차분한 작업대

솔루션 박스는 매일 여는 사내 업무 도구다. 화려할 필요는 없다. 열었을 때 **오늘 할 일과 지금 단계가 바로 보이고, 실수로 지울 일이 없어야** 한다. 그래서 컨셉은 "잘 정돈된 작업대"다. 바탕은 조용하고, 색은 의미가 있을 때만 쓰고, 일의 흐름(발굴 단계, 영업기회 단계, 제안 단계)이 눈에 보이게 한다.

이 문서는 화면을 새로 만들거나 고칠 때 지킬 원칙과, 지금 코드(`app/static/app.css`, `app/templates/_macros.html`)에 있는 구성 요소를 정리한다. 화면 목록과 흐름은 `docs/화면구성도.md` 에 있다. 값을 바꾸면 이 문서도 같이 고친다.

## 다섯 가지 원칙

1. **색은 의미에만 쓴다.** 바탕과 글은 무채색이고, 색은 브랜드 남색(주 버튼·링크·현재 위치)과 의미 색(완료·주의·위험·보라·회색)만 쓴다. 장식용 색은 쓰지 않는다. 코드 값(단계·상태·종류)의 색은 `ontology.CODE_TONES` 한 곳에서 정한다.
2. **한 화면에 주 행동은 하나다.** 꽉 찬 남색 버튼(`.primary`)은 화면마다 한 개만 둔다. 나머지는 흰 바탕 보조 버튼이다. 지우기는 빨간 글자 버튼(`.danger`)이고 주 버튼에서 떨어진 자리(오른쪽 끝, 좁은 화면에서는 수정 옆 끝)에 두며, 누르면 그 자리에서 한 번 더 묻는다(되묻기).
3. **흐름을 보여 준다.** 발굴 단계·영업기회 단계·제안 진행 단계는 단계 막대(`.stagebar`)로 보여 준다. 홈 맨 위의 발굴 흐름 칸(`.flow`)은 단계별 건수와 이번 주 늘어난 수를 보여 준다. 보류는 흐름 밖이라 따로 둔다.
4. **AI 결과는 초안이라는 것이 보이게 한다.** AI 가 만든 정리안·제안은 사람이 저장해야 반영된다는 앱 규칙이 화면에도 드러나야 한다. AI 상태는 위쪽 줄의 상태 점(`.aistat`)으로 늘 보이고, AI 가 꺼져 있어도 조회와 직접 입력은 된다고 알린다.
5. **휴대폰에서도 기록할 수 있다.** 미팅 직후 휴대폰으로 메모를 남길 수 있어야 한다. 1099px 밑에서는 왼쪽 메뉴가 위쪽 줄로 올라가고, 759px 밑(휴대폰)에서는 머리가 한 줄(표지·검색·AI 상태·"메뉴" 펼침)이 되고 아래 고정 탭(`.tabbar`)이 생긴다. 아래에 붙는 저장 막대는 탭 높이(`--tab-h`)만큼 올라선다. 메모 쓰기 화면은 안내를 줄여 메모 칸이 첫 화면에 보이게 한다. 600px 밑에서는 목록 표의 보조 칸을 숨기고 그 내용을 제목 밑 한 줄(`.row-meta`)로 모은다. 좁은 화면의 검색칸은 16px 글자라 눌러도 화면이 확대되지 않는다 (다른 입력칸은 본문과 같은 14px).

## 디자인 토큰 (`app/static/app.css` 의 `:root`)

| 쓰임 | 토큰 | 값 |
|---|---|---|
| 바탕 / 면 / 움푹한 면 | `--bg` / `--surface` / `--sunken` | `#f3f5f9` / `#ffffff` / `#eceff5` |
| 선 | `--line` / `--line-2` | `#dde2ec` / `#c9d1e0` |
| 글 (진함 → 흐림) | `--ink` / `--ink-2` / `--ink-3` | `#141a2b` / `#4a5368` / `#5f687c` (흐린 글도 흰 바탕에서 4.5:1 이상) |
| 브랜드 (주 버튼·링크·현재 위치·초점) | `--brand` / `--brand-soft` / `--brand-deep` | `#2447d6` / `#e7ecff` / `#16308f` |
| 완료 | `--ok` / `--ok-soft` / `--ok-line` | `#0f7a55` / `#dcf5ea` / `#a8dcc5` |
| 주의 (확인 필요·진행 중) | `--warn` / `--warn-soft` / `--warn-line` | `#9a5b00` / `#fff0d1` / `#f1d08a` |
| 위험 (오류·삭제·기한 지남) | `--bad` / `--bad-soft` / `--bad-line` | `#b3261e` / `#fde4e1` / `#f0b4ae` |
| 보라 (접수·정리안 등) | `--violet` / `--violet-soft` | `#5b3fc4` / `#ece7ff` |
| 중립 | `--slate` / `--slate-soft` | `#4a5368` / `#e6e9f0` |

의미 색은 글자색 + 옅은 바탕(+ 테두리) 한 쌍으로 쓴다. 새 색이 필요하면 토큰을 먼저 더하고, 화면에 색 값을 바로 쓰지 않는다.

- **글꼴**: 앱에 들어 있는 글꼴(`app/static/fonts`)과 설치된 글꼴만 쓴다. 서버 PC 가 사내망에 있어 외부 글꼴·아이콘·스크립트(CDN)를 받지 않는다. 순서는 Pretendard → 맑은 고딕 → Apple SD Gothic Neo. 본문 14px(`--fs-body`), 화면 제목 24px, 구역 제목 16px, 카드 제목 15px, 작은 글 13px·12px. 제목은 다른 글꼴 대신 굵기(700)로 구분한다. 표 안 숫자는 고정폭 숫자(`tabular-nums`).
- **간격**: 4의 배수(`--s1`~`--s6`: 4·8·12·16·24·32px). 카드 사이 16px(`--gap`), 카드 안쪽 20px(`--card-pad`, 좁은 화면 16px).
- **모서리**: 버튼·입력칸·알림 8px(`--r-sm`), 카드 10px(`--r`), 배지·칩 알약(`--r-pill`).
- **그림자**: 카드에 아주 옅은 그림자 하나(`--shadow`), 떠 있는 창에만 `--shadow-pop`. 그라데이션은 쓰지 않는다.
- **움직임**: 진행 표시(점 세 개, 정리 중 뼈대, AI 상태 점)와 성공 알림이 서서히 사라지는 것뿐이다. `prefers-reduced-motion` 이면 모두 멈춘다.

## 단계·상태 색 (`ontology.CODE_TONES`)

| 목록 | 값 → 색 |
|---|---|
| 발굴 단계 | 아이템 접수 보라 · 사전 태핑 주의 · 수요조사 브랜드 · 박스 등록 완료 · 보류 중립 |
| 영업기회 단계 | 발굴 브랜드 · 제안 주의 · 협상 보라 · 수주 완료 · 실패 위험 · 보류 중립 |
| 제안 진행 | 새 제안 중립 · 방향 브랜드 · 다듬기 보라 · 목차 주의 · PPT 완료 |

그 밖의 상태(올리기·작업·리서치 등)도 같은 표에 있다. 템플릿은 색을 직접 고르지 않고 `tone_class()` 가 주는 `tone-*` 클래스를 쓴다.

## 구성 요소

- **셸**: 왼쪽 메뉴(`.side`, 기록 종류 묶음만, 현재 위치는 `aria-current`), 위쪽 줄의 "오늘" 탭(`.top-tabs`)·"+ 올리기"(옅은 남색 `.top-upload`)·검색칸·AI 상태 점·관리 펼침(`.top-admin`)·도움말(넓은 화면 1100px 이상), 가운데 쪽(`.page`, 최대 1240px). 휴대폰은 위쪽 줄에 표지(`.m-mark`)와 "메뉴" 펼침(`.m-menu`, 같은 메뉴를 한 벌 더 그린 것)이 더해지고 사이드 메뉴는 숨는다. 아래 고정 탭 높이는 토큰 `--tab-h`(넓은 화면 0).
- **화면 머리**: `page_header` 매크로. 이동 경로, 제목, 한 줄 설명, 오른쪽 끝 동작 버튼(주 버튼 하나).
- **버튼**: 기본(흰 바탕) · `.primary` · `.danger` · `.ghost`(테두리 없음) · `.small`. 버튼처럼 보이는 링크는 `a.button`.
- **알림**: 저장·삭제·단계 변경 뒤 한 번 보이는 결과 알림(`.flash`, `app/notices.py`), 안내(`.notice`, 주의 색), 오류(`.error`, 위험 색), 고쳐 쓰기 충돌(`.conflict`), AI 작업 상태(`.job-status`).
- **되묻기**: 지우기 링크가 그 자리에서 "정말 삭제할까요? [삭제] [취소]"(`.confirm-inline`)로 바뀐다. 스크립트가 없으면 서버의 확인 화면으로 간다.
- **단계 막대**: `.stagebar .steps .step`. 좁은 화면에서는 옆으로 밀리고, 더 밀 곳이 있는 쪽 가장자리가 흐려진다.
- **배지·칩**: 상태·단계는 배지(`.badge.tone-*`), 태그·출처는 칩(`.chip`, 링크면 눌러서 거른다).
- **목록**: 도구줄(구분 탭 `.seg`, 검색, 걸러 보기, 정렬 막대 `.sortbar`) + 목록 표(`.list-table`, 제목 칸은 `title_cell` 매크로) + 쪽 넘기기(`pager`). 좁은 화면에서는 걸러 보기·정렬이 "걸러 보기·정렬" 펼침(`.tool-more`) 안으로 들어간다.
- **빈 값**: 목록 표의 빈 칸은 흐린 "–"(`none_dash`, 화면 읽기 프로그램에는 "없음"). 상세 화면의 빈 항목은 따로 표시하지 않고 `props_card` 가 한 줄로 모은다.
- **빈 화면**: 문장 하나 + 주 동작(`empty_list`, 점선 테두리 `.empty`). 걸러서 비었으면 "조건 지우기"를 준다.
- **상세 화면**: `detail_head`(삭제 → 수정 → 다음 동작 하나) + 흐름이 있으면 단계 막대 + 왼쪽 내용(`.dmain`)·오른쪽 옆 칸(`.daside`, 연결된 것·기록 정보). 두 칸은 쪽 본문 폭이 960px 이상일 때만 나란하고(컨테이너 질의) 아니면 쌓인다.
- **올리기**: 영역 전체가 파일 입력칸이라 어디를 눌러도 파일 선택이 열리고, 끌어다 놓기와 고른 파일 목록은 스크립트가 더한다.

## 하지 않는 것

- 외부 CDN 글꼴·아이콘·스크립트를 쓰지 않는다.
- 색 값을 템플릿이나 화면별 CSS 에 바로 쓰지 않는다 (토큰과 `tone-*` 로만).
- 그림자·그라데이션·애니메이션을 장식으로 쓰지 않는다.
- 화면 문구를 영어로 두지 않는다.
- 스크립트가 없으면 안 되는 기능을 만들지 않는다. 스크립트는 편의(끌어다 놓기, 되묻기, 알림 치우기)만 더한다.
