# 솔박스 (SolBox)

> 이전 이름은 "솔루션 박스"입니다. 설계·계획 문서(`docs/superpowers/`)와 Windows 작업·방화벽 규칙 이름(`SolutionBox`)에는 이전 이름이 남아 있습니다.

> 이 저장소(SolBox, 예전 이름 bizopt2026)에서 솔박스는 `solbox/` 폴더이며, 아래 명령은 모두 `solbox` 폴더 안에서 실행합니다.

솔루션 발굴 과정(아이템 접수 → 사전 태핑 → 수요조사 → 박스 등록)과 파트너·고객·프로젝트·활동 기록을 한곳에 모으는 사내 웹 앱입니다. AI(Claude CLI)는 메모 정리와 소개 초안 작성을 돕는 보조 기능이며, AI가 동작하지 않아도 조회와 직접 입력은 그대로 쓸 수 있습니다.

## 준비물

- Python 3.11 이상
- (AI 기능을 쓸 때) Claude CLI. **앱을 실행하는 PC에 설치하고, 앱을 실행하는 Windows 계정과 같은 계정으로 로그인**해 두어야 합니다. 다른 PC나 다른 계정에서 로그인한 것은 소용없습니다.

## 설치

프로젝트 폴더에서 PowerShell을 열고 아래 명령을 하나씩 실행합니다.

```powershell
python -m pip install -e .
```

## 설정 파일 만들기

예시 파일을 복사해 `config.toml` 을 만듭니다.

```powershell
copy config.example.toml config.toml
```

(이미 `config.toml` 이 있으면 복사하지 마세요. 덮어써서 `secret_key` 와 `data_dir` 를 잃습니다. 있는지 먼저 확인합니다: `Test-Path config.toml` 이 `True` 면 그 파일을 그대로 씁니다.)

메모장 등으로 `config.toml` 을 열어 다음을 확인합니다.

- `secret_key`: **반드시 길고 무작위한 값으로 바꾸세요.** 비어 있거나 `change-me` 그대로면 서버가 시작되지 않습니다. 아래 명령으로 만들 수 있습니다.
  ```powershell
  python -c "import secrets; print(secrets.token_urlsafe(32))"
  ```
- `data_dir`: 데이터(`app.db`, `uploads/`, `knowledge/`, `decks/`, `reports/`)를 저장할 폴더. 상대 경로는 `config.toml` 이 있는 폴더 기준입니다. Windows 경로는 `data_dir = "C:/solbox/data"` 처럼 `/` 로 쓰거나 `data_dir = 'C:\solbox\data'` 처럼 작은따옴표로 감싸세요 (큰따옴표 안의 `\` 는 오류가 납니다).
- `host`, `port`: 기본은 `127.0.0.1`, `8443` 입니다. 다른 PC에서도 접속하게 하려면 `host = "0.0.0.0"` 으로 바꿉니다.
- `ssl_certfile`, `ssl_keyfile`: 인증서와 키 파일 경로. 둘 다 적으면 HTTPS로, 적지 않으면 HTTP로 열립니다. 자체 서명 인증서는 `python -m app.cli make-cert --host <접속 주소>` 로 만들고, 출력되는 두 줄을 넣습니다.

## 관리자 계정 만들기

처음 한 번, 관리자 계정을 만듭니다. 아이디·이름·비밀번호는 원하는 값으로 바꾸세요.

```powershell
python -m app.cli create-admin --username admin --name 관리자
```

비밀번호는 실행하면 입력창에서 두 번 물어봅니다 (화면에 보이지 않습니다). 웹 화면과 같은 규칙(8자 이상, 아이디와 같지 않음, 한 글자만 되풀이하지 않음)이 적용되고, 맞지 않으면 이유와 규칙을 알려 주고 계정을 만들지 않습니다.

일반 사용자는 관리자로 로그인한 뒤 화면 위쪽 "관리 → 사용자"에서 추가합니다.

## 실행

```powershell
python -m app
```

브라우저에서 아래 주소를 엽니다.

- 인증서를 설정하지 않았을 때: http://127.0.0.1:8443
- `ssl_certfile`, `ssl_keyfile` 을 설정했을 때: https://127.0.0.1:8443 (자체 서명 인증서는 브라우저 경고가 나올 수 있습니다)

포트나 주소를 바꿨다면 `config.toml` 의 값에 맞춰 열면 됩니다. 종료는 실행 창에서 `Ctrl+C` 입니다.

화면 글꼴은 Pretendard Variable(SIL OFL 1.1)을 `app/static/fonts/` 에 함께 담았습니다 (사내망에서도 바깥 접속 없이 쓰고, 라이선스 글은 `Pretendard-OFL.txt`).

## 올리기

화면 위쪽 "올리기" 메뉴(또는 홈의 올리기 카드)에서 파일을 한꺼번에 올리면 AI가 어디에 정리할지 제안하고, 확인 한 번으로 저장합니다.

1. 문서(pptx, pdf, docx, xlsx, txt, md, csv)·사진·음성을 한 번에 20개까지 올립니다. 필요하면 무엇인지 알려 주는 메모를 적습니다.
2. AI가 파일을 읽고 새 솔루션, 솔루션에 자료 추가, 활동 기록, 새 고객, 새 파트너, 연락처 추가로 나눈 정리안을 만듭니다. 사진 속 글자도 읽습니다.
3. 정리안 화면에서 고칠 곳을 고치고, 저장하지 않을 항목은 "이 항목 제외"를 체크한 뒤 "이대로 저장"을 한 번 누릅니다. 그 전에는 아무것도 등록되지 않고, 같은 묶음은 한 번만 저장됩니다.
4. 마음에 들지 않으면 메모를 고쳐 "다시 정리"하거나 "이 묶음 버리기"를 누릅니다. 올린 원본 파일은 버려도 남습니다.

- AI는 기록을 추가만 합니다. 이미 있는 기록을 고치거나 지우지 않습니다. 단 하나의 예외가 "연락처 추가"입니다. 이미 등록된 파트너·고객의 명함이나 연락처가 올라오면 그 기록의 연락처 칸 끝에 한 줄(예: `박서연 팀장 · 02-555-0142 · seoyeon@… (명함, 2026-11-19 올리기)`)만 덧붙입니다. 기존 글은 그대로 두고, 같은 전화·이메일이 이미 있으면 "이미 있는 연락처"로 건너뜁니다. 저장 전 정리안 화면에서 대상과 내용을 고치거나 제외할 수 있습니다.
- 메뉴의 "올리기" 옆 숫자는 내가 올린 올리기 묶음 중 확인 대기 건수입니다.
- AI가 환경 문제(로그인·한도·네트워크 등)로 실패한 상태이면 올리기 화면에 안내와 직접 입력 링크가 나옵니다.
- 음성 받아쓰기: 설정 `transcriber = "faster-whisper"` 로 켜면 서버 PC 안에서 녹음을 글로 받아써서(GPU 없이 CPU, 녹음은 서버 밖으로 나가지 않음) 문서처럼 정리합니다. 음성만 올려도 정리안까지 갑니다. 받아쓰기는 올리는 순간이 아니라 AI 정리 작업 안에서 한 번에 하나씩 하며, 길면 오래 걸립니다(파일 표와 상태 줄에 "받아쓰는 중 37%" 처럼 보이고 화면을 떠나도 됩니다). 받아쓴 글은 틀릴 수 있어 AI가 등록된 이름으로 바로잡은 곳은 이유에 적고, 불확실한 숫자에는 "(받아쓰기 확인 필요)"를 붙입니다. 켜는 법은 운영 가이드 12번. 켜지 않으면 음성은 보관만 하고 "받아쓰기 필요"로 표시되며, 글자로 풀어 올리면 정리할 수 있습니다.
- **받아쓰기는 개발 환경에서 실제로 돌려 보지 못했습니다** (모델 저장소에 접속할 수 없었습니다). 시험은 가짜 엔진으로만 했으므로 서버 PC에서 아래 수동 확인 17~20번을 꼭 해 보세요.
- 올리기 묶음은 올린 사람과 관리자만 볼 수 있습니다.

## 화면 사용 팁

- 저장·삭제·단계 변경을 하면 다음 화면 맨 위에 "저장했습니다" 같은 결과 알림이 나오고, 닫기를 누르거나 잠시 기다리면 사라집니다.
- 지우기는 한 번 더 묻습니다 ("정말 삭제할까요? 삭제 / 취소"). 브라우저 스크립트가 꺼져 있으면 지울 대상과 지우면 어떻게 되는지를 보여 주는 확인 화면이 나옵니다.
- 상세 화면의 "+ 활동 기록 쓰기"·"+ 제안 만들기" 같은 동작은 그 고객·솔루션 등을 미리 채워 열어 줍니다. 고객 화면의 "이야기했지만 아직 제안하지 않은 솔루션"에서는 솔루션마다 "제안 만들기"로 바로 갈 수 있습니다.
- 목록은 도구줄의 "정렬"(이름순·최근 수정순, 활동 기록은 일자순·제목순)으로 바꿉니다. 목록의 줄을 아무 데나 눌러도 상세로 갑니다.
- 홈의 후속 조치 카드에서 "내 할 일"을 누르면 담당 칸에 내 이름이 적힌 것만 모아 봅니다.
- 제안 대화는 비어 있을 때 시작 질문 칩이 나오고, Ctrl+Enter(Mac 은 ⌘+Enter)로 보냅니다 (Enter 는 줄바꿈). 폼을 고친 채 다른 곳으로 가려 하면 브라우저가 한 번 묻습니다.
- 위쪽 줄 오른쪽 끝(좁은 화면은 메뉴 줄·메뉴 펼침) "도움말"에 업무 흐름 그림, 용어 풀이, 자주 하는 일의 순서, 단축키가 있습니다.

## 이번 베타 고침(B 묶음) 사용 메모

- 음성만 올렸고 받아쓰기가 꺼져 있으면 묶음은 "보관됨"(실패 아님)으로 남고, 글자로 풀어 올리거나 관리자에게 받아쓰기를 요청하는 안내가 나옵니다.
- 같은 이름의 솔루션·고객·파트너·BM·프로젝트·영업기회를 만들거나 이름을 바꾸면 경고와 "기존 것 열기 / 그래도 새로 등록"이 나옵니다. 같은 내용의 자료 파일은 솔루션에 다시 붙이지 않고, 이미 저장한 파일을 다시 올리면 확인 화면 카드에 알리고 그 원문의 활동 기록은 처음부터 제외로 둡니다.
- 솔루션·활동 기록·고객·파트너 목록에 "유래" 걸러 보기(`?origin=intake|research|manual`)와 열이 있고, 전체 검색은 소개·설명·메모·연락처·정리본·원문·후속 조치·고객 니즈까지 찾아 맞은 글을 보여 줍니다.
- 후속 조치 담당은 "이름 + 직함"(대리·과장·팀장·님 …)이어도 사용자와 이어지고(같은 이름 사용자가 하나일 때), 안 이어진 줄에는 "내 할 일로" 버튼이 있습니다. 관리자 "AI 작업"에는 대기·소요 시간, 종류 거르기, 실패한 작업의 "다시 시도"가 있고, "시스템" 화면의 서버 점검은 `python -m app.cli check` 와 같은 항목입니다.

## 영업기회와 BM

BM 은 사업 모델이고, 특정 고객별로 나뉘는 것은 프로젝트입니다. 흐름은 활동 기록 → 고객 니즈 → 영업기회 → 프로젝트입니다.

- **영업기회** (메뉴 "영업기회"): 한 고객의 니즈를 묶어 사업으로 만들어 가는 건입니다. 활동 기록 화면의 고객 니즈 옆 "영업기회 만들기"로 시작하거나(고객과 그 니즈가 채워집니다), 영업기회 목록에서 고객을 골라 만듭니다. 묶을 수 있는 니즈는 그 고객에 연결된 니즈 중 아직 다른 영업기회에 묶이지 않은 것뿐이고, 수정 화면에서 체크를 풀면 풀립니다. 이름만 쓰고 고객 기록에 연결되지 않은 니즈는 활동 기록에서 고객 이름을 등록된 이름으로 고치면 나타납니다. 단계(발굴 · 제안 중 · 협상 · 수주 · 실패 · 보류)는 상세 화면에서 한 번 눌러 어디로든 바꿀 수 있습니다. 수주하면 "프로젝트로 전환"으로 같은 고객의 새 프로젝트를 만들거나(BM 을 이어받고, 이름은 고칠 수 있음) 같은 고객의 기존 프로젝트를 이을 수 있고, 한 영업기회에 한 번만 됩니다. 단계를 나중에 바꿔도 프로젝트는 지워지지 않습니다. 영업기회를 지우면 묶은 니즈는 풀리고(니즈는 남음) 제안 건의 연결은 비워지며 프로젝트는 남습니다.
- **BM** (메뉴 "BM"): 이름, 한 줄 설명, 대상 고객 유형, 수익 구조와 BM 이 구성되는 솔루션을 적습니다. 프로젝트와 영업기회는 BM 하나를 고를 수 있습니다. 따르는 프로젝트나 영업기회가 있는 BM 은 지울 수 없습니다.
- 제안 건을 만들 때 그 고객의 영업기회를 고를 수 있습니다. 후보 솔루션의 집합은 그대로이고, AI 와 화면에서의 순서만 영업기회의 검토 솔루션 → 그 영업기회의 BM(영업기회를 고르지 않았으면 프로젝트의 BM) 솔루션 → 나머지 순서가 됩니다.
- 활동 기록의 "연결"에서 영업기회도 고를 수 있습니다. AI 정리와 올리기는 영업기회·BM 을 만들거나 제안하지 않습니다. 예상 금액·시기는 다루지 않습니다.
- AI 가 읽는 knowledge 폴더에 `bms/`, `opportunities/` 가 더해지고(형식 5), 처음 시작할 때 사본을 한 번 다시 만듭니다.

## 연결된 것 보기

솔루션·파트너·고객·프로젝트·영업기회·BM·활동 기록·제안 건의 상세 화면 아래 "연결된 것" 구역은 직접 이어진 기록(프로젝트, 활동 기록, 제안 건 …)을 먼저 보여 주고, 그 아래 "건너서 연결된 것"에 한 단계 건너 닿는 기록을 보여 줍니다. 예: 고객 화면의 "이야기된 솔루션"(그 고객의 활동 기록을 거친 솔루션), "제안된 솔루션", "남은 후속 조치", 파트너 화면의 "솔루션이 들어간 제안 건"·"솔루션이 닿은 고객", 솔루션 화면의 "관심을 보인 고객"·"이야기된 프로젝트". 건너서 닿은 항목 아래에는 "활동 기록 2건을 거쳐" 처럼 어느 기록을 거쳤는지 적힙니다. 한 그룹은 10건까지 보이고 나머지는 "외 N건 · 모두 보기"로 목록(`?customer_id=5` 같은 걸러 보기)에 갑니다. 올리기 묶음에 닿는 연결은 묶음을 열 수 있는 사람(올린 사람과 관리자)에게만 보입니다. AI 가 읽는 knowledge 폴더의 솔루션·고객·파트너·프로젝트·영업기회·BM 사본도 맨 아래 "## 연결"에 같은 내용을 적습니다(형식 6, 처음 시작할 때 사본을 한 번 다시 만듭니다).

## 2단계: 제안

고객에게 낼 제안서(PPT)를 AI와 함께 만드는 흐름입니다. 화면 위쪽 "제안" 메뉴에서 시작합니다.

1. 제안 건을 만들 때 고객과 요청 메모를 적고, 있으면 프로젝트도 고릅니다. 보류가 아닌 모든 솔루션이 제안 후보이고, 보류 단계의 솔루션은 제안 건에서 직접 추가해야 후보가 됩니다.
2. AI가 제안 방향 2~3개를 근거(출처)와 함께 내놓습니다. 하나를 선택하면 구체화 단계로 넘어갑니다.
3. 채팅으로 범위와 강조점을 다듬습니다. 답변은 글자가 늘어나며 보입니다.
4. "제안서 만들기"를 누르면 AI가 6~14장의 슬라이드 구성안을 만듭니다. 구성안 화면에서 장별로 고치고, 옮기고, 지우고, 추가할 수 있습니다. 자료에 근거가 없는 내용은 확인 항목(근거 문제·확인할 점)으로 표시되며, 출처와 확인 항목은 슬라이드 본문이 아니라 검토 화면과 슬라이드 노트에만 나옵니다.
5. "PPT 만들기"로 파일 두 개를 만듭니다: **고객용 PPT**(발표자 노트 없음, 고객에게 보내는 파일, `…_고객용.pptx`)와 **내부 검토용 PPT**(노트에 출처 이름과 확인할 점, 보내면 안 되는 파일, `…_내부검토용.pptx`). 확인하지 않은 항목이 남아 있으면 개수를 경고로 보여 주지만 만들기는 막지 않습니다. 마무리 장의 담당·연락처는 AI가 쓰지 않고 만든 사람의 이름과 "내 정보"의 연락처로 채웁니다. 구성안 본문에 작성자가 할 일처럼 쓰인 줄("…을 제시", "…확인 필요" 등)은 자동으로 "확인할 점"으로 옮겨집니다. 구성안을 고치면 "구성안이 바뀌었습니다. 다시 생성하세요." 가 보이니 다시 만드세요. 구성안 수정과 PPT 만들기에는 AI가 필요 없습니다.

만든 PPT는 `data_dir` 아래 `decks/` 에 저장되고, 제안 건을 지우면 함께 지워집니다.

## 3단계: 리서치와 서버 운영

- 관리 → 리서치 설정에서 주제와 실행 주기를 정하면 매주 시장·기술·정책 웹 조사와 발굴 방향 제안이 만들어지고, "리서치" 메뉴에서 봅니다.
- 관리 → 시스템에서 버전, 데이터 폴더, 최근 백업, AI 작업 수를 보고 "AI 연결 확인"과 "지금 백업"을 쓸 수 있습니다.
- 명령: `python -m app.cli check`(설치 점검), `make-cert --host <주소>`(HTTPS 인증서), `backup`, `backup --verify <폴더>`.
- 설치·인증서·방화벽·자동 시작·백업·복원·업데이트·문제 해결은 [docs/운영가이드.md](docs/운영가이드.md), 서버 PC로 옮기는 작업은 [docs/서버이관_Claude용.md](docs/서버이관_Claude용.md) 를 보세요. `scripts/` 의 PowerShell 스크립트는 아직 Windows 에서 실행 확인이 안 됐습니다.
- PowerShell 스크립트는 Windows 10/11 의 기본 실행 정책(Restricted)에서 막히므로 항상 `powershell -ExecutionPolicy Bypass -File .\scripts\<이름>.ps1 <인자>` 로 실행합니다 (저장소 폴더에서).

  ```powershell
  powershell -ExecutionPolicy Bypass -File .\scripts\run_server.ps1
  ```

  ```powershell
  powershell -ExecutionPolicy Bypass -File .\scripts\install_autostart.ps1
  ```

  `install_autostart.ps1` 은 서버를 실행할 Windows 계정으로 실행합니다 (등록에 권한이 더 필요하다는 "액세스가 거부되었습니다" 가 나오면 같은 계정으로 관리자 PowerShell 을 새로 열어 다시 실행). 방화벽 규칙은 **관리자 PowerShell(새 세션이므로 저장소 폴더로 다시 이동)** 에서 만들고 지웁니다.

  ```powershell
  powershell -ExecutionPolicy Bypass -File .\scripts\open_firewall.ps1 -Port 8443
  ```

  ```powershell
  powershell -ExecutionPolicy Bypass -File .\scripts\open_firewall.ps1 -Port 8443 -Remove
  ```

## knowledge 폴더 다시 만들기

`data_dir` 아래 `knowledge/` 는 DB 내용을 AI가 읽도록 옮겨 둔 사본입니다. 사본이 지워졌거나 어긋났다면 DB를 기준으로 통째로 다시 만들 수 있습니다. 올려 둔 자료의 텍스트도 원본에서 다시 뽑습니다. 사본의 폴더·제목 형식이 바뀐 버전으로 처음 시작하면 서버가 사본을 한 번 자동으로 다시 만듭니다(옛 `businesses/` 폴더는 `projects/` 로 바뀝니다).

```powershell
python -m app.cli rebuild-knowledge
```

## 실제 Claude CLI 수동 확인 목록

자동 테스트는 가짜 CLI로 돌립니다. 실제 PC에 설치한 Claude CLI로는 아래를 한 번 직접 확인하세요.

1. `claude --help` 에 `-p`, `--output-format`, `--allowedTools`, `--tools`, `--strict-mcp-config` 가 모두 있는지 확인합니다. 이름이 다르면 `app/ai/runner.py` 의 명령 구성을 맞춥니다.
2. 활동 기록에 메모를 붙여 넣고 "AI로 정리" → 초안이 나오고 저장되는지 확인합니다.
3. 솔루션에 자료를 올리고 "AI로 소개 초안 만들기" → 초안이 채워지는지 확인합니다.
4. 두 브라우저에서 동시에 요청 → 한쪽에 "AI 대기 2번째" 가 보이는지 확인합니다.
5. Claude CLI에서 로그아웃한 뒤 요청 → 로그인 안내문이 보이고, 목록 조회와 수동 저장은 정상인지 확인합니다.

2단계(제안)에서는 아래도 확인하세요.

6. `claude --help` 에 `--include-partial-messages`, `--verbose` 가 있는지 확인합니다. 없으면 `app/ai/runner.py` 의 스트리밍 명령 구성을 맞춥니다.
7. 보류가 아닌 솔루션 2개 이상과 자료를 넣고 제안 건을 만듭니다 → 방향 2~3개와 출처가 보이는지 확인합니다.
8. 방향을 고른 뒤 채팅으로 질문합니다 → 답변이 글자가 늘어나며 보이는지 확인합니다.
9. 구성안에서 한 장을 고치고 PPT를 만들어 PowerPoint에서 엽니다 → 글꼴·배치가 정상이고, 슬라이드 노트에 출처가 있는지 확인합니다.
10. AI를 끈 상태(Claude CLI에서 로그아웃)에서 제안 건 목록 조회, 기존 구성안 수정, PPT 만들기가 되는지 확인합니다.

올리기(Claude CLI의 파일 읽기 도구를 씁니다)는 아래도 확인하세요.

11. 제품 소개 PPT와 스펙 텍스트를 함께 올립니다 → 솔루션 하나(와 공급 파트너)로 묶여 제안되고, 저장하면 두 파일이 솔루션 자료로 내려받아지는지 확인합니다.
12. 글자로 풀어 쓴 통화 녹취록(고객 이름과 할 일 포함)을 올립니다 → 활동 기록의 후속 조치와 고객 연결이 맞는지, 이미 등록된 고객·파트너는 새로 만들지 않고 연결하는지 확인합니다.
13. 글자가 든 사진(명함, 화이트보드 메모)을 올립니다 → 사진 속 글자를 정확히 읽어 활동 기록이나 파트너로 정리하는지 확인합니다. 읽지 못하면 그 사실이 정리안에 드러나는지 봅니다.
14. (받아쓰기를 켜지 않은 상태) 음성 파일만 올립니다 → "받아쓰기 필요" 안내가 보이고 AI 작업은 시작되지 않는지 확인합니다.
15. 정리안에서 "다시 정리"(메모 수정)와 "이 묶음 버리기"가 되는지 확인합니다.
16. 파일 접근 범위 확인: 빈 폴더에 `안.txt` 를, 그 바깥(상위 폴더)에 `밖.txt` 를 만들고 그 빈 폴더에서 `claude -p "안.txt 와 ../밖.txt 를 읽어 내용을 말해 줘" --allowedTools "Read(./**),Glob(./**),Grep(./**)" --tools Read,Glob,Grep` 를 실행합니다 → `안.txt` 는 읽고 `../밖.txt` 는 거부해야 합니다. 둘 다 읽히면 올리기 AI가 작업 폴더 밖 파일을 읽을 수 있다는 뜻이므로 운영 가이드의 "올리기 AI의 파일 접근 범위"를 보고 조치합니다. (Linux 에서만 확인했습니다. Windows 서버에서는 반드시 직접 확인하세요.)

음성 받아쓰기(faster-whisper)는 **실제로 돌려 본 적이 없으므로** 서버 PC에서 아래를 확인하세요 (`pip install -e ".[stt]"` 후).

17. `python -m app.cli stt-setup` → 모델이 `data_dir/models/` 에 받아지고 "자체 점검 통과"가 나오는지 확인합니다 (인터넷이 한 번 필요). 이어서 `config.toml` 에 `transcriber = "faster-whisper"` 를 적고 `python -m app.cli check` 가 "음성 받아쓰기: 정상 (faster-whisper, small, CPU)" 를 보이는지 봅니다.
18. 실제 녹음 파일(1~5분 정도)로 `python -m app.cli stt-test <녹음 파일>` → 글, 걸린 시간, 속도(녹음 1분을 몇 초에)를 확인합니다. 그 속도로 모델 크기(`transcribe_model`)를 정합니다. m4a·mp3·wav 등 쓰는 형식이 모두 읽히는지도 봅니다.
19. 1분짜리 녹음(고객 이름과 할 일을 말한 것)을 올립니다 → 파일 표에 "받아쓰는 중 n%"가 보이다가 정리안이 나오는지, 받아쓴 글(활동 기록 원문)이 들은 내용과 맞는지, 등록된 고객·솔루션 이름이 등록된 표기로 연결되는지 확인합니다. 정리 중 서버를 재시작했다가 "다시 정리"를 눌러 이미 받아쓴 파일은 다시 받아쓰지 않는지도 봅니다.
20. 긴 녹음(30분 이상)을 올려 걸리는 시간을 재고, 그동안 다른 AI 작업(예: 활동 기록 AI 정리)이 얼마나 기다리는지 확인합니다 (`ai_concurrency = 1` 이면 기다립니다. 운영 가이드 12번).
21. 제안서 PDF (PowerPoint, Windows 서버): 제안서를 만든 뒤 제안서 상자의 "PDF 만들기 (미리보기)"를 누릅니다 → 1분 안에 "PDF 를 만들었습니다"가 나오고 "PDF 미리보기"가 브라우저에서 열리는지 확인합니다. 솔박스를 서비스(화면 없는 계정)로 돌리면 PowerPoint 가 열리지 않거나 멈출 수 있습니다: 3분 뒤 실패하면 logs\app.log 의 "PDF 변환 실패 (powerpoint)" 줄을 보고, LibreOffice 를 설치하거나 `config.toml` 에 `pdf_converter = "libreoffice"` 를 적습니다. 끝난 뒤 작업 관리자에 POWERPNT.EXE 가 남아 있지 않은지도 봅니다. (Linux 에서 LibreOffice 로만 확인했습니다.)
22. 구성안 AI 검토와 한 장 다시 쓰기: 구성안을 만든 뒤 구성안 구역에 "AI 검토에서 고친 점"이 보이는지, 구성안 화면에서 한 장의 "AI로 다시 쓰기"(요청 예: "표로 바꿔 줘")가 그 장만 바꾸는지, "다시 쓰기 전으로 되돌리기"가 되는지 확인합니다. app.log 에 "구성안 AI 검토를 버리고" 가 자주 나오면 알려 주세요 (검토 규칙 조정).
