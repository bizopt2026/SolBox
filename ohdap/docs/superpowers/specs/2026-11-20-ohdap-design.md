# 오답노트 앱 설계 (2026-11-20)

## 1. 무엇을, 왜

학생이 틀린 문제를 사진으로 찍어 올리면 AI가 **정답, 여러 풀이법, 핵심 개념**을 정리해 주는 오답노트 웹앱.
정리로 끝나지 않고, **비슷한 문제를 다시 풀어 보며 복습**하게 한다.
풀이는 **칠판 판서 + 음성 설명(영상처럼 재생)** 으로도 볼 수 있다.

- 사용자: 학생 본인, **초등 3학년부터 고등 3학년까지** (사용자 확인)
- 과목: 수학 포함 여러 과목 (사용자 확인). 수학이 핵심이라 수식이 정확히 보여야 한다.
- 성공 모습: 사진 한 장 → 1분 안에 정리된 노트 → 며칠 뒤 앱이 "다시 풀 문제"를 내밀고, 비슷한 문제를 풀어 맞히면 그 오답이 "정복"으로 바뀐다.

## 2. 목표 / 하지 않을 것 / 실패로 볼 것

**목표**
1. 사진(카메라·앨범) 올리기 → AI가 문제 글로 옮기기 → 정답·풀이법 2~3가지·핵심 개념·흔한 실수 정리
2. 칠판 판서 + 음성 설명 재생 (A안, 사용자 선택)
3. 비슷한 문제 만들기·풀기·채점으로 복습
4. 과목·단원·태그별 노트 모아 보기, 다시 볼 문제 목록

**하지 않을 것 (이번 범위 밖)**
- 진짜 동영상 파일 만들기(B안), 유튜브 강의 연결(C안) — 나중에 필요하면 추가
- 선생님·친구와 공유, 반 관리, 순위
- 손글씨 답안 사진 채점 (복습 답은 타이핑·객관식으로)

**실패로 볼 것 (돌아가도 실패)**
- 수식이 깨져 보이거나 사진의 문제를 잘못 옮겼는데 학생이 그걸 고칠 방법이 없는 것
- 정답이 틀렸는데 확신하는 말투로 보여 주는 것 → AI 결과는 "AI 풀이"로 표시하고, 옮긴 문제를 학생이 고친 뒤 다시 풀게 할 수 있어야 한다
- 오답노트가 "정리만 쌓이고 다시 안 보는 창고"가 되는 것

## 3. 제약

- 저장소 관례대로 **HTML 파일 하나**(`ohdap/index.html`)로 만들고 claude.ai 아티팩트로 게시한다 (써브쓰리·밑줄과 같은 방식). 서버·API 키 없음.
- AI는 아티팩트의 `sample` 기능(이미지 입력 `{sample:{images:true}}`)으로 부른다. 첫 호출 때 사용자 동의를 받는다.
- 음성은 `tts` 기능. Safari·모바일 앱에서는 `null`이므로 브라우저 내장 `speechSynthesis`로 대신하고, 그것도 없으면 글자만 보여 준다 (써브쓰리 `speakText`와 같은 방식).
- 외부 스크립트는 허용된 CDN에서 버전 고정으로만. 수식은 KaTeX(cdnjs, 버전 고정).
- 휴대폰 화면(세로)이 기본. 사진은 주로 휴대폰 카메라로 찍는다.

## 4. 만드는 방법 (Approaches)

**풀이 설명 방식** — 사용자가 A안을 골랐다.

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 칠판 판서 + 음성** (선택) | 풀이 단계가 한 줄씩 나타나고, 현재 줄 강조, 음성으로 읽기. 일시정지·이전/다음·속도 | 즉시 생성, 수식 정확, 단계별 반복 가능. 파일 공유는 불가 |
| B. 동영상 파일 생성 | A를 녹화해 파일로 | 아티팩트 안 음성 녹화 불확실, 무거움 → 제외 |
| C. 유튜브 강의 링크 | 개념별 검색 링크 | 문제 맞춤이 아님 → 이번엔 제외 |

**앱 형태** — 저장소의 다른 앱이 모두 단일 HTML 아티팩트라 같은 방식을 따른다 (내 판단). 별도 서버(FastAPI 등)는 API 키·호스팅이 필요하고 이 용도엔 과하다.

## 5. 화면과 흐름

하단 탭 3개: **노트** · **복습** · **올리기(+)**

```
[올리기]                         [노트 상세]
┌──────────────────────┐        ┌──────────────────────────┐
│ 📷 사진 찍기          │        │ 수학 · 이차함수 · ★다시보기 │
│ 🖼 앨범에서 고르기     │        │ [문제 사진]  [옮긴 문제 ✏️] │
│ 과목: [수학 ▾] (선택)  │        │ 내가 쓴 답: 3  → 정답: -1   │
│ 내가 쓴 답: [   ] (선택)│       │ ▶ 판서로 보기               │
│ [AI로 정리하기]        │        │ 풀이 1 · 풀이 2 · 풀이 3    │
└──────────────────────┘        │ 핵심 개념 / 흔한 실수        │
                                 │ [비슷한 문제 풀기]           │
                                 └──────────────────────────┘
[판서 보기]
┌──────────────────────────┐
│ 풀이 1: 근의 공식           │
│ ① x²-2x-3=0               │
│ ② (x-3)(x+1)=0  ◀ 지금 설명│
│ ③ ...(아직 안 보임)         │
│ ⏮  ⏯  ⏭   속도 1.0x  🔊    │
└──────────────────────────┘
```

### 5.1 올리기 → 정리
1. 사진을 고르면 브라우저에서 긴 변 1600px 정도로 줄이고 JPEG로 압축한다 (AI 전송·저장 크기 줄이기).
2. 선택 입력: 과목, 내가 쓴 답, 메모. 비워도 된다.
3. **1단계 (옮기기)**: `sample.json` + 이미지 → 문제 글(LaTeX 포함), 과목·단원 추정, 보기(객관식이면).
   화면에 옮긴 문제를 보여 주고 **학생이 고칠 수 있다** ("이대로 풀기" / "고치고 풀기").
4. **2단계 (풀이)**: 옮긴 문제 글(+이미지)로 `sample.json` → 아래 구조. `modelTier: "complex"`(정확도 우선).
5. 결과를 노트로 저장한다. 실패하면 사진·입력은 남겨 두고 "다시 정리" 버튼.

1·2단계를 나누는 이유: 옮기기 오류가 틀린 풀이의 가장 흔한 원인이고, 학생이 그 자리에서 바로잡을 수 있게 하려고.

### 5.2 AI 결과 구조 (2단계)
```json
{
  "answer": "x = -1 또는 x = 3",
  "answer_short": "-1, 3",
  "why_wrong": "내가 쓴 답이 있으면: 어디서 틀렸을지 추정 (없으면 빈 글)",
  "solutions": [
    { "title": "인수분해", "steps": [
        { "board": "x^2-2x-3=0", "say": "먼저 식을 정리하면 ..." } ] }
  ],
  "concepts": [ { "name": "근의 공식", "summary": "...", "formula": "x=\\frac{-b\\pm\\sqrt{b^2-4ac}}{2a}" } ],
  "mistakes": ["부호 실수 ..."],
  "unit": "이차방정식", "tags": ["인수분해"]
}
```
- `board`: 판서에 쓸 짧은 식/문장 (LaTeX 허용, `$...$`로 감싼 혼합 글)
- `say`: 음성으로 읽을 말. **수식 기호 없이 한국어로 읽히게** ("x 제곱 빼기 2x ...") — 프롬프트에서 요구
- 풀이법은 2~3개, 서로 실제로 다른 방법일 때만 여러 개 (억지로 늘리지 않게)
- 수학이 아닌 과목(국어·영어 등)도 같은 구조: `board`는 핵심 근거 문장, `formula`는 비울 수 있음

### 5.3 판서 보기 (A안)
- 풀이 하나를 고르면 단계(`steps`)를 하나씩 보여 준다. 지금 단계는 강조, 지난 단계는 흐리게, 다음 단계는 안 보임.
- `tts`가 있으면 `t.speak([{text: say, id}...])` 한 번에 넘기고 `onLine`으로 현재 단계를 맞춘다. 일시정지 `pause/resume`, 속도 `setRate`(0.7~1.5).
- 이전/다음 단계로 건너뛰면 그 단계부터 다시 읽기 시작한다 (tts에 탐색 기능이 없으므로 남은 줄로 새 reading 시작).
- `tts` 없음 → `speechSynthesis`로 같은 동작, 그것도 없음 → 자동 넘김(단계당 글자 수에 비례한 시간) + 글자만.
- 첫 재생은 학생이 버튼을 눌러야 시작 (음성 정책).

### 5.4 복습
- **비슷한 문제**: 노트에서 "비슷한 문제 풀기" → `sample.json`으로 같은 개념·비슷한 난이도 문제 1개 생성 (문제, 보기(선택), 정답, 풀이 단계). 학생이 답을 입력 → 먼저 정답과 단순 비교, 애매하면(식·서술형) AI 채점 → 맞음/틀림 + 풀이(판서 보기 재사용).
- **다시 볼 문제(복습 탭)**: 각 노트에 복습 단계를 둔다. 간격 1일 → 3일 → 7일 → 14일 → 정복.
  비슷한 문제를 맞히면 다음 단계로, 틀리면 1일로 되돌아간다. 오늘 할 것이 복습 탭 맨 위에 뜬다.
- 푼 비슷한 문제는 노트 아래에 기록으로 남긴다 (나중에 다시 풀기 가능).
- **AI 없이도 복습이 막히지 않게** (내 판단): AI를 못 쓸 때(동의 거절·`rate_limited`·오프라인)는 "원래 문제 다시 풀기"로 대신한다. 저장된 `answer_short`와 비교해 채점하고, 비교가 애매하면 학생이 정답을 보고 "맞았어요/틀렸어요"를 직접 고른다. 결과는 비슷한 문제와 똑같이 복습 단계에 반영한다.
- **학년** (내 판단): 설정에 학년(초3~고3, 기본 "자동")을 두고 모든 프롬프트에 넣는다. 그 학년에서 배우지 않는 방법(예: 중학생에게 미분)은 풀이법으로 쓰지 않게 하고, 비슷한 문제의 난이도와 `say`의 말투도 학년에 맞춘다. "자동"이면 문제를 보고 AI가 추정한다.

### 5.5 노트 모아 보기
- 과목 → 단원으로 묶어 목록, 검색(문제 글·개념 이름·태그), 필터(정복 안 됨 / 다시보기 표시).
- 개념 모아 보기: 여러 노트에 나온 같은 개념을 한곳에 (이름으로 묶기).

## 6. 데이터

`db` 기능, 학생 본인만 보는 개인 경로 `data/users/<id>/` 아래에 둔다 (`user.id()`).

- `notes/<noteId>`: 과목, 단원, 태그, 옮긴 문제, 보기, 내가 쓴 답, 메모, AI 결과(5.2), 복습 단계·다음 날짜, 만든 날, 사진 id
- `notes/<noteId>/drills/<drillId>`: 비슷한 문제, 학생 답, 맞음 여부, 날짜

**사진 저장**: `assets` 기능에 올리고 id를 노트에 저장. `assets`는 편집자 이상만 쓸 수 있는데, 학생이 자기 계정으로 게시한 주인이라 문제 없다 (사용자 확인). `assets`가 없을 때는 사진을 저장하지 않고 옮긴 문제 글만 남긴다 (화면에 안내).

**로그인 안 됨 / db 없음**: 노트를 이 브라우저(localStorage)에만 보관하고 "이 기기에만 저장됨" 표시. (db가 정상일 때는 localStorage를 쓰지 않음)
나중에 db가 되면 이 기기에 남은 노트가 있다는 알림과 "계정으로 옮기기" 버튼을 보여 준다. 옮기기는 노트 id 기준으로 없는 것만 추가하고, 다 옮긴 뒤에 이 기기 사본을 지운다 (내 판단).

**내보내기**: `downloads`로 노트 전체를 JSON/마크다운 파일로 저장 (선택 기능).

## 7. 오류·예외

- AI 동의 거절(`not_granted`): 올리기 버튼 대신 안내, 기존 노트 보기는 그대로.
- `rate_limited`: 잠시 뒤 다시 하라는 안내, 자동 반복 없음.
- JSON이 깨짐: 한 번만 다시 요청, 그래도 안 되면 "다시 정리" 버튼.
- 사진이 흐리거나 문제가 아님: 1단계에서 `{"readable": false, "reason": ...}`를 받아 다시 찍기 안내.
- 한 사진에 문제 여러 개: 1단계에서 문제 목록을 받아 학생이 하나를 고르게 한다.

## 8. 사용자가 정한 것
- 사용자: 학생 본인(초3~고3) / 과목: 수학 포함 / 복습: 정리 + 비슷한 문제 풀기
- 설명 방식: A안(칠판 판서 + 음성)
- 게시·사용: **학생 본인 claude.ai 계정으로 게시해 직접 쓴다** (학생 = 아티팩트 주인). 보호자 공유·여러 학생은 범위 밖. 따라서 `assets`(사진 저장)를 그대로 쓸 수 있다.

## 9. 내가 정한 것 (검토 부탁)
- 단일 HTML 아티팩트, 폴더 `ohdap/`, 앱 이름 "오답노트"
- 수식 KaTeX, 2단계(옮기기 → 풀이) 처리와 옮긴 문제 고치기
- 복습 간격 1·3·7·14일, 비슷한 문제를 맞혀야 단계가 오름
- 데이터는 개인 경로(`data/users/<id>/`), 사진은 `assets`
- AI를 못 쓸 때 "원래 문제 다시 풀기"로 복습하고, 채점이 애매하면 학생이 직접 맞음/틀림을 표시
- 설정의 학년(기본 "자동")을 프롬프트에 넣어 풀이 방법과 난이도를 맞춤
- 이 기기에만 저장된 노트를 계정으로 옮기는 버튼

## 12. 초등 모드 (초3~초6) — 사용자 요청으로 추가

학년 범위는 **초3~고3**(사용자 확인). 처음 열 때 학년을 고르고, 초등이면 같은 앱이 "초등 모드"로 바뀐다.

- **글자·버튼**: 본문 17px 이상, 버튼 높이 60px 이상, 둥근 모서리를 더 크게.
- **말투·낱말**: 쉬운 해요체. "개념" → "꼭 기억해요", "풀이" → "이렇게 풀어요", "판서로 보기" → "선생님 설명 듣기", "복습" → "다시 풀기", "비슷한 문제 풀기" → "비슷한 문제 도전!".
- **별 모으기**: 비슷한 문제를 맞히면 별 1개. 홈 위쪽에 모은 별 수. 틀리면 꾸중 대신 "괜찮아요, 같이 다시 봐요".
- **홈**: "틀린 문제 찍기"를 가장 큰 버튼으로 홈에 직접 둔다. 단원·검색은 감춘다.
- **세로셈 판서**: 초등 사칙연산은 단계마다 세로셈 칸(받아올림·받아내림 표시, 지금 자리 강조, 답 숫자가 차례로 나타남)으로 보여 준다.
  AI 결과의 단계에 선택 항목 `visual`을 더한다:
  `{"type":"column","op":"-","a":"503","b":"267","marks":{"h":"4","t":"9","o":"13"},"focus":["o"],"result":"__6"}`
  앱이 이것을 세로셈 칸으로 그린다. `visual`이 없거나 틀린 모양이면 `board` 글로 보여 준다.
- **AI 프롬프트**: 학년별 교육과정 범위 안의 방법만 쓰고(초3에게 방정식 금지 등), `say`는 그 학년이 알아듣는 말로.
- **시안**: 캔버스 두 번째 줄 "초등 모드" 화면 5개(학년 고르기·홈·노트·세로셈 판서·비슷한 문제).
