# 솔루션 박스 시스템 설계

- 작성일: 2026-11-18
- 상태: 사용자 승인 대기 (검토자 확인 완료)

## 1. 목적

회사의 솔루션 사업은 기존 사업의 업셀링 포인트를 찾아 새 사업기회를 만들고, 부가가치를 높여 이익 증대에 기여한다. 이를 위해 발굴한 솔루션을 "솔루션 박스"에 담아 두고, 박스에 있는 자료를 조합해 기존 사업 고객에게 새 사업을 제안한다.

이 시스템은 그 일을 하는 직원들이 함께 쓰는 사내 웹 시스템이다. 다음 네 가지 일을 한곳에서 처리한다.

1. **솔루션 발굴**: 파트너사에서 아이템을 받고, 기존 고객 사전 태핑과 수요조사를 거쳐 활용 방향을 정리한 뒤 솔루션 박스에 담는다.
2. **솔루션 조합·제안**: 사용자가 업셀링 대상 사업·고객을 지정하면 AI가 솔루션 자료를 조합해 제안 방향을 내고, 대화로 구체화한 뒤 PPT 제안서 초안을 만든다.
3. **동향 리서치**: 시장·기술·정책 동향을 주기적으로 조사해 보관하고, 시사점과 다음 발굴 방향을 제시한다.
4. **활동 기록**: 회의록 등 텍스트 기록을 쉽게 남기고, 그 기록이 1~3번에 다시 쓰인다.

## 2. 목표 / 하지 않는 것 / 피해야 할 것

### 목표

- 솔루션, 파트너, 고객, 기존 사업, 활동 기록을 한곳에 모으고 서로 연결한다.
- 기록 부담을 최소화한다. 사용자는 메모를 붙여 넣거나 파일을 올리기만 하고, 정리와 연결은 AI가 초안을 만든다.
- 고객·사업을 지정하면 제안 방향 → 대화 구체화 → 10장 내외 PPT 초안까지 한 흐름으로 이어진다.
- 동향 리서치가 사람 손 없이 주기적으로 쌓이고, 발굴 방향 제안으로 이어진다.
- 서버 PC 한 대에서 관리자 한 명이 운영할 수 있을 만큼 단순하다.

### 하지 않는 것 (비목표)

- CRM·영업관리 시스템 대체 (매출, 계약, 견적 관리 없음)
- 결재·승인 워크플로
- 음성 녹음 자동 받아쓰기
- 모바일 앱, 사외 접속
- 여러 명이 한 문서를 동시에 편집하는 기능
- 사내 양식 PPT 맞춤 (별도 양식 없음. 시스템 기본 디자인 틀 한 가지만 제공)

### 피해야 할 것 (기술적으로 동작해도 실패인 경우)

- **AI가 자료에 없는 스펙·실적·수치를 지어내는 것.** 제안 방향과 제안서의 사실 주장은 출처(어느 솔루션의 어느 자료, 어느 활동 기록)를 표시한다. 근거가 없으면 "자료 없음, 확인 필요"로 표시한다.
- **기록 입력이 번거로워져 아무도 쓰지 않는 것.** 필수 입력 항목은 최소로 한다.
- **AI 결과가 검토 없이 확정되는 것.** AI가 만든 정리·연결·제안은 모두 초안이며, 사용자가 확인·수정해야 저장된다.

## 3. 제약 조건

- **배포 위치**: 사내망의 24시간 켜진 서버 PC. 직원은 브라우저로 `https://10.231.1.254/` 에 접속한다. 사외에서는 접속하지 않는다.
- **AI**: 별도 API 계약을 쓰지 않는다. 서버 PC에 설치·로그인된 **Claude CLI(구독 계정)** 를 시스템이 호출한다. CLI는 인터넷으로 Anthropic에 접속하며, 이는 사용자가 허용했다.
- **개발·테스트**: 사용자 PC에서 테스트하고, 완성되면 서버 PC로 이관한다. 이관은 폴더 복사와 실행으로 끝나야 한다.
- **운영체제**: 서버 PC는 Windows다 (사용자 확인). 사용자 PC도 Windows로 가정한다.
- **인터넷**: 서버 PC는 일반 인터넷 접속이 가능하다 (사용자 확인). 설치 시 Python 패키지를 인터넷에서 내려받으며, 오프라인 설치 꾸러미는 만들지 않는다.
- **규모**: 직원 수십 명, 솔루션 수십~수백 개, 자료 파일 수천 개 이하.
- **구독 계정 1개 공유**: AI 요청은 동시에 많이 처리할 수 없다.

## 4. 검토한 방식

| 방식 | 내용 | 장단점 |
|---|---|---|
| **A. 한 덩어리 웹앱 + 파일 기반 지식 (선택)** | 웹앱 1개, DB 파일 1개, 자료 폴더. Claude CLI가 자료 폴더를 직접 읽음 | 설치·이관·백업이 단순. 화면은 실용적 수준. 수십 명 규모에 적합 |
| B. 화면/서버 분리 + DB 서버 + 검색 엔진 | React 화면, API 서버, PostgreSQL, 벡터 검색 | 화면이 세련되고 대규모에 강함. 설치·운영 부담이 3~4배. 현재 규모에 과함 |
| C. 기성 위키·협업 도구 + AI 연동 | 기록·보관은 기성 도구 사용 | 바로 쓸 수 있으나 서버 Claude CLI 연동과 조합→대화→PPT 흐름 구현이 어려움 |

**사용자가 A를 선택했다.** PC 한 대, 관리자 한 명 운영이라는 조건에서 단순함과 이관 용이성이 가장 중요하기 때문이다. 자료가 크게 늘면 나중에 검색 엔진만 추가할 수 있다.

## 5. 전체 구조

```
[직원 브라우저] ──HTTPS──> [웹앱 (FastAPI, 단일 프로세스)]
                              │
          ┌───────────────────┼─────────────────────┐
          │                   │                     │
   [SQLite DB 파일]     [자료 폴더 data/]      [AI 작업 대기열]
   목록·관계·기록        원본 + 텍스트 변환본         │
                              ▲                [Claude CLI 실행기]
                              └── 읽기 전용 ────────┘
                                                    │
                                             [PPT 생성기] → .pptx
          [스케줄러] ── 주기 리서치 작업 등록 ──> [AI 작업 대기열]
```

### 기술 선택 (작성자 결정)

- **언어·프레임워크**: Python, FastAPI
- **화면**: 서버에서 그리는 HTML(Jinja2) + HTMX. 별도 프런트엔드 빌드 없음. 한국어 UI
- **DB**: SQLite (파일 1개)
- **자료 보관**: 디스크 폴더
- **AI**: Claude CLI를 하위 프로세스로 비대화형 실행
- **PPT**: python-pptx
- **주기 작업**: 웹앱 프로세스 안의 스케줄러

### 폴더 구성

프로그램 코드와 운영 데이터를 분리한다. 이관·백업은 `data/` 폴더 복사로 끝난다.

```
app/            프로그램 코드
data/
  app.db        DB
  uploads/      원본 업로드 파일
  knowledge/    Claude CLI가 읽는 지식 폴더 (DB에서 자동 생성되는 사본)
    solutions/<id>/card.md, files/<파일명>.md
    customers/<id>.md
    businesses/<id>.md
    partners/<id>.md
    activities/<연도>/<id>.md
    research/<날짜>-<분야>.md
  decks/        생성된 PPT
```

- **DB가 원본**이고 `knowledge/` 는 사본이다. 항목이 저장·수정·삭제될 때마다 해당 MD 파일을 다시 만든다. 전체 재생성 명령도 제공한다.
- 업로드 파일(PPT, PDF, Word, Excel, 텍스트)은 텍스트를 추출해 `files/*.md` 로 저장한다. 추출에 실패하면 실패 상태를 표시하고 원본만 보관한다. 스캔 이미지 PDF의 글자 인식(OCR)은 하지 않는다.

### 솔루션 발굴 단계

`아이템 접수 → 사전 태핑 → 수요조사 → 박스 등록` 과 `보류`. 단계는 사용자가 직접 바꾼다. "박스 등록" 단계의 솔루션만 조합·제안에 기본 포함한다 (그 외 단계는 사용자가 선택하면 포함).

### 활동 기록 종류

`회의`, `파트너 미팅`, `고객 태핑`, `수요조사`, `기타`.

## 7. 기능 설계

### 7.1 솔루션 박스 (1단계)

- 솔루션·파트너·고객·기존 사업의 목록, 검색, 등록, 수정, 삭제
- 등록은 한 건씩 한다. 기존에 쌓인 자료가 없으므로(사용자 확인) 엑셀 일괄 등록은 만들지 않는다.
- 한 솔루션의 자료 파일은 **여러 개를 한 번에 선택해 올릴 수 있다** (사용자 요청). 파일마다 종류(소개/스펙/관련)를 지정하며, 기본값은 '관련'이다.
- 솔루션 상세 화면: 기본 정보, 발굴 단계, 자료 파일 목록(업로드·내려받기), 연결된 활동 기록 시간순 목록, 이 솔루션이 들어간 제안 건
- 고객·사업 상세 화면: 기본 정보, 연결된 활동 기록, 제안 건
- 솔루션 등록 시 자료를 올리면 AI가 한 줄 소개·상세 설명·태그 초안을 채워 준다 (선택 기능, 사용자가 확인 후 저장)

### 7.2 활동 기록 (1단계)

흐름:

1. 사용자가 "기록 추가"에서 메모를 붙여 넣거나 텍스트 파일을 올린다. 필수 입력은 **원문 메모 하나**뿐이다.
2. AI가 다음 초안을 만든다.
   - 종류, 일자, 제목
   - 정리본: 참석자, 논의 내용, 결정 사항
   - 후속 조치: 할 일, 담당, 기한
   - 수요 단서: 고객이 드러낸 필요·관심 (어느 고객, 어떤 내용)
   - 연결 후보: 메모에 언급된 솔루션·고객·사업·파트너. 등록되지 않은 이름은 "새로 등록" 후보로 표시
3. 사용자가 초안을 확인·수정하고 저장한다. AI 정리를 건너뛰고 원문만 저장할 수도 있다.

저장된 기록은 연결된 솔루션·고객·사업·파트너 화면에 나타나고, `knowledge/activities/` 에 MD로 쓰여 조합·제안과 리서치 시사점에서 읽힌다.

### 7.3 솔루션 조합·제안 (2단계)

흐름:

1. **대상 지정**: 사용자가 고객과 기존 사업을 고르고, 원하면 요청 메모(예: "에너지 절감 쪽으로")를 적는다.
2. **제안 방향 제시**: AI가 지식 폴더에서 해당 고객·사업 정보, 관련 활동 기록(특히 수요 단서), 솔루션 카드와 자료, 최근 리서치를 읽고 **제안 방향 2~3개**를 낸다. 방향마다 다음을 담는다.
   - 제안 제목과 한 줄 요약
   - 조합한 솔루션과 각 역할
   - 이 고객·사업에 맞는 이유 (근거 출처 표시)
   - 기대 효과
   - 확인이 필요한 점
3. **대화로 구체화**: 사용자가 방향을 하나 고르고 채팅으로 다듬는다 (범위, 강조점, 솔루션 추가·제외 등). 답변은 생성되는 대로 화면에 흘려 보여 준다. 대화 내역은 제안 건에 저장된다.
4. **슬라이드 구성안**: 사용자가 "제안서 만들기"를 누르면 AI가 10장 내외 구성안을 만든다. 사용자는 화면에서 장별 제목·내용을 고치거나 다시 만들게 할 수 있다.
5. **PPT 생성**: 구성안을 기본 디자인 틀에 넣어 `.pptx` 를 만들고 내려받는다. 구성안을 고쳐 다시 생성할 수 있다.

#### 슬라이드 구성안 형식

AI는 정해진 구조의 데이터(JSON)로 구성안을 낸다. 슬라이드 한 장은 `종류`, `제목`, `핵심 메시지`, `본문` 을 가진다. 종류는 다음 여섯 가지로 한정한다.

| 종류 | 내용 |
|---|---|
| 표지 | 제안 제목, 고객명, 일자 |
| 글머리 | 제목 + 핵심 메시지 + 글머리 항목 |
| 2단 비교 | 좌우 두 칸 (예: 현황 / 제안 후) |
| 표 | 제목 + 표 |
| 단계 | 추진 단계·일정 (3~5단계) |
| 마무리 | 요약, 다음 단계 |

기본 목차(AI가 내용에 맞게 조정): 표지 → 고객 현황과 과제 → 제안 개요 → 솔루션 구성 → 솔루션별 상세(1~3장) → 기대 효과 → 추진 방안·일정 → 마무리.

#### 출처와 "확인 필요" 표시 위치 (작성자 결정)

제안서는 고객에게 나가는 문서이므로 내부 출처(회의록, 내부 자료명)와 "확인 필요" 표시는 슬라이드 본문에 넣지 않는다.

- 슬라이드 한 장은 `출처`(근거가 된 자료·기록 목록)와 `확인 필요`(근거가 없는 주장 목록) 항목을 추가로 가진다.
- 두 항목은 **구성안 검토 화면**에서 장별로 보여 준다. "확인 필요"가 있는 장은 눈에 띄게 표시한다.
- 생성된 PPT에는 **슬라이드 노트**에만 넣는다. 화면에 보이는 슬라이드에는 나타나지 않는다.

구조가 맞지 않는 응답은 한 번 다시 요청하고, 그래도 실패하면 오류로 표시한다.

### 7.4 동향 리서치 (3단계)

- 관리자가 **리서치 주제**(주제·키워드, 분야)를 등록한다.
- 스케줄러가 **매주 1회**(기본값: 월요일 새벽, 관리자가 변경 가능) 분야별 조사 작업을 대기열에 넣는다. "지금 조사" 버튼으로 수동 실행도 가능하다.
- AI가 웹을 검색해 분야별 보고서를 만든다: 주요 동향, 출처 링크, **시사점**.
- 분야별 보고서가 끝나면 AI가 이번 주 보고서, 현재 솔루션 박스, 최근 수요 단서를 함께 읽고 **발굴 방향 제안**을 쓴다: 어떤 종류의 솔루션을 새로 찾을지, 기존 솔루션 중 무엇을 밀지, 그 이유.
- 보고서는 목록·상세 화면에서 읽고 검색한다. 보고서에서 "솔루션 후보로 등록"을 누르면 `아이템 접수` 단계의 솔루션이 만들어진다.
- 보고서는 `knowledge/research/` 에도 쓰여 조합·제안에서 참고된다.

### 7.5 홈 화면

최근 활동 기록, 기한이 다가오는 후속 조치, 발굴 단계별 솔루션 수, 진행 중인 제안 건, 최신 리서치 시사점을 한 화면에 보여 준다.

### 7.6 사용자·권한

- 아이디·비밀번호 로그인. 가입은 관리자가 계정을 만들어 준다.
- **일반 사용자**: 모든 항목 조회·등록·수정. 삭제는 본인이 만든 것만.
- **관리자**: 전부 가능 + 사용자 관리, 리서치 주제·주기 설정, AI 작업 현황 조회.
- 모든 항목에 작성자와 수정 시각을 남긴다.

## 8. AI 연동

### 실행 방식

- 웹앱이 Claude CLI를 비대화형 모드로 하위 프로세스 실행한다. 작업 폴더는 `data/knowledge/` 이다.
- **도구 제한**: 기본은 파일 읽기·검색 도구만 허용한다. 쓰기, 명령 실행은 허용하지 않는다. 리서치 작업에만 웹 검색·웹 읽기를 추가로 허용한다. 업로드 자료에 섞인 지시문이 시스템을 움직이지 못하게 하기 위함이다.
- AI의 출력은 텍스트 또는 정해진 구조의 데이터로만 받고, DB·파일 저장은 웹앱이 한다.
- 작업 종류별 지시문(프롬프트)은 코드와 분리된 파일로 관리해 운영 중 다듬기 쉽게 한다.

### 대기열

- 모든 AI 요청은 AI 작업으로 DB에 기록하고, **한 번에 하나씩** 순서대로 처리한다 (동시 처리 수는 설정값, 기본 1).
- 대기 중이면 화면에 "대기 n번째"를 표시한다. 대화형 요청(채팅, 기록 정리)은 주기 리서치보다 먼저 처리한다.
- 작업당 제한 시간(기본 10분, 리서치는 30분)을 넘으면 중단하고 실패로 표시한다. 실패한 작업은 사용자가 다시 시도할 수 있다.
- 웹앱이 재시작되면 "진행" 상태로 남은 작업은 실패로 정리한다.

### 오류 처리

- CLI 미설치, 로그인 만료, 사용량 한도 초과, 인터넷 불통은 원인을 구분해 화면과 관리자 화면에 표시한다.
- AI가 동작하지 않아도 솔루션 박스와 기록의 조회·수동 입력은 정상 동작한다.

## 9. 운영

- **HTTPS**: `https://10.231.1.254/` 로 제공한다. 사내 IP이므로 자체 서명 인증서를 쓴다 (브라우저 경고는 최초 1회 예외 등록).
- **설정 파일**: 포트, 인증서 경로, 데이터 폴더, Claude CLI 경로, 동시 처리 수, 리서치 주기를 설정 파일 하나로 관리한다. 사용자 PC 테스트와 서버 PC 운영은 설정 파일만 다르다.
- **이관**: 서버 PC에 Python과 Claude CLI 설치·로그인 → 프로그램 폴더 복사 → 설치 스크립트 실행 → 시작. 절차를 문서로 제공한다.
- **자동 시작**: 서버 PC 부팅 시 자동 실행되게 한다.
- **백업**: `data/` 폴더를 매일 날짜별로 복사하는 스크립트를 제공한다 (보관 일수 설정).
- **최초 실행**: 관리자 계정을 만드는 명령을 제공한다.

## 10. 구현 순서

전체 구조는 이 문서대로 잡고, 구현은 세 단계로 나눈다. 각 단계가 끝나면 사용자 PC에서 써 볼 수 있다.

| 단계 | 범위 |
|---|---|
| 1 | 기반(로그인, 설정, 폴더 구조, AI 대기열·CLI 실행기) + 솔루션 박스(7.1) + 활동 기록(7.2) + 홈 화면 |
| 2 | 솔루션 조합·제안(7.3) + PPT 생성 |
| 3 | 동향 리서치(7.4) + 운영 도구(이관·백업·자동 시작 문서와 스크립트) |

## 11. 테스트

- 자동 테스트에서는 실제 Claude CLI 대신 **가짜 CLI**(정해진 응답을 내는 대역)를 쓴다. 대기열, 시간 초과, 구조 오류 응답 처리까지 검증한다.
- 실제 CLI 연동은 사용자 PC에서 수동 확인한다 (단계별 확인 목록 제공).
- 개발은 Linux 환경에서도 이뤄지므로, 경로·프로세스 실행 코드는 Windows와 Linux 모두에서 동작하게 작성한다.

## 12. 구현자에게 맡기는 것

- 화면 배치와 세부 디자인 (실용적이고 깔끔한 수준, 한국어)
- DB 테이블 세부 구조와 마이그레이션 방법
- Claude CLI 호출 옵션, 대화 이어가기 방식(세션 재개 또는 대화 내역 재전송), 답변 스트리밍 방식
- 지시문(프롬프트) 문구
- PPT 기본 디자인 틀의 색·글꼴·배치 (Windows 기본 한글 글꼴 사용)
- 텍스트 추출 라이브러리 선택
- Windows 자동 시작 방법, HTTPS 처리 방법(웹앱 직접 또는 앞단 프록시)
- 목록 검색 방식 (단순 문자열 검색으로 시작)

## 13. 작성자가 정한 사항 (사용자 확인용)

사용자가 직접 말하지 않았고 작성자가 정한 것들이다.

1. 사용자 PC는 Windows로 가정 (서버 PC는 Windows로 확인됨)
2. 권한은 관리자/일반 두 가지, 계정은 관리자가 생성
3. 일반 사용자는 본인이 만든 항목만 삭제 가능
4. 솔루션 발굴 단계 5종 (아이템 접수 / 사전 태핑 / 수요조사 / 박스 등록 / 보류)
5. 활동 기록 종류 5종, 필수 입력은 원문 메모뿐
6. 제안 방향은 2~3개 제시
7. PPT는 시스템 기본 디자인 틀 한 가지, 슬라이드 종류 6가지
8. 리서치 주기는 주 1회가 기본값
9. AI 작업은 한 번에 하나씩 처리
10. 스캔 PDF 글자 인식, 음성 받아쓰기는 범위 밖
11. 제안서의 출처와 "확인 필요" 표시는 검토 화면과 슬라이드 노트에만 넣고, 슬라이드 본문에는 넣지 않음
